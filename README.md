## 一、项目简介

面向长文剧情创作的 Windows 单机桌面工具，核心能力：

- **故事与时间线**：绝对时间起点、按日存储、日历视图、插曲/倒叙、历史修改与后续失效标记
- **角色与世界观**：角色库、关系图、世界观硬规则
- **剧情生成**：旁白 / 对话两态 · `*…*` 心声 · `#标签` 元指令 · `@角色` 聚焦 · `〔导演指令〕` · 流式输出（可中途停止）
- **上下文管理**：系统提示词→角色设定→关系图→世界观→最近 N 轮→用户输入；Token 估算与智能截断（只截断历史、超限自动降 N）
- **后台静默演进**：事件日志 → 候选事件提取 → 实质性判断 → 变更提案 → 校验 → 人工确认/拒绝 → 快照更新 → 可回滚
- **设置与安全**：API Key 存系统钥匙串（不落剧情文件夹）、缓存管理、日志与调试面板

详细规格见 [docs/dev/SPEC.md](docs/dev/SPEC.md)，文档总入口 [docs/README.md](docs/README.md)。

## 七、启动方式

**四种启动方式，选一种即可**（关键区别：**数据会落在不同目录**，换方式会"看不到"另一套数据）：

| # | 方式 | 怎么启 | 数据落在 | 适合 |
|---|---|---|---|---|
| 1 | **开发模式** | `npm run tauri dev` | 探测顺序第一可写项（通常是 `%APPDATA%\com.guchenxi.story-weaver`）| 改代码 |
| 2 | **本地脚本** | 双击 `start.cmd`（**不入库**，写死本机路径）| 项目下 `data\` | 本机日常用（推荐）|
| 3 | **直接双击 exe** | 双击 `src-tauri\target\release\app.exe` | `%APPDATA%\com.guchenxi.story-weaver` | 不想用脚本 |
| 4 | **安装包 / 便携版** | 装 [MSI](#三0-下载安装) 或解压便携 zip 后双击 `Story-Weaver.exe` | `%APPDATA%\com.guchenxi.story-weaver` | 给不装开发环境的人 |

> ⚠ 方式 3 在本仓库路径（`D:\project\ai生成`）下**可能起不来** —— 见下方「为什么必须复制」；
> 官方做法是方式 2（脚本会先复制到纯英文目录再启动）。

### 改代码时（开发模式）

```powershell
cd D:\project\ai生成
npm install        # 首次
npm run tauri dev  # 自带 vite 服务（devUrl = http://localhost:5173）
```

⚠ **不要**直接双击 `target\debug\app.exe` —— debug 版要去 `localhost:5173` 取界面，
没有那个服务时窗口会开了又立刻关。

### 平时使用：双击项目根目录的 **`start.cmd`**（本地脚本，不在仓库里）

> ⚠ **这个脚本不在仓库里**（`.gitignore` 已排除）。它写死了本机路径，属于运行配置而非源码。
> 拿不到这份文件时，自己建一个 `start.cmd`，等价于：
>
> ```bat
> set "PROJ=%~dp0"
> set "DREAMWEAVER_DATA_DIR=%PROJ%data"
> start "" "%PROJ%src-tauri\target\release\app.exe"
> ```
>
> 不想用脚本就直接双击 `src-tauri\target\release\app.exe`（方式 3）——
> 但数据会落到 `%APPDATA%`，与用脚本启动**不是同一份**（见 [数据与备份](docs/user/数据与备份.md) §一）；
> 而且在本仓库这种**中文目录名**下可能起不来，原因见下方「为什么必须复制」。

它会做三件事：

1. 把 `target\release\app.exe` **复制到一个纯英文路径**（`%LOCALAPPDATA%\DreamWeaverRun`）
2. 把数据目录设为项目里的 `data\`
3. 启动程序

**为什么必须复制**（这是踩了很久的坑）：

> **Tauri / WebView2 在"程序所在目录恰好叫 `ai生成`"时，无法创建主窗口** ——
> 现象是窗口一闪就没了（或干脆不出现），进程却还活着，且**没有任何报错**。
> 同一个 exe 放到 `ai生成x`、`a生成`、`生成`、`中文`、纯英文路径下**都正常**。
> 所以启动器把它复制到一个纯英文目录再运行；**数据仍然留在项目里**。

### 前提：先构建 release 版（只需做一次）

```powershell
npm run build
cd src-tauri
cargo build --release --features custom-protocol
```

> ⚠ **`--features custom-protocol` 不能省**。
> Tauri 用这个**特性**（不是 debug/release）判断"打包版还是开发版"：
> 缺了它，release 版也会去连 `http://localhost:5173`，页面就显示"localhost 拒绝连接"。
> （`src-tauri/Cargo.toml` 的 `[features]` 段里有详细注释，别删。）

`start.cmd` 找不到 exe 时会提示这两条命令。

### 数据落在哪（取决于启动方式，别混用）

| 启动方式 | 数据目录 |
|---|---|
| `start.cmd`（显式设了 `DREAMWEAVER_DATA_DIR`） | 项目下 `data\` —— `library\default\projects\<故事>\story.db` + `library.db` |

## 安全说明（没有代码签名，怎么自己验）

**安装包与便携版都没有代码签名。** 原因很朴素：作者是学生，这软件不赚钱，也没钱买代码签名证书
（OV 证书一年几百到几千元 + 资质审核）。所以第一次运行时 Windows 会弹：

> 「Windows 已保护你的电脑 —— 发布者：未知」

**直接跳过**：点「更多信息」→「仍要运行」。这个弹窗的含义是"微软没见过这个文件、没有签名能证明发布者身份"，
**不是**"检测到病毒"（真有病毒会被 Defender 拦下并报出威胁名）。

如果不放心 —— 这是完全合理的 —— 请**别信作者，信证据**：

|---|---|
| **[SECURITY.md](SECURITY.md)** | **安全策略与威胁模型**（信任边界、4 类威胁、已知限制、报告渠道）|

把这段话直接发给你的 agent（豆包 / DSH / Claude Code 都行）就能让它替你查：

```text
请按 docs/user/security/AGENT-AUDIT-GUIDE.md 逐条核对 https://github.com/gu-chen-xi/story-weaver
是否有恶意行为。每步给出实际命令或文件行号；无法验证的写"未验证"，不许猜；最后输出检查表。
```

**我们只验证了这三件事**（每条都给了可复现的命令；**超出这个范围的本文件不下结论**）：

1. **源码里没有"调用外部程序"的代码** —— `src-tauri/src/**` 里 `Command::new` 命中 0 次。
   这只覆盖**我们自己写的源码**；依赖链（`Cargo.lock` 里那些包）没有逐个审。
2. **源码里没有自启/驻留的调用** —— 无注册表自启、无服务安装、无计划任务。
   这只覆盖"代码有没有这么写"；"关窗后进程还在不在"请开任务管理器自己看。
3. **源码里的外部地址只有一张清单** —— 见 [AGENT-AUDIT-GUIDE.md §3.1](docs/user/security/AGENT-AUDIT-GUIDE.md)
   （模型 API 预置默认值、本地绘图默认值、测试夹具、文档链接）。
   **这不等于"你的机器上只会连这几个地址"**：代理、DNS、系统级拦截都在我们视野外 ——
   想确认实际连了谁，只有抓包（同文档 §3.3）。

**下载后请校验哈希**（发布页附 `SHA256SUMS.txt`）：

```powershell
Get-FileHash .\Story-Weaver_3.8.0_x64_en-US.msi -Algorithm SHA256
```

出问题时把那个文件发出来即可。退出码 **0 = 可用 / 1 = 有问题**。

> 详细说明（含每一项"为什么查"、以及它自己是怎么被验证的）见
> [启动自检工具说明.md](docs/dev/自检工具.md)。

## 数据存在哪里

数据根**按顺序探测，用第一个真能写的**（不是"看起来存在"就算 —— 见下文）：

1. **环境变量 `DREAMWEAVER_DATA_DIR`** —— 显式指定就以它为准（便携 / 放移动硬盘 / 换到可写盘）
2. `%APPDATA%\com.guchenxi.story-weaver` —— 标准位置
3. **`<程序同级目录>\data`** —— 便携 / **受限环境兜底**
4. `<当前目录>\data` —— 再退一步
5. 系统临时目录下的 `dreamweaver-data` —— 最后手段

目录结构（以最终选定的数据根为准）：

```
<数据根>\
├── library\            故事与素材（library.db + projects\<id>\story.db + shared\portraits\）
├── exports\            导出产物
├── temp\               生成过程的临时文件
├── logs\               日志（含启动失败日志 startup-error.log）
└── backups\            备份
```

> 注：项目根目录下**不再有** `app/ config/ plugins/ models/ cache/ logs/ backups/`
> 这些空壳目录（2026-10-16 已删，代码 0 引用）；全局配置在 `library.db` 的 `configs` 表里。

### 为什么"要探测可写"

实测踩到过两次，都是**同一个坑**：

- 数据根指向 `%APPDATA%`，但那台机器上**安全软件不允许程序写 AppData**
  → sqlite 报 `attempt to write a readonly database` → 应用起不来
- 日志插件的默认目标（`%LOCALAPPDATA%`）被拒
  → 插件初始化失败 → **setup panic，界面都出不来**

而且**同一台机器上 Python 能写、本程序不能写** —— 所以"目录存在/权限看起来对"
**完全不能作为依据**：现在一律**真写一个探针文件**来判定，任何一级写不了就退到下一级。

### 受限环境下怎么让数据固定在某个盘（推荐）

如果程序最终落在 `%APPDATA%` 之外的兜底位置（日志里会打印"已改用：..."），
建议**显式指定数据根**，数据位置就完全可控：

```powershell
# 方式一：临时（只对当前窗口有效）
$env:DREAMWEAVER_DATA_DIR = "D:\织梦机数据"
.\src-tauri\target\debug\app.exe
```

方式二：用项目根目录下的 **`start.cmd`**（本机脚本，**不在仓库里**；没有就按
[「平时使用」](#平时使用双击项目根目录的-startcmd本地脚本不在仓库里) 里的 3 行等价物自建）。
> 旧文档这里写过 `启动（开发版）.cmd` —— 那个文件从未入库、现已不存在，统一用 `start.cmd`。

### 升级说明

从旧版本（数据在 `<项目根>/library`）升级时，程序会在**新位置还没有数据**的前提下
自动搬一次（有日志；跨盘移动失败会退化为复制）。搬完旧目录可删。

## 分支功能的适用范围

**主要面向"主线 + 第一层分支"**：从主线某个节点分叉出来的分支，是本轮完整验证过的场景
（时间维、共享历史、天数、状态隔离、删除分支都已走通）。

**嵌套分支**（从分支再分叉）数据层是通的（状态从源分支复制、天数与共享历史都正确），
但界面表达有限 —— 时间维是一条横向窄条，多层分叉时链条会很长、不容易一眼看清。
一层够用时不建议建第二层。

详见 [docs/design/分支系统.md](docs/design/分支系统.md) 第十三节。
