## 一、项目简介

**AI 原生叙事引擎**：通过结构化角色卡、世界书触发注入、动态数值系统和导演指令机制，在保持叙事一致性的前提下实现开放式互动叙事。

面向长文剧情创作的 Windows 单机桌面工具（核心关注故事本身的质量：结构、连续性、人物一致、伏笔能回收）。核心能力：

- **故事与时间线**：绝对时间起点、按日存储、日历视图、插曲/倒叙、历史修改与后续失效标记
- **角色与世界观**：角色库、关系图、世界观硬规则
- **剧情生成**：旁白 / 对话两态 · `*…*` 心声 · `#标签` 元指令 · `@角色` 聚焦 · `〔导演指令〕` · 流式输出（可中途停止）· **失败自动重试**（429 / 5xx 最多 3 次，只在还没吐字时重试）· **彻底失败保留半截 + 红字写原因**（导出剥掉）
- **上下文管理**：系统提示词→角色设定→关系图→世界观→最近 N 轮→用户输入；Token 估算与智能截断（只截断历史、超限自动降 N）· **回顾检索**：说「第 4 天」就只带第 4 天，未来天与前三天不给，「第 3 到第 5 天」这类范围用「🔍 回顾」多选
- **后台静默演进**：事件日志 → 候选事件提取 → 实质性判断 → 变更提案 → 校验 → 人工确认/拒绝 → 快照更新 → 可回滚
- **章节与大纲**：章 ↔ 天手动圈定（一天只属一章）· **章卡上的天可拖到别的章（或拖回「未归章」）** · 编辑章时能改「关联的天」· 按章导出全书 · 每章「目标」可注入生成（默认开、空目标零 token）· 统计卡（进度/字数/未归章/伏笔）
- **伏笔台账**：手标 + 规则扫描提议（可拒绝）· **本地模型扫原文，一批一章**（轮数 = 章数；前情摘要只带这一章的天 + 往前三天，不再把整本历史塞进去）· 逾期按章序现算 · 埋设章与计划回收章一眼可见
- **动态数值**：体力/理智/存在感（插件默认关）· 事件类走对话协议、作息走「日结」· **数值会压台词**：低理智只剩短句、低体力句子更短（每句字数与本段句数都有硬上限）· **体力还决定"做得到做不到"**：很低时力气活写失败或走形（搬不动 / 扶不住 / 走两步就得停），正常以上不许无端写虚弱 · 存在感正负各自封顶 ±5 · 普通的一夜恢复 +10 体力 · 每次变化可单条撤销 · 导演代价按故事日衰减（每 10 天 −5）
- **承诺状态**：从剧情提炼（多条并存）· 标记结算兑现/未兑现 · 记忆卡三态徽标可手改 · 关键记忆按祖先链继承（嵌套分支读得到父分支的承诺，兄弟分支互不可见）
- **本地模型（Ollama）**：插件页填地址 + 模型名 + 上下文档位，「检查连接」读版本、「测试对话」发一句验证（**走原生 `/api/chat` 并关思考** —— 思考型模型不再永远回空，空时会说清原因）；开着时主模型走本地（**原生 `/api/chat`，档位真的作为 `num_ctx` 发过去，结束块还能拿到真实用量**；**不下载、不启动 Ollama，也不做失败回落**）
- **设置与安全**：API Key 存系统钥匙串（不落剧情文件夹）、缓存管理、日志与调试面板

详细规格见 [docs/dev/SPEC.md](docs/dev/SPEC.md)，文档总入口 [docs/README.md](docs/README.md)。

## 二、技术栈（已确认落地）

| 层 | 技术 |
|------|------|
| 桌面壳 | Tauri 2（Rust 核心） |
| 前端 UI | React + TypeScript + Vite（深色 STORY DECK 主题，内联样式） |
| 数据库 | SQLite（sqlx），story.db / library.db |
| 状态管理 | React useState / 组件内状态（未引入状态库） |
| Token 估算 | 按字符类别加权（汉字 0.79 / 英文 0.20 / 空白 0.12 / 标点 0.39），按真实 usage 校准；前后端同一套系数 |
| 网络 | reqwest + tokio |
| 钥匙串 | keyring（Windows Credential Manager） |
| 云端模型 | OpenAI-compatible（DeepSeek 已验证） |
| 本地模型 | Ollama（Windows 版，实测 **0.40.11**）—— 主对话与伏笔扫描都走原生 `/api/chat`（`num_ctx` 真生效） |
| 分析器 | Rust 规则引擎（段落归属 + 代词回指） |

> 注：早期原型曾用 Electron + 原生 HTML/CSS/JS，已废弃重规划；Tailwind CSS / Zustand / tiktoken-rs 曾在规划中提及，最终未落地（token 仍是**估算**，不是真分词器：2026-10-28 起按字符类别加权并用 API `usage` 校准）。

> 官方做法是方式 2（脚本会先复制到纯英文目录再启动）。

### 改代码时（开发模式）

```powershell
cd D:\project\ai生成
npm install        # 首次
npm run tauri dev  # 自带 vite 服务（devUrl = http://localhost:5173）
```

⚠ **不要**直接双击 `target\debug\app.exe` —— debug 版要去 `localhost:5173` 取界面，
没有那个服务时窗口会开了又立刻关。

### 平时使用：双击项目根目录的 **`start.cmd`**（本地脚本，不在仓库里）

> ⚠ **这个脚本不在仓库里**（`.gitignore` 已排除）。它写死了本机路径，属于运行配置而非源码。
> 拿不到这份文件时，自己建一个 `start.cmd`，等价于：
>
> ```bat
> set "PROJ=%~dp0"
> set "DREAMWEAVER_DATA_DIR=%PROJ%data"
> start "" "%PROJ%src-tauri\target\release\app.exe"
> ```
>
> 不想用脚本就直接双击 `src-tauri\target\release\app.exe`（方式 3）——
> 但数据会落到 `%APPDATA%`，与用脚本启动**不是同一份**（见 [数据与备份](docs/user/数据与备份.md) §一）；
> 而且在本仓库这种**中文目录名**下可能起不来，原因见下方「为什么必须复制」。

它会做三件事：

1. 把 `target\release\app.exe` **复制到一个纯英文路径**（`%LOCALAPPDATA%\DreamWeaverRun`）
2. 把数据目录设为项目里的 `data\`
3. 启动程序

**为什么必须复制**（这是踩了很久的坑）：

> **Tauri / WebView2 在"程序所在目录恰好叫 `ai生成`"时，无法创建主窗口** ——
> 现象是窗口一闪就没了（或干脆不出现），进程却还活着，且**没有任何报错**。
> 同一个 exe 放到 `ai生成x`、`a生成`、`生成`、`中文`、纯英文路径下**都正常**。
> 所以启动器把它复制到一个纯英文目录再运行；**数据仍然留在项目里**。

### 前提：先构建 release 版（只需做一次）

```powershell
npm run build
cd src-tauri
cargo build --release --features custom-protocol
```

> ⚠ **`--features custom-protocol` 不能省**。
> Tauri 用这个**特性**（不是 debug/release）判断"打包版还是开发版"：
> 缺了它，release 版也会去连 `http://localhost:5173`，页面就显示"localhost 拒绝连接"。
> （`src-tauri/Cargo.toml` 的 `[features]` 段里有详细注释，别删。）

`start.cmd` 找不到 exe 时会提示这两条命令。

### 数据落在哪（取决于启动方式，别混用）

打包版 / `start.cmd` 与开发模式**可能用不同的数据根**（探测顺序见下文「数据存在哪里」）。
混用会出现"故事不见了"的错觉 —— 想知道当前用的是哪个，看启动日志里的 `数据根：...` 一行。

### 11.4 谁说了算：人工确认 vs 角色自决

软件里有两类东西，边界必须写清楚，否则用户会觉得「AI 在替我改设定」，或者反过来「什么都得我点确认，太累」。

**一条总则**：

> **事实进角色，解释进审批；短尾自动，长尾人工；自动必须可撤销。**

| 判据 | 交给人工（你/审批） | 交给角色（自动） |
|---|---|---|
| **事实 vs 解释** | "这意味着什么"——关系该升温、她应该更信任他 | "发生了什么"——熬夜、受伤、被当众羞辱、被安抚 |
| **长尾 vs 短尾** | 改了会影响**之后所有轮次**的前提：世界观、角色卡文字、关系定义、身份、生死 | 只影响**这一段**：体力、理智、情绪、姿态、当天的存在感 |
| **方向盘 vs 后果** | 会**否决或改写你刚下的指令**（你写"她同意了"，软件判"她拒绝"） | 只是给指令**补上代价**（她答应了，但累了 / 委屈了） |

**允许自动写入的三个条件（缺一条就降级为提示或提案）**：

1. **可见**——改了什么要当场提示，不能黑箱；
2. **可撤销**——每一次自动写入都进账本（带来源与撤销标记），能单条撤销；
3. **有上限**——单次变化的幅度有封顶，不能一轮从 80 掉到 0。

**当前落在哪一边（对照表）**：

| 东西 | 谁说了算 | 依据 |
|---|---|---|
| 世界观 / 角色卡文字 / 关系定义 | 人工 | 长尾 + 解释 |
| 关系强度（演进提案） | 人工 | 解释："应该升温" |
| 关系强度（导演代价自动扣） | 自动 | 事实：她被迫让步；且有审计、可撤销 |
| 关系强度（正向变好） | 人工（走演进） | "好"比"坏"主观，容易自我感动 |
| 记忆判定（她接受 / 拒绝） | 角色（协议标记） | 事实：她怎么说的；软件**不**据此限制剧情 |
| 情绪 / 当下 | 角色 | 短尾、体感 |
| 体力 / 理智 / 存在感（插件开启时） | 角色 | 事实（熬夜 / 受伤）+ 短尾 + 可撤销 |
| 导演指令能不能用 | 软件（规则） | 关系强度 = 0 或代价满 60，不归任何一方"同意" |

**三条硬边界**：

1. 软件**不替你决定剧情走向**——记忆判定说你被拒绝了，它也不会禁止 AI 之后写"你们在一起了"，只会在提示词里提醒角色"之前发生过什么"；
2. **生死与不可逆损伤只能人工**——自动链路里没有"死亡 / 致残"类型，这类事只能你改角色卡或走提案；
3. **你手改的数值永远优先**——手动改 = 重设基线，自动变化只在新基线上加减（改的时候会提示"会清空今天的累计"）。

具体到「体力 / 理智 / 存在感」这条链路的完整设计（协议、类型表、上限、撤销、插件开关）见
[三维数值变更（设计稿）](docs/design/三维数值变更.md)。

> 每项"为什么查"见 [启动自检工具说明](docs/dev/自检工具.md)；常见症状见
> [错误合集](docs/dev/错误合集.md) 的「症状索引」。
## 数据存在哪里

数据根**按顺序探测，用第一个真能写的**（"目录存在/权限看起来对"不算数 —— 一律真写一个探针文件）：

1. 环境变量 **`DREAMWEAVER_DATA_DIR`**（显式指定就以它为准）
2. `%APPDATA%\com.guchenxi.story-weaver`（标准位置）
3. `<程序同级目录>\data`（便携 / 受限环境兜底）
4. `<当前目录>\data`
5. 系统临时目录下的 `dreamweaver-data`（最后手段）

```
<数据根>\
├── library\      故事与素材（library.db + projects\<id>\story.db + shared\portraits\）
├── exports\      导出产物
├── temp\         临时文件
├── logs\         日志（含 startup-error.log）
└── backups\      备份
```

想固定位置就设环境变量：`$env:DREAMWEAVER_DATA_DIR = "D:\织梦机数据"`。

> 为什么必须"真写探针"、目录里每张表是什么、怎么备份/迁移/清理：
> 见 [数据与备份.md](docs/user/数据与备份.md)。
## 分支功能的适用范围

**主要面向"主线 + 第一层分支"**（时间维、共享历史、天数、状态隔离、删除分支都已走通）。
**嵌套分支**数据层是通的，但时间维是横向窄条，多层分叉不容易看清 —— 一层够用时不建议建第二层。
