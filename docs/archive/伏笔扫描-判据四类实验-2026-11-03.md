## 一、这是什么实验

2026-11-02 的本地伏笔扫描使用的是「先列细节，再逐条判断」的两步式提示词。用户实测发现：

> 只给 5 个例子时，7B 会把例子清单当成白名单。表外的一律算「无」。

于是 2026-11-03 开了一组实验，核心是：

1. **判据先行**：把「这条细节当场有没有被消化——被解释、被接住、当场用掉 = 是；还悬着 = 否」放在最前面；
2. **四类清单只作例子**：缺失型 / 悬置义务型 / 重估型 / 异常型，并写明「清单不是穷举」；
3. **判断贴到条目后面**：每条细节直接写成 `细节 → 是/否`，避免两张表按编号对齐时 7B 丢行；
4. **缺口感测与兜底**：数「→ 否」和实际写出的〔伏笔〕差多少，只在必要时提醒；模型不回补时，直接用第一步的「→ 否」原文兜底；
5. **类别硬要求**：尝试要求模型在每条后面标类别，禁止「可标可不标」。

## 三、为什么没有合入

后续提交 `be0cc48` 的结论是：

> 判据段 + 四类清单 + 类别标注对 qwen2.5 7B（Q4_K_M）是纯负担，效果不理想。

用户实测 5 轮后，主线回退到两步式；只重新保留了其中两处确实修 bug 的做法：

1. 判断贴到条目后面，减少 7B 两张表对齐时丢行；
2. 模型少写伏笔时，用第一步的「→ 否」兜底，不再要求它第二遍补写。

因此这条分支里的「判据 + 四类清单 + 类别硬要求」是**已放弃的候选方案**；不能直接合回 main。
