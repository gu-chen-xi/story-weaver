## 一、目标定义

1. **端到端闭环**：创建故事 → 设定时间起点 → 创建角色和世界观 → 写剧情 → 调用模型生成 → 按日保存 → 重启恢复 → 修改历史 → 基于修改续写 → 后台生成设定变更提案 → 人工确认 → 快照更新 → 可回滚
2. **MVP 验收 14 条全过**（最小MVP实现.md §8）
3. **测试样板通过**：后台静默演进主用例（暗恋→明恋，强度 60→85，快照 V10→V11）+ 6 个负例与边界
4. 技术栈（已确认落地）：Tauri 2 + Rust + React+TS+Vite + SQLite（sqlx）；前端内联样式深色 STORY DECK 主题（未引入 Tailwind/Zustand）；Token 前端字符粗估 + N 值自适应；分析器 = Rust 规则引擎；Ollama 本地模型 / 评估判断模型 / 立绘生图走插件（后置）

## 五、逻辑关系与因果对照

### 5.1 主因果链

```
用户输入
  → 三重语法解析（动作/台词/元指令）
  → 双模式判定（沉浸/上帝）
  → 上下文组装（绝对不截断区 + 最近 N 轮 + 用户输入）
  → 模型生成（流式输出，状态包含性）
  → 保存到当前时间节点
  → 后台分析器启动（读取快照/关系图/当日剧情）
  → 事件提取 → 实质判断 → 变更提案 → 校验
  → 用户确认/拒绝 → 应用 → 新快照
  → 后续剧情基于新快照续写
```

### 5.2 异常对照表（E1-E12 见 SPEC.md §8）

| # | 异常 | 触发 | 处理 |
|---|------|------|------|
| E1 | 空输入 | 发送空内容 | 禁止发送 |
| E2 | 语法未闭合 | 括号/引号未闭合 | 提示位置不提交 |
| E3 | 模式冲突 | 上帝模式输台词 | 并入剧情 |
| E4 | Token 超限 | 濒临超限 | 自动降 N / 动态不上传，仍超提示 |
| E5 | 模型不可用 | 未配置/超时/网络 | 提示 + 保留输入可重试 |
| E6 | 提案校验失败 | 冲突/越界 | 拒绝提案 + 原因 |
| E7 | 冷却期内 | 3 天内重复变更 | 不自动应用只记录 |
| E8 | 低置信度 | < 0.8 | 忽略 |
| E9 | 回滚不可用 | 快照链缺失 | 禁用回滚 |
| E10 | 存储写入失败 | 磁盘/权限 | 报错 + 内存保留提示另存 |
| E11 | API Key 缺失 | 未配置调用 | 引导设置页 |
| E12 | 缓存超限 | 超上限 5GB | 自动清理 |

### 5.3 边界条件表

| 项 | 边界 | 说明 |
|----|------|------|
| 置信度阈值 | 0.8 | 低于忽略（E8） |
| 冷却期 | 3 天 | 期内不自动应用（E7） |
| 缓存上限 | 默认 5GB | 可自定义（E12） |
| 关系强度 | 0-100 | 越界拒绝 |
| 关系类型/方向变更 | 人工确认 | 高风险 |
| N 值 | 随模型窗口自适应 | 超限自动降 |
| 绝对不截断区 | 4 类内容 | 永不压缩 |

## 六、状态流转

### 6.1 剧情生成状态机

```
[空闲] → 输入 → [解析] → 语法错误 → [E2 提示] → 修正 → 输入
   │                    │ 通过
   │                    ▼
   │              [模式判定] → 元指令 → [金色横幅拦截]（不进剧情上下文）
   │                    │ 剧情类
   │                    ▼
   │              [上下文组装] → 超限 → [E4 自动降 N]
   │                    ▼
   │              [模型生成] → 失败 → [E5 可重试]
   │                    ▼
   │              [保存到当日节点] ──→ [后台演进状态机]
   └──────────────[空闲]
```

### 6.2 后台演进状态机（核心）

```
[剧情保存完成]
  → [读取快照+关系图+剧情]
  → [提取候选事件] ──置信度<0.8──→ [E8 忽略]
  → [实质判断] ──非实质──→ [结束（仅记事件日志）]
  → [生成变更提案]
  → [校验] ──失败──→ [E6 拒绝+原因]
  → [策略判定]：强度可自动 → [应用]；类型变更 → [待用户确认]
  → [用户确认] → [应用] / [拒绝] → [丢弃]
  → [生成新快照 V(n+1)] → [审计] → [关系图更新]
  → [后续剧情读取 V(n+1)]
```

### 6.3 提案状态流转

```
[待确认] ──确认──→ [已应用] ──回滚──→ [已回滚]（沿快照链）
    │
    └──拒绝──→ [已拒绝]
```

### 6.4 快照链

```
V10（parent=null） → V11（parent=V10） → V12（parent=V11） …
回滚 = 从当前快照退回指定父版本（如 V11 → V10）
```

#### 一、 核心定位与技术形态

1. **产品形态**：一款带有完整图形界面（UI）的电脑端聊天/剧情生成软件。采用原生桌面应用框架结合 Web UI 层的混合架构，兼顾本地运行效率与 UI 表现力。
2. **纯本地与联网限制**：软件本体追求纯本地部署与运行，**唯一需要联网的环节**是用户自行配置和调用云端 API Key 时。
3. **插件化架构**：核心功能保持精简，扩展功能采用插件化设计（如 Ollama 本地模型插件、JEV AI 评估判断模型插件等）。用户可自主选择安装和启用，以应对第三方服务下线风险并保持软件轻量化。

#### 二、 上下文管理与 AI 记忆机制（核心底层逻辑）

1. **上下文优先级与动态上传控制（防遗忘与防超限）**：
   - **绝对不截断区**：系统提示词（最高优先级）、人物设定（第二高优先级）、角色关系图、世界观。这四部分内容本身绝不参与对话历史的压缩或截断。
   - **动态上传策略**：虽然上述内容不被截断，但**角色关系图**和**世界观**是否在本次请求中上传给 AI，由**软件系统智能判断**（基于当前剧情节点的相关性或 Token 余量），而非无脑全量发送，以节省上下文空间。
2. **对话历史的智能截断与 N 值自适应**：
   - 在角色对话或长剧情中，仅对"AI 历史生成内容 + 用户历史输入"进行截断。
   - **智能降级**：软件会实时读取当前所选 AI 模型的"最大上下文窗口"数据。当用户自定义的"保留最近 N 轮对话"导致总 Token 濒临超限时，软件会**自动向下调整 N 值**，确保请求永远合法且不报错。
3. **AI 输出内容的"状态包含性"要求（替代严格结构化）**：
   - **放弃死板格式**：不再强求 AI 输出 JSON 或严格的标记格式，以免破坏文学表达的自然感。剧情生成时，整体内容依然包裹在一个大文本框内展示。
   - **内容包含性约束**：在 Prompt 中强制要求 AI 在输出的文本中，**必须自然地包含**其所扮演角色的**动作变化、心理活动和神态描写**。
   - **软件后台提取**：软件通过自身的解析能力（或调用轻量级判断插件），从这段自然文本中提取角色的当前状态（如情绪、动作），用于驱动 UI 层的立绘变化和状态卡更新。

#### 三、 角色设定与世界观演进系统

1. **世界观与设定管理**：
   - 提供独立的"世界观"与"角色库"模块，集中查看和管理背景设定、物理法则、人物初始设定及关系图。
2. **设定的"后台静默演进"机制（核心亮点）**：
   - **职责分离**：负责写故事的"剧情 AI"**不参与**设定的判断和修改。
   - **软件自动演进**：人物设定和关系图不再是写死的。每次剧情生成后，由**软件系统后台**（通过规则引擎或独立的分析模型）来审阅剧情。
   - **演进逻辑**：如果软件判断剧情发展已实质性改变了人物关系（例如：初始设定"男主暗恋女主"，但近期剧情表现出"双向奔赴"），软件会自动将设定更新为"明恋"，并同步更新关系图。后续剧情 AI 将基于新设定生成更大胆、自然的互动。

#### 四、 时间线与日历管理系统（核心骨架）

1. **故事开幕与起点设定**：
   - 首次创建故事时，弹出"故事开幕"弹窗，设定"绝对时间起点"（现实日期或架空纪元）。起点固定后，后续"X天后"由系统自动计算，AI 仅负责填充内容。
2. **双重视角与局部化统计**：
   - **用户视角**：滚动型日历 UI；**AI 视角**：后台转化为 AI 易读格式。
   - **局部化标签**：标签管理和数据统计**必须绑定在对应的时间线/日期节点上**，跟随时间线走，不做全局统计，避免剧情割裂。
3. **剧情存储、修改与蝴蝶效应**：
   - 按日独立存储剧情。用户修改历史剧情后，AI 后续必须严格基于修改后的结果续写。
   - 大幅修改后弹出"蝴蝶效应预览"，对比新旧分支，由用户手动选择保留哪一条。
4. **插曲与倒叙功能**：
   - 在空白日期右键"插入插曲"，系统自动打上"倒叙/回忆"标签，并给 AI 附加明确的时空提示。

#### 五、 立绘与视觉反馈系统

1. **立绘双通道生成**：
   - 支持"云端常规生成"和"本地自由生成"。在设置中提供醒目的下拉框切换，可微调参数。
2. **角色状态卡与动态情绪（UI 彩蛋）**：
   - 侧边/底部设置"角色状态卡"。AI 生成剧情后，软件从文本中提取情绪标签（如 `[Angry]`），**无需重新生图**，直接在 UI 层为当前立绘叠加动态效果（如红框、气泡），直观反馈角色状态。
3. **手动"拍照"与节点标记**：
   - 提供"拍照"按钮，一键生成并挂载立绘到当前时间节点。
   - 日历节点通过颜色或图标（🎭/🎬）标记该段剧情的生成模式。

#### 六、 输入语法与指令控制系统

1. **三重文本语法规范**：
   - `（圆括号）`：动作、表情、心理等侧面描写。
   - `"双引号"`：人物台词。
   - `裸文本（无括号）`：作者对 AI 的**元指令**（最高权限）。
2. **元指令拦截与视觉反馈**：
   - 裸文本绝不塞入正式剧情上下文。
   - 发送元指令后，该消息在聊天框转化为带有"齿轮/铅笔"图标的**金色横幅**，实现视觉区隔。

#### 七、 叙事模式系统（双模式交互）

1. **模式切换 UI**：输入框上方设置醒目的滑块/标签页。
2. **🎭 模式 A：沉浸式扮演（代入式）**：用户代入角色，AI 扮演特定角色回应，时间随对话自然流动。
3. **🎬 模式 B：上帝视角扩写（导演式）**：用户提供大纲/提示，AI 进行大段剧情扩写。

#### 八、 角色对话系统（独立于主剧情）

1. **核心定位**：独立于主剧情的"闲聊/测试"入口，用于测试人设或激发灵感。
2. **上下文构成与智能降级**：
   - 上下文 = 角色人设 + 角色关系表 + 最近 N 轮对话历史。
   - **N 值自适应**：软件根据当前模型的上下文窗口限制，若用户设定的 N 值超限，自动向下调整 N 值。超过 N 值的历史直接丢弃，不做摘要。
3. **时间线锚定与联动**：
   - 可选择主剧情的"某一段时间"作为对话背景。
   - 在主线剧情 AI 气泡旁提供快捷入口，一键跳转角色对话。切换时间点后对话历史保留。
   - 支持创建"不保存到角色库"的临时角色，用完即弃。

#### 九、 系统设置与安全管理

1. **API Key 安全隔离**：
   - 严格限制 API Key 读取权限。绝不上传、不给第三方读取、**绝不保存在剧情文件夹内**，采用单独的安全存储机制。
2. **缓存空间管理**：
   - 设置中提供可视化的"缓存管理"面板，清晰展示各文件夹缓存内容。
   - 用户可自定义缓存总容量上限（默认 5GB）。超限后系统自动清理，也支持手动选择性删除。
