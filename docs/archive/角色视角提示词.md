> 目标不是省 token（省是顺带的），是**角色隔离**：AI 只该知道自己角色该知道的事。

### 7.1 两种模式 = 两种视角

| | 旁白（`mode = narr`） | 对话（`mode = chat`） |
|---|---|---|
| 视角 | **全局（上帝）** | **角色视角**（以 AI 扮演的那个角色为中心） |
| 提示词 | **现状，一个字都不改**（只加"旁白"标记） | 新装配器 `build_roleplay_prompt(ai_role, my_role)` |
| 关系 | 全量 | 只给 `from = ai_role` 的行 |
| 角色卡 | 全员 | 只有 ai_role；"我"只给名字 / 年龄 / 性别 + `ai→我` 那一行关系 |
| 世界条目 | 全量 | **全量**（2026-11-10 定：世界是公共的） |
| 关键记忆 | 全量 | 先全量；第二步加 `character` 归属 |
| 历史 | 全量 | **按配对过滤**（`ai_role × my_role`）+ 旁白 + 无标记兜底（2026-11-11） |
| 排版规则 | 全量 | 角色版（去掉旁白那几段） |
| 数据字典 / 台词口径 / 情绪表演 / 配合度 / 前史 | 全量 | 全量 |
| 对账协议（导演代价 / 状态变化 / 承诺 / 本章目标 / 表态） | 全量 | **全量，一条不少** |

### 7.2 关系：一行 = 一个方向（"自己对别人"）

关系表**本来就是"自己 → 别人"**，一行一条方向：

```
a → b        （a 眼里对 b 的关系）
b → c
a → c
```

AI 扮演 **a** → 提示词的关系栏只给 `a→b`、`a→c` 两条；`b→c` 不给（那是 b 的私事）。

- **单向行**（`direction = 单向`）：`relations.rs:68` 的 `split_for_relation` 直接返回空，渲染用的就是这一行的 from / to / 类型 / 描述 → 拿到的正是"她眼里的你"。
- **双向行**：一行 + **一条共用描述**，渲染时才按关系名词拆两句 → 约定：**双向关系的描述写成中性句**（"母子，关系紧张"），不要写带视角的话（"他很怕我"），否则两面共用会串味。
- **不需要给关系表加字段**（2026-11-10 看图后确认：关系条目本身就是一行一个方向）。

### 7.5 MVP（4 步，每步可独立验收）

1. ✅ **打标（2026-11-10 已完成）**：`timeline::message_meta()` 统一构造 `meta`（`tod` 只认早/午/晚，`ai_role`/`my_role` 跳过空值与「自由」），用户消息（`create_message` 多两个可选参数）与 assistant 消息（成功 / 中途失败两条路径）都写；顺手修了 `messages.mode` 的错注释。4 条单测。**老消息无标记 = 全局可见，不猜不补**。
2. ✅ **角色装配器（2026-11-10 已完成）**：`build_system_prompt` 多一个 `PromptScope`（空 = 全局，行为与以前逐字节一致）；角色视角下只留她的卡 + `from=她` 的关系 + 【你对面的他】（名字/年龄/性别/身份）；尾部【数值与当下】只列她的关系与属性；示例对话只认她；**历史按「旁白 + 她在场 + 无标记」过滤**。旁白路径一行未改。开关 `prompt.roleplay_scope`（默认 role，写 `global`/`false`/`0`/`off` 回退）。**未做**：精简排版规则（用户 2026-11-11 定：排版是基础，先不动）。**关键记忆已按角色（2026-11-11）**：写卡带 `character:`，读卡按角色过滤（含全局兜底）。**2026-11-11 补**：对面那行改成「只知身份；其余只能从你亲眼所见、亲耳所听里推」（原来的「你并不知道」会让模型在"该不该知道他昨晚没睡好"上卡）；视角**改按配对**；换扮演者时弹一条 T3 提示（`lib/roleHint.ts`，5 条测试）。
3. **开关 + 可观测**：故事级 `prompt.roleplay_scope = role | global`（默认 role，可一键回退）；请求快照的 `status` 写 `pool=role:<名字>`，出问题一眼看出走的是哪套。
4. **对比工具**（可选）：参数页「Prompt 预览」加"按模式对比"，同一节点打两版看字数差。

### 7.6 验收（要能一眼判死）

- **隔离题**：AI 扮 a，问"b 对你是什么态度？" → 不该说得出 `b→a` 那一行的内容；切旁白问同样的问题 → 答得出。
- **对账段齐**：导演代价 / 状态变化 / 承诺 / 本章目标 / 表态标记，一条不少（少一条就会静默失效）。
- **质量不掉**：3 个真实故事各跑 5 轮，人工看"人设有没有变薄"。

### 7.7 注意（坑先记下来）

1. **AI 在对话里不演 NPC**：提示词要明说"不要替其他角色写台词"，否则它顺手给路人加戏（现在就是全员演员）。
2. **历史先共用 = 隔离只在设定层**：她照样能在历史 / 旁白里读到别人的事。文档要写清"第一版不是信息隔离"。
3. **前缀缓存会击穿**：两套 system 完全不同，切模式那一次必然重建缓存。频率低，接受 —— 别指望"切模式还能命中"。
4. **预算要重算**：system 变短 → 历史预算变大 → 可能又塞更多历史进来。省下的预算给谁要先定（建议留给回复或更长历史，别全吃掉）。
5. **双向关系描述要中性**（见 7.2）。
6. **记忆"读分池、写不分池"会空**：日结 / 演进现在抽出来的记忆是全局的，第二步必须同时改"写"。
7. **叫"角色视角"，别叫"角色池"** —— 后者容易被理解成"只给这个角色的历史"（现在历史是共用的）。
8. **后台静默演进要等标记就位**：它现在读当天全文，没有 per-message 标记就分不了池。

### 7.8 还没定的三件

1. ~~**视角按"角色"还是"配对"**~~ → **定了：配对**（2026-11-11）。a 和 b 聊的、a 和 c 聊的算两段关系；`visible_in_role_view(mode, meta, ai, my)` 配对相同或互换才可见，「自由」模式下退回按角色。
2. **老消息回填**：建议"无标记 = 全局"，不推断（编出来的归属比缺失更糟）。
3. **记忆 `character` 的多值问题**：一张卡可能涉及两个人（"a 和 b 的告白"），归属写谁？可能要 `characters: "a,b"`。
