## 三、设计规则（这套图标"长什么样"）

- 画布 **24×24**，全部用 `<path>` / `<circle>` / `<rect>` 手写；
- 线宽 **1.7**、圆头圆角（`stroke-linecap/linejoin: round`）、颜色 `currentColor`（跟随文字）；
- 几何统一：矩形类圆角 1.8~2.6，视觉重心落在 12×12 中心附近；
- 两个签名图标：`whale`（左上角 Logo）、`fish`（首页问候旁）—— 这两个是这套图标"自己的角色"，不来自任何图标库；
- 加图标的流程：先在画板 `docs/design/icon-set.preview.html` 画 → 满意了进 `icons.tsx` → 跑 `node scripts/verify-icons.mjs`。

## 五、怎么证明是这套图标（复核）

1. **文件同一性**（任意一台机器都能算）：

   ```powershell
   # 当前工作区
   Get-FileHash src\components\icons.tsx -Algorithm SHA256

   # v3.17.0 发布时的那个版本（git blob 原始字节）
   cmd /c "git cat-file blob v3.17.0:src/components/icons.tsx > %TEMP%\icons.tsx"
   Get-FileHash "$env:TEMP\icons.tsx" -Algorithm SHA256
   ```

   应得到 `FC95E24E9F8C00B3E8246DB3145775A89B3861F6FA0905E567F7EF27D91058C8`（13,595 字节）。

2. **数量与一致性**：

   ```powershell
   node scripts/verify-icons.mjs
   ```

   它会核对：50 个名字、每个名字都有 path、没有重复、没有引入图标库依赖，并打印当前文件 sha256。

3. **第三方时间**：上面 6 个提交、tag `v3.17.0`、Release 都在 GitHub 上，有服务器侧时间；GitHub 的提交页/发布页可直接点开对照。

4. **二进制里的同一批 path**：安装包/便携版里的前端 bundle 内嵌了这些 SVG path 字符串，可与源码对照（`grep` 包内 JS 里的 `M3.5 7.8` 这类 path 片段）。

## 六、和参考页 / 第三方图标的关系

- 作者最初的参考是桌面上的一个静态 HTML（`code.html`，**已不在原路径**），里面只有 6 个简单图标；
- 那 6 个只提供了"要线性、要深色底、要跟文字同色"的方向，**没有复制它的 path 数据**；
- 本套扩到 50 个，坐标与构图按本项目重画；两个签名图标是原创角色；
- 简单几何形状本身通常不受版权保护，也可能与别家图标"撞形"—— 这是**独立创作**能接受的相似度，不等于复制；真要主张权利，比的是具体表达（path 数据、整体风格）是否被照搬。
