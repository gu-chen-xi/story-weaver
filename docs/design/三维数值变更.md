# 三维数值变更（体力 / 理智 / 存在感）· 设计稿

> 状态：**草案 · 待拍板**（2026-10-28）｜只定口径，不写码
> 相关：[SPEC §3 数据模型](../dev/SPEC.md)、[提示词规则](../dev/提示词规则.md)、[ROADMAP](../dev/ROADMAP.md)

## 0. 一句话

体力/理智/存在感从"只读装饰"变成"真的会变"，但**数字不由模型给**：
模型只报「发生了什么类型的事」，软件按表扣分、写进可撤销的变更账本 ——
和「导演代价」是同一套骨架（`director.rs` 的哲学：模型不碰数字）。

## 1. 现状（读代码确认，不是印象）

| 项 | 事实 |
|---|---|
| 字段 | `characters.stat_stamina / stat_sanity / stat_screen`（0-100，默认 50）；`stat_emotion` 仍在表里但**已不参与**（情绪由「当下」文字表达） |
| 档位 | `stat_tier`：0-19 很低 / 20-39 偏低 / 40-59 正常 / 60-79 偏高 / 80-100 很高 |
| 进提示词 | 尾部【数值与状态】按「档位(数字)」注入，**焦点角色优先**，自由模式最多 8 人；数据字典里解释三维含义并**明令禁止当血条演** |
| 谁能改 | **只有手动**（角色卡编辑）；分支快照/回滚；演进提案**不碰** `stat_*`（`evolution/analyze.rs` 里没有 stat 字段） |
| 已有基础设施 | `event_logs`（事件）、`audit_logs`（审计）、`change_proposals`（提案-审批）、分支隔离（`branch_id`） |

**结论**：现在这三项是"会进提示词、但永不变化的常数"。要做的是**变更链路**，不是调参。

## 2. 三个方案

| | 谁决定 | 优点 | 缺点 | 结论 |
|---|---|---|---|---|
| **A 协议行 + 软件算分** | 模型报「类型 + 理由」，软件查表给 Δ | 和导演代价同一套；数字稳定；可审计 | 模型可能忘写（要兜底） | ✅ 推荐 |
| B 关键词规则 | 软件按词表推断 | 零成本、不靠模型 | 误报高（"累"字满天飞）；说不清"为什么变" | 只当 A 的兜底 |
| C 提案-审批 | AI 提 proposal，人点确认 | 最安全 | 每轮都要点确认，破坏"体感"；审批适合设定，不适合生理 | 不做 |

推荐：**A 为主 + B 兜底**（同 `director::settle`：收据与推断取更重的一笔，一轮只结一次）。

## 3. 四个问题

### 3.1 谁改（推荐 A）

- 这一轮回复后，要求模型在**末行写一行**：`〔状态变化〕熬夜：她一夜没合眼`
- 类型 → (维度, 步长) 写在代码里（`STAT_KINDS`），**提示词里只有类型和口径，没有数字**；
- 表外类型 = 0 分、不记账，只把那一行从正文剥掉（和导演代价一致）；
- 一轮里每个角色**每个维度最多 1 条**，每轮总数 ≤ 2 条（防刷）；
- 兜底：模型没写时按关键词推断（同类型命中 ≥2 个词），**且只补空缺**。

### 3.2 改多少（建议）

**快变量（体力/理智）**：单次 |Δ| ≤ 15；**慢变量（存在感）**：单次 |Δ| ≤ 5，且只在大事件出现。

| 维度 | 类型 | Δ | 例子 |
|---|---|---|---|
| 体力 | 熬夜 / 长途奔波 | −10 | 守了一整夜 |
| 体力 | 受伤 / 生病 | −15 | 被推下台阶 |
| 体力 | 休息 / 吃饱睡好 | +10 | 睡了一觉 |
| 体力 | 力竭 | −15 | 打了一架 |
| 理智 | 被欺骗 / 背叛 | −10 | 发现他一直在骗她 |
| 理智 | 撞见无法解释的事 | −15 | 看见不该看见的东西 |
| 理智 | 被安抚 / 想通 | +10 | 有人把话说开 |
| 理智 | 崩溃 | −15 | 当众失控 |
| 存在感 | 被无视 / 被冷落 | −5 | 全场没人接她的话 |
| 存在感 | 被当众羞辱 | −10 | 被点名嘲笑 |
| 存在感 | 被看见 / 被认可 | +5 | 有人特意提到她 |

- 每轮每个角色**总变化 ≤ 20**（两个维度各 −10 就满额，第三个不再记）；
- 夹到 **0..100**，到 0 不做硬闸门（叙事里"昏过去"由模型写，软件不锁功能）。

### 3.3 何时改

- **每轮回复后结算一次**（和导演代价同一条链路，在存库前解析、存库后写账）；
- 只在**对话模式**；旁白模式（上帝视角扩写）不结算 —— 旁白不代表角色经历；
- **导演轮次照记**，但不因"导演指令"额外加码（开挂的代价已经在导演账本里算过一次）；
- 协议行**不进历史**（和 `〔态度〕`、`〔导演代价〕` 一样按形状剥）；
- 不触发演进提案，不等人工确认。

### 3.4 怎么退

新表 `stat_changes`（每次变化一行，只增不改）：

```sql
CREATE TABLE IF NOT EXISTS stat_changes (
  id           INTEGER PRIMARY KEY AUTOINCREMENT,
  branch_id    TEXT,              -- 分支隔离
  node_id      INTEGER,           -- 哪一天
  message_id   INTEGER,           -- 哪条 AI 回复
  character_id INTEGER NOT NULL,  -- 谁
  dim          TEXT NOT NULL,     -- stamina / sanity / screen
  delta        INTEGER NOT NULL,  -- 正负
  kind         TEXT NOT NULL,     -- 类型名（熬夜/受伤/…）
  reason       TEXT NOT NULL DEFAULT ''
  source       TEXT NOT NULL DEFAULT 'model',  -- model / rule
  revoked      INTEGER NOT NULL DEFAULT 0,     -- 撤销标记
  created_at   TEXT NOT NULL DEFAULT (datetime('now','localtime'))
);
```

- **撤销 = 反向补一次**（再写一行 `delta = -原值, source='undo'`），并给原行 `revoked=1`；
  不算术回滚、不改其它行，历史永远可追溯；
- 同时写一条 `audit_logs`（operator=system, action=stat_change）；
- 不做"整天回滚"——要整段重来请用现有快照/回滚。

## 4. 提示词改动

尾部【数值与状态】之后加一小段（**只在有变化时出现**）：

```
【状态变化】（给软件的对账行，不是剧情内容）
- 这一轮如果有人物状态发生明显变化，在回复末尾单独一行写：〔状态变化〕类型：理由
- 类型只能写：熬夜 / 受伤 / 生病 / 力竭 / 休息 / 被欺骗 / 被安抚 / 崩溃 / 被无视 / 被羞辱 / 被认可
- 冒号前直接写类型名，不要写字段名；理由 ≤ 32 字
- 没有明显变化就不写这一行
```

数据字典里补一句：**"状态变化是叙事结果，不是数值游戏；不要在正文里报数字。"**

## 6. 测试清单（先列，写码时逐条落地）

1. 类型 → 维度/步长表：表外类型 = 0、不记账；
2. 一轮多行只结一次（取更重）；
3. 单轮总变化 ≤ 20；
4. 夹 0..100（到 0 不越界、不到负）；
5. 每角色每维度单轮最多 1 条；
6. 导演轮次照记但不加码；
7. 协议行不进历史、不显示在气泡；
8. 分支隔离（A 分支的变化不出现在 B）；
9. 撤销写反向行且原行标记 revoked；
10. 老库自动建表（迁移幂等）。

## 7. 风险 / 开关

- ⚠ **这是"AI 内容自动改库"**：项目默认 `evolution.require_approval = true`，而这套是自动的 ——
  和当初「导演代价自动扣关系」一样，需要你**明确点头**（不是技术问题，是产品边界）。
- 建议加配置开关 `stat.auto_change`（默认 true），关掉后只记 `stat_changes` 不改 `characters`。
- 参数可配：单次上限 / 每轮上限 / 是否记存在感。
- 数值到 0 不锁任何功能（避免像导演代价那样把叙事卡死）。
