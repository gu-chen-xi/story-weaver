# 三维数值变更（体力 / 理智 / 存在感）· 设计稿 v2

> 状态：**已拍板 · 待实现**（2026-10-28，v2 按塘主 8 条决定改）｜相关：[README §11.4 边界](../README.md)、[SPEC](../dev/SPEC.md)、[提示词规则](../dev/提示词规则.md)

## 0. 一句话

体力 / 理智 / 存在感从「只读装饰」变成「真的会变」，但**数字不由模型给**：模型只报「发生了什么类型的事」，
软件按表给分、写进可撤销的变更账本。**默认关闭**，做成插件开关；关着的时候这三个值仍然只能手动改。

## 1. 现状（读代码确认）

| 项 | 事实 |
|---|---|
| 字段 | `characters.stat_stamina / stat_sanity / stat_screen`（0-100，默认 50）；`stat_emotion` 仍在表里但**不参与**（情绪由「当下」文字表达） |
| 档位 | `stat_tier`：0-19 很低 / 20-39 偏低 / 40-59 正常 / 60-79 偏高 / 80-100 很高 |
| 进提示词 | 尾部【数值与状态】按「档位(数字)」注入，焦点角色优先，自由模式最多 8 人 |
| 谁能改 | **只有手动**（角色卡编辑）+ 分支快照/回滚；演进提案不碰 `stat_*` |

## 2. 形态：插件，默认关

插件系统目前是**前端**的（卡片 + 开关 + 面板），后端没有插件机制。所以落地方式是「前端一张卡 + 后端一个开关」：

| 层 | 做什么 |
|---|---|
| 前端 | 插件页加卡 `stat-growth`（「三维数值自动变化」），默认关，开关写 `plugin.stat-growth.enabled`（现有 `pluginConfigKey()` 规范） |
| 后端 | 生成链路读这个 config：**关** → 不注入【状态变化】段、不解析、不写表（零 token、零行为变化）；**开** → 注入 + 结算 |
| 关闭时 | 三个数值仍然可以**手动改**（角色卡），和现在完全一样 |
| 卡片文案 | 必须写清「开启后会自动改角色数值（可在角色卡里看到并撤销）」 |

## 3. 边界：这套为什么「可以自动」

判据见 [README §11.4](../README.md)。落到本功能恰好三条都命中：

- **事实**（熬夜、受伤、被羞辱是「发生了什么」，不是「这意味着什么」）；
- **短尾**（只影响这一段，不改变设定/身份/关系定义）；
- **补后果、不抢方向盘**（她不因为你按了按钮就改变剧情走向，只是「累了」）。

并且满足自动三件套：**可见**（生成后提示）、**可撤销**（`stat_changes` 单条撤销）、**有上限**（单条封顶）。

## 4. 谁改：协议行 + 软件算分

这一轮回复的**末尾单独一行**（和 `〔态度〕`、`〔导演代价〕` 同属协议区，按形状剥，不进历史）：

```
〔状态变化〕熬夜：她一夜没合眼
```

类型 → (维度, Δ) 写在代码里（`STAT_KINDS`）；**提示词里只有类型和口径，没有数字**。
表外类型 = 0、不记账，只剥行。模型没写时，关键词兜底（同类命中 ≥2 词，只补空缺，一轮只结一次）。

## 5. 改多少：只设单条上限

**不设**「每轮总变化」和「每轮最多影响几个维度」——塘主定：给模型加这种约束它会乱输出。
每维度单条封顶：**体力 15 / 理智 10 / 存在感 5**。

| 维度 | 类型 | Δ | 说明 |
|---|---|---|---|
| 体力 | 熬夜 | −10 | 通宵没睡 |
| 体力 | 没睡好 | −5 | 只眯了两三个小时 |
| 体力 | 受伤 | −15 | 摔伤、被打 |
| 体力 | 生病 | −15 | 发烧、旧伤发作 |
| 体力 | 力竭 | −15 | 打完一架、跑了一路 |
| 体力 | 睡好 | **+15** | 一觉到天亮（同时给理智 +4） |
| 理智 | 被欺骗 | −10 | 发现被瞒了很久 |
| 理智 | 撞见无法解释的事 | −10 | 看见不该看见的 |
| 理智 | 崩溃 | −10 | 当众失控 |
| 理智 | 被安抚 | +10 | 有人把话说开 |
| 理智 | 想通 | +10 | 自己转过弯 |
| 理智 | 睡好 | **+4** | 与体力 `睡好` 同一条，一次给两个维度 |
| 存在感 | 被无视 | −3 | 全场没人接她的话 |
| 存在感 | 被当众羞辱 | −5 | 被点名嘲笑 |
| 存在感 | 被看见 | +3 | 有人特意提到她 |
| 存在感 | 被认可 | +5 | 当众被肯定 |

**软件侧去重（不写进提示词，模型不需要知道）**：

- 每角色每维度每轮最多 1 条；
- **同一故事日同一类型最多 1 条**（防同一类型一天刷多次，也让「睡好」一天只算一次）。

## 6. 存在感：慢变量，按天封顶

存在感不是「每轮都能变」的量，按天结算语义：**当天累计净额夹在 ±5**。

- 每个事件照记，但写入前算「该角色今天已经变过多少」；超过 ±5 的部分**不记**（界面提示「今天的存在感已经到上限」）；
- 净额为 0（比如被无视 1 次、被看见 1 次）→ 等于没变；
- 语义：0 = 透明人（别人会跳过她说话），100 = 全场焦点。它天然不需要每轮回。

## 7. 自然恢复：作息是事件，不跟「下一天」绑定

**不做**「每点一次下一天就 +15」——那会被刷分（塘主原话）。改成**握手协议**：

- 恢复和扣分一样走协议行；模型判断**这一夜/这一天到底发生了什么**，软件给数：
  - `睡好` → 体力 **+15**、理智 **+4**（对应塘主定的单天恢复量）；
  - `熬夜` → 体力 **−10**；
  - `没睡好` → 体力 **−5**；
- **换天不自动加**：只有叙事里真的休息了、模型报了 `睡好`，才恢复；点「下一天」但故事里她在赶路，就报 `熬夜`；
- 同一天 `睡好` 只算一次（见 §5 去重），所以刷不出来。

## 8. 何时改

- 每轮回复后结算一次（和导演代价同一条链路）；
- 只在**对话模式**（旁白是上帝视角扩写，不代表角色经历）；
- **导演轮次照记**，但不因导演指令额外加码（开挂的代价已在导演账本算过一次）；
- 协议行不进历史、不显示在气泡；
- 不触发演进提案，不等人工确认（这是本插件「开着」的前提）。

## 9. 怎么退：单条撤销

```sql
CREATE TABLE IF NOT EXISTS stat_changes (
  id           INTEGER PRIMARY KEY AUTOINCREMENT,
  branch_id    TEXT,
  node_id      INTEGER,
  message_id   INTEGER,
  character_id INTEGER NOT NULL,
  dim          TEXT NOT NULL,              -- stamina / sanity / screen
  delta        INTEGER NOT NULL,
  kind         TEXT NOT NULL,
  reason       TEXT NOT NULL DEFAULT "",
  source       TEXT NOT NULL DEFAULT "model",  -- model / rule / undo / user
  revoked      INTEGER NOT NULL DEFAULT 0,
  created_at   TEXT NOT NULL DEFAULT (datetime("now","localtime"))
);
```

- **单条撤销**：再写一行 `delta = -原值, source = undo`，原行 `revoked = 1`；历史只增不改；
- 同时写 `audit_logs`（operator = system）；
- **不做整库/整天回滚**（要整段重来用快照）；
- 界面：角色卡数值条旁「最近变化：熬夜 −10（3 天前）· [撤销]」。

## 10. 不可逆事实：人工

自动类型表里**没有**「死亡 / 致残 / 失忆」这类不可逆事件；这类只能通过角色卡手改或演进提案。
数值到 0 不锁任何功能（不强制昏倒），叙事后果由模型写。

## 11. 提示词段（只在插件开启时注入）

```
【状态变化】（给软件的对账行，不是剧情内容）
- 这一轮如果有人物状态发生明显变化，在回复末尾单独一行写：〔状态变化〕类型：理由
- 类型只能写：熬夜 / 没睡好 / 受伤 / 生病 / 力竭 / 睡好 / 被欺骗 / 撞见无法解释的事 / 崩溃 / 被安抚 / 想通 / 被无视 / 被当众羞辱 / 被看见 / 被认可
- 冒号前直接写类型名，不要写字段名；理由 ≤ 32 字
- 没有明显变化就不写这一行；同一轮最多写一条
- 举例：她熬了一夜没合眼 → 熬夜；有人把误会解释清楚了 → 被安抚；她睡到天亮才醒 → 睡好；
  当众被点名嘲笑 → 被当众羞辱；一整天没人接她的话 → 被无视
```

数据字典补一句：**「状态变化是叙事结果，不是数值游戏；不要在正文里报数字、不要写『体力 -10』。」**

## 13. 测试清单

1. 类型表：表外类型 = 0 不记账、只剥行；
2. 一轮多行只结一次（取更重）；
3. 单条封顶（体力 15 / 理智 10 / 存在感 5）；
4. 夹 0..100；
5. 每角色每维度每轮最多 1 条；
6. 同一故事日同一类型最多 1 条（`睡好` 一天只 +15 一次）；
7. 存在感当天累计夹 ±5（超出不记）；
8. 换天不自动加：没有 `睡好` 就不恢复；
9. 导演轮次照记但不加码；
10. 协议行不进历史、不显示；
11. 分支隔离；
12. 单条撤销写反向行 + 原行 revoked；
13. 插件关闭时：不注入、不解析、不写表；手动改仍可用；
14. 老库自动建表（迁移幂等）。

## 14. 风险 / 遗留

- ⚠ **没有「每轮维度数上限」**（塘主定）：最坏一轮可能 体力 −15 + 理智 −10 + 存在感 −5 = 30。
  目前靠「同日同类型 1 条 + 依赖模型叙事合理性」兜着；如果实测发现「一轮三降」很常见，再回来看要不要加结构约束。
- ⚠ **这是「AI 内容自动改库」**：默认关，开了才生效；开关关闭时零影响。
- 遗留：**关系强度的自动写入还没有 source/revoked 账本**（现在只写 `audit_logs`）。
  按塘主决定（负向自动、正向人工、每次自动写入带 source/revoked 可撤销），需要一个 `relation_changes` 表——
  建议单独一项做完（不改现有导演代价逻辑，只补账本），不要塞进本功能。
