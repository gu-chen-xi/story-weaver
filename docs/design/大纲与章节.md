# 剧本大纲 / 历史章节 / 伏笔清单 · 设计稿

> 状态：**已拍板 · 第一版待实现**（2026-10-30）｜相关：[SPEC](../dev/SPEC.md)、[提示词规则](../dev/提示词规则.md)

## 0. 一句话

三层分工：**大纲 = 写之前的意图**（幕/章/情节点）；**剧情区 = 按天写**；**历史章节 = 写之后的成稿**（只读+跳转）。
第一版只做「只读章节聚合」，先把“章”这个概念跑顺，再加大纲与伏笔。

## 2. 伏笔的定义（这一条最容易被做歪）

> 用户原话：**“当时不知道”才叫伏笔。**

判定五条，**同时满足**才算（宁漏不错）：

1. **具体**：能指认（物件/一句话/伤口/名字/数字/约定），不是氛围；
2. **当时不知道**：埋下时没有当场解释或兑现（当场兑现 = 事件，不是伏笔）；
3. **有指向**：文本给了异常感——特意描写、人物追问未答、反复出现的意象、反常反应；
4. **可回收**：后文能有一个“原来如此 / 终于来了”的动作；
5. **跨场景**：埋与收不在同一场（同场马上回收叫铺垫）。

可扫的信号：未回答的问题、被强调的物件、承诺/约定（关键记忆里的 `promise` 天然是一类）、异常细节、重复意象。

**排除项**：只出现一次且没被强调的日常道具 / 角色卡里已有的背景 / 当章就解释掉的细节 / 纯景色描写。

## 3. 数据模型（草案）

```sql
CREATE TABLE chapters (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  branch_id   TEXT,
  act         INTEGER NOT NULL DEFAULT 1,   -- 1/2/3 幕
  order_no    INTEGER NOT NULL,             -- 章序（1 起）
  title       TEXT NOT NULL DEFAULT '',
  synopsis    TEXT NOT NULL DEFAULT '',     -- 一句话梗概
  goal        TEXT NOT NULL DEFAULT '',     -- 本章目标（注入用，可空）
  target_words INTEGER NOT NULL DEFAULT 0,
  status      TEXT NOT NULL DEFAULT 'draft',-- draft/revising/final
  created_at  TEXT NOT NULL DEFAULT (datetime('now','localtime'))
);

CREATE TABLE chapter_nodes (
  chapter_id INTEGER NOT NULL,
  node_id    INTEGER NOT NULL,
  PRIMARY KEY (chapter_id, node_id)
);

CREATE TABLE foreshadows (
  id           INTEGER PRIMARY KEY AUTOINCREMENT,
  branch_id    TEXT,
  text         TEXT NOT NULL,               -- 埋了什么（作者写的原句/摘要）
  planted_chapter_id INTEGER,
  planted_node_id    INTEGER,
  window_chapters    INTEGER NOT NULL DEFAULT 3, -- 预期几章内回收
  payoff_chapter_id  INTEGER,
  status       TEXT NOT NULL DEFAULT 'planted',  -- planted/payoff/overdue/dropped
  source       TEXT NOT NULL DEFAULT 'manual',   -- manual/ai
  note         TEXT NOT NULL DEFAULT '',
  created_at   TEXT NOT NULL DEFAULT (datetime('now','localtime'))
);
```

说明：
- 章是**独立实体**；与天的关联表保留多值结构，但**语义上一天只属于一章**（加进新章会自动从旧章摘掉）；
- 大纲的“已完成”由**统计**得出（章下关联天的字数），不写回时间线；
- 伏笔的“逾期”由 `window_chapters` 与当前最大章序比较得出，不存布尔。

## 4. 第一版：只读章节聚合

| 功能 | 行为 |
|---|---|
| 新建章 | 选时间线节点（多选）→ 生成章卡；标题/状态可改，**正文只读** |
| 章卡 | 章号 · 标题 · 状态 · 字数（统计关联消息）· 节数（=关联天数）· 关联的天 |
| 进度 | 顶部：`章数 / 未归章天数`、累计字数 |
| 跳转 | 点章 → 打开剧情区第一个关联节点 |
| 未归章提示 | “还有 N 天没归章”，点一下列出 |
| 不注入 | 第一版**不往提示词里加任何东西** |

## 5. 第二版：大纲 + 注入

- 三幕视图 + 章卡（章号/标题/梗概/目标字数/状态/情节点徽标）；
- **每章目标** `goal`：生成时若当前节点属于该章、`goal` 非空、开关开 → 尾部块加：
  `【本章目标】…（写到这里为止，不要提前收束 / 不要跑题）`；
- 开关 `outline.inject`，**默认 true**；没写目标就整段不出现（零 token）；
- 情节点（激励事件/幕转折/中点/低谷/高潮）标在章上，只做展示与导出，**不进提示词**（先不给模型加结构约束）。

## 6. 第三版：伏笔清单

- 手动新建：写一句“埋了什么”、选埋在哪章/天、预期几章内回收；
- AI 提议：从摘要与正文扫（第 2 节那五条信号）→ 进「待确认」，**接受/拒绝**；拒绝的记 hash，不重复提；
- 状态：埋下 / 已回收 / 逾期 / 废弃；逾期在大纲页顶部计数；
- 不自动改任何剧情文本，只做清单与提醒。

## 7. 明确不做

- ❌ 不在历史章节里做第二个正文编辑器（只读 + 跳转）；
- ❌ 不做“章节版本表”（复用现有快照/回滚）；
- ❌ 不自动把天切成章（用户手动圈定）；
- ❌ 不用大纲反向改时间线（意图与事实分离）；
- ❌ 不把摘要与大纲合并（事后事实 vs 事前意图）。

## 8. 与 Ollama

Ollama 已有占位插件。定位是**可选通道**：单章目标生成、局部润色这类“短输入短输出”适合本地；
三幕 12 章这种长上下文仍走云端。第一版不接，等大纲编辑落地后再评估。

## 10. 待定（实现前确认）

1. 字数统计口径：算 `messages.content` 的字符数（含旁白/台词/标记剥掉后），不算元数据；
2. 一章跨多天时，导出顺序按“天在时间线上的顺序”，不按加入章的先后；
3. 章的删除：只删章与关联，**不删任何剧情**（明确提示）。
