## 1. 视觉基调

一句话：**冷灰底 + 单一暖橙强调 + 暖琥珀副层。**

| 不变量 | 具体 | 为什么 |
|---|---|---|
| 底色永远是**冷灰** | 色相 H 215–225°、饱和度 S 9–24% | 15 级灰度实测全落在这条线上（§3.1），已经统一，别破坏 |
| 强调永远是**暖橙** | `#FF7A18`，H 25.5°、S 100%、L 54.7° | 唯一的品牌色，铺开在 20+ 文件 |
| 副层是**暖琥珀** | 同色相族（H 20–39°），靠明度往上走（L 55→84%） | 暖色内部的明度阶梯，不引入第二个饱和色相 |
| 语义色只做**小面积** | ok / warn / danger，见 §3.3 | 面积一大就跟主色抢焦点 |

**这套配色的骨架是"冷暖对撞"**：底 222° 冷，强调 25° 暖，差 197°。所以它天然需要一个**低饱和的中间地带** —— 这就是为什么琥珀（暖但低饱和）能当副层，而蓝（高饱和、且撞在 222° 上）只能当功能色。

> 推论：**不要给这套配色配第二个品牌色。** 橙 + 蓝是撞色关系，大面积并列会把界面撕成两半。

`T.info` 的色相 222.1° **正好落在中性阶的 215–225° 区间里** —— 它是"高饱和版的冷灰"，不是外来色。所以它在暗灰底上不跳、很协调，这正是让蓝当功能色、而不是当品牌色的物理依据。

**`T.danger` 保持 `#f0554d`，不换色。** 见 §4 规则三。

**紫/青是"区分色"不是"品牌色"**（2026-11-28 定案）：它们只用于给并列的分区/分类做视觉区分（提示词分段色、角色 vs 关系），不进按钮、不进导航、不做强调。`T.purple` 的 S 100% 看着扎眼，所以它**只以小色块/小标签形式出现**，不许铺大面积。

## 4. 三条硬规则

### 规则一：一屏最多一个橙色主按钮

`T.accent` 的职责是"回答用户现在该点哪儿"。一屏出现两个以上橙面按钮，焦点就散了，用户得自己判断。

- ✅ 主按钮、选中 tab、当前步骤、主 CTA
- ❌ 列表项、图标、装饰线、普通卡片边框、**关闭按钮**
- 次要操作 = 灰色底 + `T.line` 描边；破坏性操作 = `T.danger`

### 规则二：蓝只做功能色

`T.info` 只用于**承载信息**的元素：数字、指标、状态标签、分区标记。

- ✅ "理智 62"、字数统计、存疑虚线、提示词分区色
- ❌ 主按钮、导航高亮、品牌露头、大面积背景

### 规则三：语义色不许只靠颜色传达

**实测**：`T.accent #FF7A18` 是 H 25.5°，`T.danger #f0554d` 是 H 2.9° —— **只差 22.6°**。在 8px 状态点、9.5px 小标签上，眼睛分不出来。

这不靠换色解决：红色系本身就扎堆在 0–15°，橙在 25°，**换任何红都拉不开 60°**（试过 `#e5484d`：H 358.1°，反而更近到 27.4°，而且更暗）。

正确做法（WCAG 1.4.1）：**语义永远带一个非颜色载体。**

- ✅ `⚠ 失败`、`✕ 删除`、`● 危险` —— 符号 + 文字
- ✅ 破坏性按钮用 `T.danger` 的**实底**，普通强调用 `T.accent` 的**渐变底**，靠形状区分
- ❌ 一个孤零零的红色圆点表示"有错误"

## 7. 不许进 `theme.ts` 的东西

| 东西 | 为什么 |
|---|---|
| 情绪词表配色（`perform.rs`） | 内容色，22 对「前景 + 浅底」；后端是唯一真相，前端 `emotionInfo()` 取用 |
| 分支配色池（`branch.rs`） | 内容色，按分支序号轮转，存进 `branches.color` 字段 |
| 用户上传的立绘/封面主色 | 不可预知 |
| HTML 导出件的配色（`export.rs`） | 导出是**浅色文档**（打印/阅读场景），跟暗色界面是两套，互不影响 |

**分支与情绪这一层不整（2026-11-28 塘主拍板）。** 它们是后端给的内容色，前端只渲染，不进配色收口范围 —— 包括 `perform.rs` 那套浅底 chip 在深色界面上的观感问题，也**不在 ② 里处理**。要动的话是独立的一次改动（换个底、或只取前景色），跟配色系统解耦。
