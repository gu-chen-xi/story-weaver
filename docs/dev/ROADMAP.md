## 二、还没做的

### 2.1 真欠账（有人问过、也确实没做）

| # | 事项 | 为什么没做 | 现在什么状态 / 下一步 |
|---|---|---|---|
| 1 | **429 / 5xx 自动重试与指数退避** | 当时判定"属重试范畴，另行评估"，优先做了超时与取消 | 代码里**无任何 retry/backoff**；只做了超时（90s 连接、60s 空闲）。要做需先定"重试几次、退避曲线、失败后是否保留半截内容" |
| 2 | **结构化抽取只覆盖"关系"类** | 用户决定后置，避免"能入队、批不了"的死锁 | 抽取器只产关系类提案；`apply_group` 对其它类型直接报错「暂不支持应用 X 类型提案」（`evolution.rs:569`）。新角色/地点/术语/世界观补充都还没有抽取器 |
| 3 | **立绘表情差分 ×4** | 后置：依赖生成通道稳定 + 差分提示词设计 | 未实现。现有 `stat_emotion` 是角色"情绪"数值，与立绘差分无关 |
| 4 | **立绘主色卡** | 后置 | 未实现 |
| 5 | **Ollama 本地模型插件** | 依赖插件系统提供"模型发现 + 下拉选择接入哪个模型" | 插件注册表里 `status: "planned"`，卡片是占位态，无任何实现 |
| 6 | **`portrait://` 自定义协议**（`assetProtocol.scope=["**"]` 的 C 方案） | SECURITY.md §3.2 已论证当前风险可接受（不能外发、不能提权），列为后续 | 未实现，仍是 `assetProtocol + convertFileSrc`。做它是为了让前端不再传任意绝对路径 |
| 7 | **`App.tsx` 继续拆分** | 逐批拆，有需求驱动再搬 | 现 1880 行（守卫上限 1950），剩下的主要是顶层状态 + 跨页逻辑 |
| 8 | **超时链路的运行时验证** | 属"人工验收"步骤，需要本地起一个只监听不响应的端口 | 有可复现步骤（起 8099 端口 + 改 base_url 发一条消息，预期约 90s 报超时），但没automated 化 |

> **RAG 的后续阶段**：目前只落地了 ①（回忆意图 + 摘要检索注入）。后面要不要做向量检索、要不要扩词表，**还没有正式编号**——需要时再规划，别在文档里假装已有计划。

### 2.2 明确不做（不是欠账，别再提）

| 事项 | 决定 | 理由 |
|---|---|---|
| **代码签名** | 不做 | 作者是学生、软件不赚钱、无证书（OV 一年几百到几千元 + 资质审核）。改交付"可验证性"：源码公开 + SHA256SUMS + [安全自证四件套](../user/security/README.md) |
| **自动更新** | 不做 | 避免"静默更新"这类风险；升级靠手动下载新版本 |
| **多用户 / 权限系统** | 不做 | 单机单人，数据目录权限 = 你的账户权限 |
| **加密数据库** | 不做 | 有意选择：无密码、方便备份/迁移/直接查库。需要加密就套 BitLocker/VeraCrypt，而不是做"半吊子加密" |
| **上帝视角扩写模式** | 不做 | 2026-10-20 用户明确放弃（"太麻烦"）。现有「旁白 / 对话」两态已够用；`messages.mode` 里的 `director` 值是历史遗留，不会再被写入 |
| **裸文本 = 元指令** | 不做 | 同上。元指令已由 `#标签` 承担；裸文本就是普通剧情，不再改造输入语法 |
| **蝴蝶效应预览** | 不做 | 同上。原设计是"改历史后对比新旧分支让用户选"，实现成本高；现有「设定版本 + 回滚」已能兜住误改 |

## 三、仍然有效的设计决策

| # | 决策 | 结论 |
|---|---|---|
| D1 | 跨天历史策略 | 近三天用原文 + 更早用摘要；摘要走 C 路线（分层），先落 B 层（日摘要），再叠阶段摘要 |
| D2 | 时间流逝的表现 | 日历/时间线用**灰色区间条**表现"无事件"，**不生成空节点**；用户点区间才插入事件 |
| D3 | "近三天"的口径 | **按节点数**（当前节点 + 前 2 个 day 节点），不按自然日 |
| D4 | 摘要的三条铁律 | ①生成一次就固化，绝不每轮重算 ②只追加不回改 ③摘要属稳定前缀，进 system 的【前情提要】段 |
| D5 | 评估模型评什么 | 评 **AI 回复质量**：输出排版 / 角色贴合 / 接续前文 / 剧情推进，四维 1–5 分，每维必须有证据引文，总分由软件算 |
| D6 | 检查的两层分工 | 本地规则只查纯结构；语法/歧义/数值矛盾交给 AI。AI 只报三类，不得评价文笔与创意 |
| D7 | 分支的适用范围 | **只做手动分叉**，不自动分叉；主要面向"主线 + 第一层分支"，嵌套在数据层可用但界面表达有限 |
| D8 | AI 输出的执行边界 | AI 只输出文本/JSON 补丁，**不接入 tool calling**；补丁经白名单校验 + 二次确认 + 快照后才落库 |
