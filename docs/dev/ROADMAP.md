### 2.2 明确不做（不是欠账，别再提）

| 事项 | 决定 | 理由 |
|---|---|---|
| **代码签名** | 不做 | 作者是学生、软件不赚钱、无证书（OV 一年几百到几千元 + 资质审核）。改交付"可验证性"：源码公开 + SHA256SUMS + [安全自证四件套](../user/security/README.md) |
| **自动更新** | 不做 | 避免"静默更新"这类风险；升级靠手动下载新版本 |
| **多用户 / 权限系统** | 不做 | 单机单人，数据目录权限 = 你的账户权限 |
| **加密数据库** | 不做 | 有意选择：无密码、方便备份/迁移/直接查库。需要加密就套 BitLocker/VeraCrypt，而不是做"半吊子加密" |
| **上帝视角扩写模式** | 不做 | 2026-10-20 用户明确放弃（"太麻烦"）。现有「旁白 / 对话」两态已够用；`messages.mode` 里的 `director` 值是历史遗留，不会再被写入 |
| **裸文本 = 元指令** | 不做 | 同上。元指令已由 `#标签` 承担；裸文本就是普通剧情，不再改造输入语法 |
| **蝴蝶效应预览** | 不做 | 同上。原设计是"改历史后对比新旧分支让用户选"，实现成本高；现有「设定版本 + 回滚」已能兜住误改 |

## 三、仍然有效的设计决策

| # | 决策 | 结论 |
|---|---|---|
| D1 | 跨天历史策略 | 近三天用原文 + 更早用摘要；摘要走 C 路线（分层），先落 B 层（日摘要），再叠阶段摘要 |
| D2 | 时间流逝的表现 | 日历/时间线用**灰色区间条**表现"无事件"，**不生成空节点**；用户点区间才插入事件 |
| D3 | "近三天"的口径 | **按节点数**（当前节点 + 前 2 个 day 节点），不按自然日 |
| D4 | 摘要的三条铁律 | ①生成一次就固化，绝不每轮重算 ②只追加不回改 ③摘要属稳定前缀，进 system 的【前情提要】段 |
| D6 | 检查的两层分工 | 本地规则只查纯结构；语法/歧义/数值矛盾交给 AI。AI 只报三类，不得评价文笔与创意 |
| D7 | 分支的适用范围 | **只做手动分叉**，不自动分叉；主要面向"主线 + 第一层分支"，嵌套在数据层可用但界面表达有限 |
| D8 | AI 输出的执行边界 | AI 只输出文本/JSON 补丁，**不接入 tool calling**；补丁经白名单校验 + 二次确认 + 快照后才落库 |

**顺带修掉一个自检误报**：`Tauri npm 包与 Rust crate 版本匹配` 原来读 `Cargo.toml` 的**声明最低版**

### 2026-10-21 修：回顾检测不到新加的物品（两个 bug + 一处权重设计问题）

用户实测：世界观里加了物品「rtx显卡」（**别名**「显卡」），第 4 天的日摘要里确实有「显卡」，
但「🔍 回顾试算」检测不到。

**真实数据摆在这里**：

```
world_settings: key='rtx显卡', category='物品', meta_json={"aliases":"显卡"}
timeline_nodes: 第 4 天 day_summary 含「显卡」✅
```

| # | Bug | 后果 |
|---|---|---|
| ① | `recall::explain`（试算用的那份）**自己复制了一份词典查询，且 category 列表没有 '物品'** | 试算面板里物品完全不存在 |
| ② | 两份词典都只取 `key`，**不解析 `meta_json.aliases`** | 用户输「显卡」（别名）永远匹配不上 |
| ③ | `entity` 权重 12 < `min_score` 20 | 就算命中也 `picked=false` —— "检测得到却带不出来" |

**修法**：

1. 把词典构建合并成**唯一实现** `push_world_terms(pool, branch, &mut lexicon)`，
   `search` 与 `explain` 都调它 —— 根治"改一处漏一处"（这正是 ① 的成因）；
2. 加 `split_aliases(meta_json)` 解析别名（中英文逗号 / 顿号 / 分号；**单字别名丢弃**，
   因为单字误命中率太高），名称与别名一起进词典；
3. `entity` 权重 12 → **20**（与标签词同档）。理由：用户点名一个专有名词、
   且它真的出现在那天摘要里，是**最强信号**，不该比"日常标签词"还低。

**真实数据验证**（`cargo test --lib diag_explain_alias -- --ignored`，只读副本）：

```
=== explain("显卡") ===
第 4 天    score=   22 picked=true  理由=含「显卡」
第 2 天    score=    0 picked=false
第 3 天    score=    0 picked=false
第 5 天    score=    0 picked=false 理由=这天没有日摘要 —— 自动检索看不到它（手动选择不受限）
```

**测试**：`split_aliases_handles_separators` / `split_aliases_skips_empty_and_single_char` /
`single_entity_hit_reaches_min_score`（回归锁：实体单命中必须过门槛）。

**教训**：同一段逻辑复制两份，早晚会漂移。词典构建、提示词渲染这类"两处都要用"的东西，
必须抽成一个函数，否则一定出现"界面上有、试算里没有"。

### 2026-10-26 故事卡片的「前史」撑破卡片（**v3.8.0**）

**症状**：给故事补写很长的前史后，卡片上那一行会**一直往右长**，冲出卡片、压到列表容器外面，
而 `text-overflow: ellipsis` 看着像是写了却没生效。

**根因**：典型的 flex 陷阱 —— 卡片是 `display:flex`，左栏是 flex 子项但**没写 `min-width: 0`**，
flex 子项的默认 `min-width: auto` 等于内容最小宽度；配合 `white-space: nowrap`，
它就"撑到内容那么宽"，`ellipsis` 永远没有收缩空间。

**修法**：左栏 `flex: 1; minWidth: 0`；前史本身做成**限宽的单行小框**（虚线/实线边框 + `ellipsis` + `title` 悬停看全文）；
标题行、元信息行同样单行省略；卡片加 `overflow: hidden` 兜底。

**验证**：`tsc` 0 错 · 前端 140 项 · `vite build` 通过（纯样式，无单测）。

### 2026-10-26 关键记忆改「态度打分 + 累计一张卡」（**v3.8.0**）

**起因**：用户看完记忆卡后问「AI 拒绝了，这需要记吗？被拒多次不该每条都写吧」。
讨论后的方案（用户拍板）：

| 决策 | 内容 |
|---|---|
| 判定方式 | **只给这一轮 AI 的回复打分**，不再用 4 个拒绝词做布尔判断 |
| 打分规则 | 强/中/弱三档拒绝为正、接受为负；**负向优先**（「我不喜欢你」不会被判成接受）；**标点算短语的一部分**（「别。」才是拒绝，「别忘了带伞」不算）；`|分| ≥ 2` 才算有判定，否则「未定」 |
| 多次表白 | **同一张卡累计**：`attempts` 次数一直加，`stance` 记被拒/被接受，`reasons` 只留前 3（权重×次数） |
| 后来接受 | **同一张卡改判**（不新开一条），已接受的卡不会被后来的拒绝翻回去 |
| 正文 | 只留**最近一次**的用户消息 + AI 回复；更早的交给「🔍 回顾」 |
| 范围 | 只对「表白」这样做；承诺 / 牺牲 / 背叛仍按"每种只记第一次" |

**文件格式**：front matter 增加 `attempts` / `refusals` / `stance` / `score` / `reasons`（JSON 一行），
正文第一段就是给提示词用的摘要（`render_block` 不用改）。

**验证**：Rust **348** 项（328 + 20 ignored；`memory` 8 → **15**）·

**第二轮（同日，用户实测打脸第一版）**：三段真实拒绝回复（「别说了。」「这种话，我不接。」／「说多了，就不算数了。」／

  ① **只扫台词**（`「」`/`“”`），旁白里的「她没应声」不再影响判定；
  ② **短台词兜底**：≤24 字且含「不/没/别」算一条弱拒绝（词表补不全的正解）；
  ③ 词表补「别说了 / 我不接 / 不算数 / 我哪句话是同意 / 你一个人」等"只能是拒绝"的说法；

**第四轮（同日，换路线：不再猜自然语言）**：又出现「你这算什么。」「刚还念数字呢。」这类说法。
