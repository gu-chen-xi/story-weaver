# 日摘要 / 日结（两个请求，别混）

> 受众：开发者 ｜ 状态：现行 ｜ **最后核对：2026-11-14（按代码逐段核对）**

## 一句话

这是**两个不同的模型请求**：

| 请求 | 干什么 | 什么时候 | 提示词常量 |
|---|---|---|---|
| **日摘要** | 把"这一天"压成 200 字摘要（供很久以后再回读） | 一天结束 / 补摘要时 | `timeline/summary.rs::DAY_SUMMARY_PROMPT` |
| **日结** | 这一天收尾：摘要 + 作息 + 新实体抽取 + 告白（可选） | 用户点「下一天」 | `timeline/day_close.rs::DAY_CLOSE_PROMPT` |

## 代码入口

| 职责 | 代码：`文件::符号` |
|---|---|
| 日摘要生成（生成一次即固化） | `timeline/summary.rs::generate_day_summary` |
| 日摘要补跑 | `timeline/summary.rs::backfill_day_summaries` |
| 日结 | `timeline/day_close.rs`（`DAY_CLOSE_PROMPT` + `call_summary_model`） |
| 通用摘要调用 | `timeline/summary.rs::call_summary_model`（不是主模型，见 `docs/dev/SPEC.md` 的摘要模型口径） |
| 告白行解析 | `timeline/summary.rs::parse_confessions` / `strip_confessions` |
| 作息行解析 | `timeline/day_close.rs`（`SLEEP_TAG`） |
| 新实体行解析 | `evolution/new_entity.rs`（`〔新角色〕/〔新地点〕/〔新术语〕/〔世界观〕/〔改角色〕/〔改设定〕`） |

## 请求长什么样（两者同构）

```
[system]   DAY_SUMMARY_PROMPT 或 DAY_CLOSE_PROMPT（纯文本，无角色卡/无世界观）
[user]     【第 N 天】的剧情记录：
           [用户] …
           [AI] …（已剥导演指令标记）
           …（整段 transcript，最多 24000 字）
           + 日结额外追加：【已有角色】清单 + 【已有设定】清单
```

**没有**历史、没有角色卡、没有关系图、没有记忆 —— 摘要模型只读这一天的记录。

## 关键差异

| 维度 | 日摘要 | 日结 |
|---|---|---|
| 长度要求 | 200 字以内，一段 | 同 + 允许"这一天没有值得写的事" |
| 告白行 `〔告白〕` | **有**（一天最多 3 行） | 无（告白只在日摘要里判） |
| 作息行 `〔作息〕` | 无 | **有**（`角色名：睡好\|熬夜`） |
| 新实体行 | 无 | **有**（先喂【已有角色】【已有设定】，只写清单外的） |
| 固化策略 | 生成一次即固化（已有摘要不再回改） | 每次点「下一天」都跑（但摘要若已有则复用） |

## 为什么要给"已有清单"

实测 deepseek-flash 在**不给清单**时会一条 `〔新角色〕` 都不写（它不知道谁算"旧的"）。
所以日结的 user 末尾固定拼一段：「只写**不在这两份清单里**的新东西」。
