# 已知坑与测试（日摘要 / 日结）

> 最后核对：2026-11-14 ｜ 上游：[`README.md`](README.md)

## 踩过的坑

| 坑 | 症状 | 现在的处理 |
|---|---|---|
| 不给"已有清单" | 模型一条 `〔新角色〕` 都不写 | 日结 user 末尾固定拼【已有角色】【已有设定】 |
| 摘要重跑覆盖旧值 | 昨天看过的前情提要今天变了 | 日摘要**生成一次即固化**，已有值直接返回 |
| 协议行进摘要 | 前情提要里出现 `〔作息〕…` | 解析后立刻剥掉（`strip_confessions` 等） |
| 超长的一天 | 请求超过上下文窗口 | transcript `take(24000)` 截尾 |
| 摘要模型说"没有内容" | 空摘要覆盖了正常摘要 | 空/纯协议行 → 不写库 |
| 阶段摘要重复覆盖 | 同一段被压两次 | 见 `04-phase-summary`（`ignore_covered` + 重叠清理） |

## 手工验收

1. 开发者工具 →「请求快照」：日结请求的 `system_prompt` 应等于 `DAY_CLOSE_PROMPT`（一整段），
   `user_text` 末尾应能看到两份清单；
2. 日结完 → 「关键记忆」页：不应出现"写入失败"；
3. 时间线「第 N 天」的摘要：不应含台词原文或 `〔…〕` 行。

## 什么时候回来更新

- 改 `DAY_SUMMARY_PROMPT` / `DAY_CLOSE_PROMPT` 的任何一句（它们直接决定摘要质量）；
- 加新的 `〔…〕` 行（同时更新 `../common/协议标记清单.md`）；
- 改清单注入格式或 24000 字截断值。
