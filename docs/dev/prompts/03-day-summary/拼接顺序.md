# 拼接顺序（日摘要 / 日结）

> 最后核对：2026-11-14（按代码逐段核对）｜ 上游：[`README.md`](README.md)

## A. 日摘要（`DAY_SUMMARY_PROMPT`）

| # | 部分 | 内容来源（`文件::符号`） | 说明 |
|---|---|---|---|
| 1 | system | `timeline/summary.rs::DAY_SUMMARY_PROMPT` | 纯文本常量：只写事实 / 不写台词 / 200 字 / 第三人称；末尾要求判 `〔告白〕` |
| 2 | user 第 1 行 | `format!("【{node_label}】的剧情记录：")` | 节点标签来自 `timeline_nodes.date_label` |
| 3 | user transcript | `timeline/summary.rs::generate_day_summary` 内拼装 | 每条 `[用户] / [AI]`，**已剥导演指令标记**（`relations::strip_director`） |
| 4 | 截断 | 同上 | 整段 `take(24000)` 字 —— 超长的一天会被截尾（设计选择：宁可少读也不爆窗） |

## B. 日结（`DAY_CLOSE_PROMPT`）

| # | 部分 | 内容来源 | 说明 |
|---|---|---|---|
| 1 | system | `timeline/day_close.rs::DAY_CLOSE_PROMPT` | 摘要 + 作息 + 新实体，三段机器可读要求合并在一份常量里 |
| 2 | user transcript | 同 A 的第 2~4 步 | 同一天的记录 |
| 3 | **【已有角色】清单** | `timeline/day_close.rs`（拼在 user 末尾） | 只给名字（+定位），让模型知道谁算"旧的" |
| 4 | **【已有设定】清单** | 同上 | 地点 / 术语 / 世界观条目名 |
| 5 | 收尾一句 | 同上 | 「只写**不在这两份清单里**的新东西」 |

> 两份清单**必须先给**：不给的话模型一条 `〔新角色〕` 都不写（2026-11-07 实测）。

## C. 落库与副作用

| 动作 | 位置 |
|---|---|
| 摘要写回 `timeline_nodes.day_summary` | `timeline/summary.rs` |
| 写一条 `debug_requests`（可在开发者工具看到） | `timeline/day_close.rs` |
| `〔告白〕` → 记忆卡（`ai_confession`） | `timeline/day_close.rs` → `memory::record_ai_confession_as` |
| `〔作息〕` → 三维结算 | `timeline/day_close.rs` |
| `〔新角色〕…` → 提案队列（只入队，**不自动落库**） | `evolution/new_entity.rs` |

## D. 与主生成的边界

- 这两个请求**不带**角色卡 / 世界观 / 关系 / 记忆 —— 只读当天文本；
- 它们也不吃 `prompt.roleplay_scope`（日报/日结与视角无关）；
- 摘要模型与主模型可以不同（见 `docs/dev/SPEC.md` 的摘要模型口径）。
