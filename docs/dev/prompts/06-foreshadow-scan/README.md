# 伏笔扫描（本地单步 / 云端两步）

> 受众：开发者 ｜ 状态：现行 ｜ **最后核对：2026-11-14（按代码逐段核对）**

## 一句话

拿**本批章节原文 + 往前 3 天的前情摘要**，让模型找出"当时没说清、后面应当回收"的东西，
产出 `〔伏笔〕<东西或话题>` 行 → 入伏笔表（不自动改正文）。

## 两条路

| 路 | 提示词 | 模型 | 步数 |
|---|---|---|---|
| 本地 | `lib.rs::local_scan_system_prompt()` | Ollama 本地模型（插件页勾「伏笔扫描走本地」） | **单步**（直接列伏笔） |
| 云端 | `lib.rs::cloud_scan_system_prompt()` | 主模型 | **两步**（① 列细节 + `→ 是/否`，② 把「否」改写成伏笔） |

为什么要双规制：本地 7B **做不了"这条当场有没有被消化"的判断**（实测「是」出现率 0/4），
所以本地只让它列举；云端模型能判，就多要一步。

## 代码入口

| 职责 | 代码：`文件::符号` |
|---|---|
| 本地命令 | `lib.rs::scan_foreshadow_local` |
| 云端命令 | `lib.rs::scan_foreshadow_cloud` |
| 共用核心 | `lib.rs::scan_foreshadow_core` |
| 提示词（本地/云端） | `lib.rs::local_scan_system_prompt` / `lib.rs::cloud_scan_system_prompt` |
| 前情窗口 | `foreshadow.rs::context_window`（本批 + 往前 3 天） |
| 第一步丢行自检 | `foreshadow.rs`（数条目 vs 数判断） |
| 逾期计算 | `foreshadow.rs::is_overdue`（3 章窗口） |
| 落库 | `foreshadow.rs::scan_proposals_in` → `foreshadows` 表 |

## 输入长什么样

```
[system]  扫描提示词（本地单步 / 云端两步）
[user]    【前情摘要】<往前 3 天的日摘要>
          【本批章节原文】<本批覆盖的天，已剥导演/协议/状态标记>
```

**不带**角色卡、世界观、关系、记忆 —— 与主生成完全解耦。
