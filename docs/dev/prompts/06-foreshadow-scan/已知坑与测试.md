# 已知坑与测试（伏笔扫描）

> 最后核对：2026-11-14 ｜ 上游：[`README.md`](README.md)

## 踩过的坑

| 坑 | 症状 | 现在的处理 |
|---|---|---|
| 第一步丢行 | 列 6 条、只判 5 条（用户实测） | 完整性自检：数"带编号条目" vs "标了 →是/→否 的条目"，不一致就报警 |
| 只写 1 条伏笔 | 第二步输出过短 | 取第一步判「否」的细节**直接兜底**，不再问第二遍 |
| 把台词当伏笔 | `〔伏笔〕她说以后别来了` | 过滤含人名/代词/引号/问号的行 |
| 幻视"用户/AI" | `〔伏笔〕用户声称…` | 云端提示词**禁止**出现「用户」「AI」二字；解析侧仍兜底过滤 |
| 重复入表 | 同一件事扫两次出两条 | 与已有伏笔按名字去重 |
| 跨批候选丢了 | `prev_found` 恒空 | `accumulate_prev_found` 真写入了（去重 + 最近 10 条） |
| 本地不可用静默失败 | 点了没反应 | 明确报"没勾本地扫描" / "连不上 Ollama"，**不自动切云端** |

## 手工验收

1. 插件页开「扫描伏笔走本地」→ 点扫描 → 应出现若干 `〔伏笔〕…` 条目；
2. 再点一次 → **不应重复入表**；
3. 云端扫描：开发者工具里应能看到**两步**输出（第一步带 `→ 是/否`）；
4. 逾期：把某条伏笔埋在前 4 章之前、仍未回收 → 界面上应显示"逾期"。
