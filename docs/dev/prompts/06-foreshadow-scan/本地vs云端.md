# 本地 vs 云端（伏笔扫描）

> 最后核对：2026-11-14（按代码逐段核对）｜ 上游：[`README.md`](README.md)

## 差异表

| 维度 | 本地（Ollama） | 云端（主模型） |
|---|---|---|
| 提示词 | `lib.rs::local_scan_system_prompt()` | `lib.rs::cloud_scan_system_prompt()` |
| 步数 | **单步**：直接列 `〔伏笔〕…` | **两步**：① 逐条 `细节 → 是/否`；② 只把「否」改写成 `〔伏笔〕…` |
| 条数上限 | 见提示词（不设硬上限，靠"别凑数"约束） | 第一步**最多 12 条**，且**每条都必须标判断** |
| 判据 | 只问"当时没说清、后面该回收" | 追加判据"**当场有没有被消化**"（解释过/接住过/用掉了 = 是） |
| 为什么这么设计 | 本地 7B 判"是/否"不可靠（实测「是」0/4） | 云端能判，所以多要一步，减少"把已消化的东西当伏笔" |
| 兜底 | 回「无」→ 空列表 | 第一步判「否」的条目会被**直接取出来兜底**（模型常只写 1 条） |

## 两份提示词共同的硬约束

1. **只写东西或话题本身**，不写谁做了什么、不出现人名；
2. **不出现「我/你/他/她」**（云端还额外禁止出现「用户」「AI」这两个词）；
3. **不照抄台词**；心声/台词不是伏笔，只是"句子里没交代清楚的那个东西"；
4. **不要为了凑数硬找**：找不到就输出「无」+ 一句原因；
5. 20 字以内、一行一条、严格前缀 `〔伏笔〕`。

## 好/坏写法（提示词里自带例子）

| | 例子 |
|---|---|
| ❌ 坏 | 夏婉琴说以后别来了的狠话（写了人、写了动作） |
| ✅ 好 | 「以后别来了」的狠话 / 门闩上的手 / 抽屉里的两把钥匙 |

## 选哪条路

| 情况 | 建议 |
|---|---|
| 有本地 Ollama 且模型 ≥ 7B | 可以本地扫（免费），但要接受"漏判" |
| 想少误报、或本地模型很小 | 走云端（花 token，但两步式更稳） |
| 两者都开着 | 各自产出各自入表，去重靠名字 |
