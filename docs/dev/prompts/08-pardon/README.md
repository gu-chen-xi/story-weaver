# 赦免请求（她原不原谅那条导演指令）

> 受众：开发者 ｜ 状态：现行 ｜ **最后核对：2026-11-14（按代码逐段核对）**

## 一句话

导演账本里点「请求赦免」→ 单独发一次**元对话**请求（不是剧情），
模型按角色性格回「同不同意」，最后一行用 `〔赦免:同意/不同意〕` 表判。

## 代码入口

| 职责 | 代码：`文件::符号` |
|---|---|
| 提示词拼装 | `pardon.rs::profile_block` + `pardon.rs` 内的补充说明 |
| 请求 | `pardon.rs::request_pardon` |
| 结算 | `pardon.rs::apply_pardon` |
| 列表 | `pardon.rs::list_requests` |

## 请求长什么样

```
[system]  （主生成的 system 前缀：角色卡 / 世界观 / 关系…
           由 prompt.rs::build_system_prompt 拼，PromptScope::default() → 全局视角）
          + 【本次任务的边界】这是元对话，不是剧情；不要续写场景
          + 【你的设定与当前关系】…（角色卡摘要 + 与"我"的关系强度/态势）
          + 【回答模板】先写理由与想说的话，最后一行〔赦免:同意〕/〔赦免:不同意〕
[user]    刚刚那条导演指令 + 当时的代价收据 + 请求原谅的那句话
```

## 关键边界（写在提示词里）

1. **不是剧情**：不要续写场景、不要输出旁白，只回一两句态度 + 协议行；
2. **按强度档位表演**：强度低 / 态势破裂时**不许心软**（"不要用软话给台阶"）；
3. **协议行必须在最后一行**：软件只认最后一行（`apply_pardon` 解析）。

## 与主生成的关系

- 它复用主生成的 **system 前缀**，但**不吃** `prompt.roleplay_scope`（这里传的是 `PromptScope::default()`）；
- 它**不写历史**（元对话不入时间线）；
- 产出直接落 `pardon_requests` + 导演账本（同意才回补一半关系）。

## 验收

1. 有导演指令的那天 → 点「请求赦免」→ 回复末尾应有一行 `〔赦免:同意〕` 或 `〔赦免:不同意〕`；
2. 同一条消息最多 3 次、同一故事日最多 5 次（超出应拒绝）；
3. 强度低 / 破裂时，回复**不应**出现"算了""这次就原谅你"这类软化（那是提示词被改坏了）。
