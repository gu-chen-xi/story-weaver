# 协议标记清单（跨场景共用）

> 受众：开发者 ｜ 状态：现行 ｜ 最后核对：2026-11-14（按代码逐段核对）

## 一句话

这些 `〔…〕` 标记是**软件和模型之间的暗号**：只为解析服务，**不进正文、也不该留在历史里**。
历史装配时会被剥掉（`strip_*` 一族），否则模型会把它当"每轮都要写"的惯例照着抄。

## 清单

| 标记 | 谁要求写 | 谁解析 | 会进历史吗 | 代码：`文件::符号` |
|---|---|---|---|---|
| `〔态度:接受/拒绝〕` | 表白轮：`prompt.rs::stance_hint()`；非表白轮：`memory.rs::render_block_for()` 的改判出口 | `memory/attitude.rs::parse_marker()` | ❌（`memory::strip_marker`） | `attitude.rs`、`prompt.rs` |
| `〔导演代价〕` | 有导演指令的那一轮：`director.rs::cost_legend()` | `director.rs`（解析 + 落库） | ❌（`director::strip_receipt`） | `director.rs` |
| `〔导演指令〕` | 用户在输入台写的原文（不是模型） | `relations.rs`（`DIRECTOR_TAG`） | ❌（`relations::strip_director`） | `relations.rs` |
| `〔承诺〕` | `promise.rs::hint()`（有待兑现承诺时） | `promise.rs`（状态结算） | ❌（`promise::strip*`） | `promise.rs` |
| `〔作息〕角色：睡好/熬夜` | 日结提示词（`timeline/summary.rs`） | `day_close.rs`（结算三维） | —（日结是一次性请求） | `timeline/day_close.rs` |
| `〔赦免:同意/不同意〕` | `pardon.rs`（赦免请求） | `pardon.rs::apply_pardon` | 视场景 | `pardon.rs` |
| `〔状态变化〕`（插件开启时） | `stat_change.rs::legend()` | `stat_change.rs` | ❌（`stat_change::strip_line`） | `stat_change.rs` |

## 两条硬规则

1. **同一轮只教一次**：表白轮用 `stance_hint`，普通轮才用记忆块里的改判出口 ——
   否则模型会写两行一样的标记（解析只认第一行，那是运气不是设计）。
2. **进历史前一律剥掉**：`generate_stream.rs` 装配历史时会依次调用
   `relations::strip_director` → `director::strip_receipt` → `memory::strip_marker` → `stat_change::strip_line`。
   漏掉任何一个的症状都是"模型开始自己编协议行"（历史上真出现过 `〔态度:冷淡〕` 这种表外值）。

## 加新标记时要一起改的地方

| 步骤 | 位置 |
|---|---|
| ① 定义常量 | 对应模块（如 `promise.rs::TAG`） |
| ② 写进提示词 | 该场景的尾部块（`prompt.rs::build_tail_block` 或场景自己的拼装函数） |
| ③ 解析 | 模块里的 parser + 测试 |
| ④ **从历史里剥掉** | `generate_stream.rs` 的历史装配处 + 一份测试 |
| ⑤ 登记进本表 | 本文件 |
