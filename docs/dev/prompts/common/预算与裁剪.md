# 预算与裁剪（跨场景共用）

> 受众：开发者 ｜ 状态：现行 ｜ 最后核对：2026-11-14（按代码逐段核对）

## 一句话

主生成的上下文不是"塞满窗口"，而是**先算固定成本、再倒推历史能留几条**；
固定在前、易变在后，是为了吃**前缀缓存**（同一段前缀不重算，省钱也省时间）。

## token 怎么估（前后端同一套系数）

| 字符 | 系数 |
|---|---|
| 汉字 | 0.79 |
| 英文字母 / 数字 | 0.20 |
| 空白 | 0.12 |
| 标点 | 0.39 |

后端 `tokens.rs::estimate()`、前端 `lib/parse.ts::estimateTokens()` —— **两边必须同步改**。

## 预算公式（主生成）

```
历史可用预算 = 窗口 × 安全系数 − 输出预留 − 固定区(实测) − 摘要区(实测) − 尾部块 − 本次输入预估
每日基准预算 = 历史可用预算 ÷ 保留天数
N（每天保留几条） = 每日基准预算 ÷ 单条消息平均 token
```

| 常量 | 值 | 位置 |
|---|---|---|
| 保留天数 `KEEP_DAYS` | **3** | `generate_stream.rs::KEEP_DAYS` |
| 单条消息最小均值 `MIN_AVG_MSG_TOKENS` | 400 | `generate_stream.rs::MIN_AVG_MSG_TOKENS` |
| 世界书命中预算 `LORE_BUDGET` | 1200 字 | `generate_stream.rs`（局部常量） |
| 关键记忆预算 | 1200 字 | `memory.rs::render_block_for` 调用处 |
| N 值/降级计算 | — | `generate_stream.rs::plan_day_limits` |

## 降级顺序（预算不够时先牺牲谁）

1. 最老的**整段原文**先被降级 → 它的日摘要进【前情提要】；
2. 日摘要再被阶段摘要吞并（`coalesce_with_phases`）；
3. 记忆按"重要度 + 时间"排队，装不下的整卡跳过；
4. 世界书按优先级（`priority`）进，超预算的整条跳过并计数（`lore_skipped`）。

## 为什么这么排（前缀缓存）

- `system` 只放**跨轮不变**的东西（规则、字典、世界观、角色卡、关系方向）；
- 会变的全进尾部：当前模式、篇幅、数值与当下、世界书命中、记忆、示例、聚焦、约束、导演指令；
- 尾部不进 `system`，避免"每轮改一个字，整段缓存全废"。

## 已知代价（不是 bug）

- 世界书/记忆被裁时**模型真的不知道** —— 设计选择是"宁缺不超窗"；
- `KEEP_DAYS = 3` 意味着第 4 天以前的细节只剩摘要，长线伏笔要靠回忆检索或章目标兜。
