## 三、日常工作流

```powershell
cd D:\project\ai生成

npm run tauri dev        # 开发（前端热更新 + Rust 后端）
```

改完代码，**三道关**必须全绿：

```powershell
npm test                              # 前端纯逻辑（项数以输出为准，见 测试用例.md §一）
cd src-tauri; cargo test --lib        # Rust（项数以输出为准，见 测试用例.md §一）
npx tsc --noEmit && npm run build     # 类型 + 构建
```

**CI 跑的就是这三关**（2026-11-10 起，`.github/workflows/test.yml`）：

| job | 跑什么 | 在哪 | 大概多久 |
|---|---|---|---|
| `web` | `tsc --noEmit` → `npm test` → `npm run doclinks` → `npm run build` | ubuntu（公共仓库 Actions 不计时长） | 1 分钟内 |
| `rust` | 先 `npm ci && npm run build`（tauri 编译期要读 `dist`），再 `cargo test --lib` | **windows-latest** —— 项目只支持 Windows，`deny.toml` 也只审 Windows 目标，不能拿 ubuntu 顶 | 首次 ~8 分钟，有缓存后 ~3 分钟 |
| `Security`（另一个工作流） | `cargo-deny check advisories bans sources` + `npm audit` | ubuntu | 1~2 分钟 |

> CI **不打包、不发版** —— `tauri build`、`pack-portable`、打 tag、建 Release 都是作者手动的（见 §四）。
> 触发条件：`test.yml` 跟 push 到 main / 每个 PR；`security.yml` 是每周一 + 依赖文件变了才跑（免得把红叉刷成背景）。

提交：**格式与硬约束看 [开发规范.md §3](开发规范.md)**（`type(scope): 中文描述`、push 前必须征得同意）。

流程上的两条（这里只管顺序）：
- **提交前**：先报改动摘要 + 拟用提交信息；
- **提交后**：告诉用户"没推 / 已推"，推之前再确认一次。

## 四、打包与发布

```powershell
npm run tauri build       # 自动带 custom-protocol，产出 MSI + exe
```

**只想在自己机器上跑**（不打包 MSI）：

```powershell
npm run sync:run          # 构建前端 → 带特性编 exe → 验证不是 dev 版 → 同步到运行目录
```

> `sync:run` 是手动构建的**唯一推荐方式**：它固定带 `--features custom-protocol`，
> 构建完还会**验证**（查构建脚本输出里有没有 `cargo:rustc-cfg=dev`），
> 不通过就不复制；目标 exe 正在运行会提前拦下。
> 2026-10-25 就是手搓 `cargo build --release` 漏了特性 → 白屏（[E-BOOT-03](错误合集.md)）。

> ⚠ **不要**手搓 `cargo build --release` 而不带特性 —— 那样出来的 exe
> 仍会去连 `localhost:5173`，表现为"页面拒绝连接"（见 [错误合集 E-BOOT-03](错误合集.md)）。

**版本号要三处对齐**（自检工具会查这个）：

`package.json` · `src-tauri/tauri.conf.json` · `src-tauri/Cargo.toml`

**产物**（`dist-package\`，已 gitignore，不进仓库）：

| 文件 | 说明 |
|---|---|
| `Story-Weaver_<版本>_x64_en-US.msi` | 安装包 |
| `Story-Weaver-<版本>-portable.zip` | 便携版 |
| `SHA256SUMS.txt` | 哈希清单（发布页要贴） |

**便携 zip 用脚本打，别再手搓**（2026-10-30 定的）：

```powershell
node scripts/pack-portable.mjs <版本>     # 等价于 npm run pack:portable -- <版本>
```

它把三件事钉死：① 包里**只准** `README.txt` + `Story-Weaver.exe`（多一个文件就报错退出）；
② 打包前把两个文件的 mtime **钉成同一个值**（默认取 exe 的 mtime、截到整秒）——
同样的内容 + 同样的 mtime ⇒ 同样的字节 ⇒ **同样的哈希，重打可复现**；
③ 哈希清单自己写（UTF-8 无 BOM / CRLF / 两行），不会出现 `Out-File` 那种带 BOM、`sha256sum -c` 读不了的文件。

> 为什么要有这条：3.11.0 发版前手搓过一次 zip，结果包里那份 `README.txt` 还写着旧测试项数（465 vs 实际 472），
> 换工具重压一次哈希又变了、发布说明里写死的 sha256 直接对不上。`node scripts/pack-portable.mjs <版本> --check`
> 可以只校验"清单与产物是否一致"，不改文件。

### 本地跑起来之后，哪些东西只有 dev 有

| 能力 | dev（`npm run tauri dev` / `npm run sync:run`）| 打包版（`npm run tauri build`）|
|---|---|---|
| 侧栏「🔧 开发者工具 · 请求快照」 | ✅ 有 | ❌ 没有（导航项包在 `import.meta.env.DEV` 里）|
| `list_prompt_snapshots` / `get_prompt_snapshot` | ✅ 能调 | ❌ 直接报错「请求快照只在开发构建里可用」（`dev_snapshot_guard()`）|
| `debug_requests` 表本身 | ✅ 照常写 | ✅ 照常写（参数页的「实测 / 估算」靠它）|

> 所以**别拿打包版去看"当时发给模型了什么"** —— 那一页是给排查用的，用户版故意不带。
> 要核对就 `npm run tauri dev`，或在 `sync:run` 的窗口里看。

**发布步骤**：打 tag → 推 → GitHub Release 贴 `docs/user/releases/<版本>.md` 正文 +
SHA256SUMS → 提醒用户"无代码签名，首次运行会被 SmartScreen 拦"（说明见 [SECURITY.md](../../SECURITY.md)）。

> tag 必须打在**文档齐全**的提交上。v3.1.0 就踩过：tag 先打在 `d341ea7`，
> 那之后的提交才补进验证文档，只好把 tag 挪到 `bb98aee`。

## 五、出问题怎么查

### 第一步：先跑自检工具，别从零猜

```
双击 scripts\selfcheck\selfcheck.cmd
```

退出码 **0 = 可用**，**1 = 有问题**；报告落在 `debug-diagnostics\selfcheck-<时间>.txt`。
**出问题就把这个文件发出来**，比口述准得多。

它检查十几项（2026-10-28 数了源码里 **22 种结果标签**；实际跑了多少项看输出的「结论：可用（通过 N 项…）」），其中三个"只有它能抓到"：

| 检查 | 为什么单测抓不到 |
|---|---|
| **主窗口真的建出来了吗**（枚举窗口 + 尺寸） | Tauri 建窗口失败时进程照活着、无 panic |
| **有没有去连 dev 服务器**（假监听器数连接） | 缺 `custom-protocol` 时进程完全正常，只是页面报"拒绝连接" |
| **数据目录真能不能写**（真写探针） | 同一目录 Python 能写、app.exe 不能；`create_dir_all` 会骗人 |

详见 [自检工具.md](自检工具.md)。

### 第二步：对照报告结论

| 报告结论 | 大概原因 |
|---|---|
| `指定的 exe 存在 = FAIL` | 没构建 release，或 `-ExePath` 指错 |
| `exe 内嵌了前端 = FAIL` | 构建时漏了 `custom-protocol` |
| `Tauri npm 包与 Rust crate 版本匹配 = FAIL` | npm 包与 crate 版本不匹配，CLI 拒绝启动 |
| `主窗口已创建 = FAIL` | ① exe 在 `ai生成` 这类风险目录 ② WebView2 缺渲染组件 |
| `没有去连 dev 服务器 = FAIL` | 同上，缺 `custom-protocol` |
| `start.cmd 用的数据目录可写 = FAIL` | 权限/安全软件拦截；换可写盘并设 `DREAMWEAVER_DATA_DIR` |
| 有 `SKIP` | **没测成，不代表通过** —— 看 Detail 为什么 |

### 第三步：还是没有 → 按症状查错误合集

[错误合集.md](错误合集.md) 有 **89 条**真实坑位 + 9 个分区标题（2026-10-30 实测 `^#{2,3} E-` = 98），按**症状**排版（白屏 / 打不开 / 数据不对 / 构建炸…）。

## 六、已知问题

### K1 · 设定演进对非焦点角色的误伤 —— ⏸️ 搁置

- **现象**：AI 回复里同时出现多个角色名 + 表白/接受信号时，规则引擎会把所有"单向"关系都生成方向变更提案。
- **根因**：规则引擎只按"文本含两端角色名 + 信号词"判断归属，**不判断本次焦点角色**；AI 还可能写错角色名。
- **现状（2026-10-20 复核）**：`evolution.rs` 里仍**没有**焦点判断逻辑，状态未变。
- **下一步**：引入段落归属判断，或改用模型辅助分析器（后置）。
