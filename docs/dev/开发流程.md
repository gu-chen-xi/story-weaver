## 七、排查"打不开"的标准流程

> 2026-10-16 曾连踩 5 个**静默失败**（数据目录不可写 / 日志插件失败 / `.cmd` 中文注释被 GBK 撕碎 /
> exe 目录名叫 `ai生成` 导致 Tauri 建不出窗口 / 缺 `custom-protocol` 导致页面连 localhost）。
> 共同点：**进程活着、没有报错、日志停在中途** —— 单元测试完全抓不到。
> 排查过程已固化成工具，**下次直接跑它，不要从零开始猜**。

### 第一步：跑启动自检

```
双击 scripts\selfcheck\selfcheck.cmd
```

- 退出码 **0 = 可用**，**1 = 有问题**
- 报告会自动存到 `debug-diagnostics\selfcheck-<时间>.txt`
- 出问题时**把这个文件发出来**，比口述现象准得多

它检查 14 项，重点是这 3 个"只有它能抓到"的：

| 检查 | 为什么单测抓不到 |
|---|---|
| **主窗口真的建出来了吗**（枚举窗口 + 尺寸） | Tauri 建窗口失败时进程照活着、无 panic |
| **有没有去连 dev 服务器**（起假监听器数连接） | 缺 `custom-protocol` 时进程完全正常，只是页面报"拒绝连接" |
| **数据目录真能不能写**（真写探针文件） | 同一目录 Python 能写、app.exe 不能；`create_dir_all` 会骗人 |

### 第二步：看报告里说了什么

| 报告结论 | 大概原因 |
|---|---|
| `指定的 exe 存在 = FAIL` | 没构建 release 版，或 `-ExePath` 指错 |
| `exe 内嵌了前端 = FAIL` | 构建时漏了 `--features custom-protocol` |
| `Tauri npm 包与 Rust crate 版本匹配 = FAIL` | npm 包比 Rust crate 新/旧，CLI 会拒绝启动 |
| `主窗口已创建 = FAIL` | ① exe 在 `ai生成` 这类风险目录下（用 `start.cmd`）② WebView2 缺渲染组件 |
| `没有去连 dev 服务器 = FAIL` | 同上，缺 `custom-protocol` |
| `start.cmd 用的数据目录可写 = FAIL` | 权限/安全软件拦截，换可写盘并设 `DREAMWEAVER_DATA_DIR` |
| 有 `SKIP` 项 | **没测成**，不代表通过 —— 看 Detail 里为什么 |

### 第三步：确认构建命令

```powershell
npm run build
cd src-tauri
cargo build --release --features custom-protocol   # ← 这个特性不能省
```

漏了 `--features custom-protocol` 会得到一个"**看似打包、实则仍要 dev 服务器**"的 exe。

### K1：设定演进对非焦点角色的误伤（"秦旭识别不对"）
- **现象**：AI 剧情回复中同时出现多个角色名 + 表白/接受信号时，规则引擎会把所有"单向"关系都生成方向变更提案。
