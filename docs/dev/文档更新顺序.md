## 一、为什么"顺序"是刚需

文档之间不是并列的，是**投影关系**——下游写的是上游的摘要。

```
代码（唯一真相）
  └→ SPEC 定义了行为
       └→ UI_TREE 描述界面怎么呈现这个行为
       └→ 测试用例 验证这个行为
            └→ ROADMAP 记"这个功能做完了"
                 └→ README 对外宣布"我们支持这个功能"
```

**先改下游 = 双倍返工**：你先把 README 写成"支持 X"，回头 SPEC 一改口径，README 又得重写。
**先改上游 = 一次到位**：SPEC 定稿后，下游照抄它。

## 二、六层顺序（照这个顺序改）

| 层 | 文档 | 什么时候动 | 为什么在这一层 |
|---|---|---|---|
| **0** | **代码** | — | 唯一真相，其它都是它的投影 |
| **1** | `dev/SPEC.md` | 功能行为变了 | 行为的正式定义，下游全部依赖它 |
| | `dev/提示词规则.md` | 动了 prompt 拼接 | 提示词是"产品行为"的一部分 |
| | `dev/UI_TREE.md` | 动了页面/组件 | 界面的结构定义 |
| | `dev/PLUGINS.md` | 动了插件系统 / 加插件 / 改插件契约 | 插件契约（卡片、面板、开关、宿主数据）的唯一定义，插件与守卫都照它写 |
| **2** | `dev/测试用例.md` | 加了测试 / 改了跑法 | 从第 1 层推导：行为变了，验证也该变 |
| | `dev/自检工具.md` | 动了 `scripts/selfcheck` | 同上 |
| **3** | `dev/ROADMAP.md` | 功能做完 / 发现欠账 | 账本：只记"当前状态"和"还差什么" |
| | `dev/开发流程.md` | 构建 / 跑测 / 提交方式变了 | 操作手册：命令改了这里必须改，否则下一个人照着跑会撞墙（`sync:run` 就是为 E-BOOT-03 补的）|
| | `dev/错误合集.md` | **踩了坑才加** | 坑位索引，不主动维护 |
| | `dev/开发规范.md` | 模块/目录/命令变了 | 硬约束与约定 |
| **4** | `README.md` | 对外能看见的变化 | 门面：简介 / 下载 / 版本记录 |
| | `SECURITY.md` | 威胁模型 / 支持范围变了 | 对外安全承诺 |
| | `user/数据与备份.md` | 存储位置/表结构/备份方式变了 | 用户最关心的一件事 |
| | `user/security/*.md`（4 份） | 威胁模型 / 权限 / 自证步骤 / 发行文件名变了 | 用户"自己验一遍"的全部命令都在这里，错一条等于自证失效 |
| | `LICENSE` / `LICENSE-CONTENT` | **几乎不动**（法律文本） | 动了要连带改 5 处，见 §四 |
| | `user/releases/<版本>.md` | 发版时 | 发布说明正文 |
| **5** | `docs/README.md` | **最后改** | 索引：它指向的文档都定稿了才对 |
| | `AGENTS.md` | 红线变了才动 | 给 AI 的硬约束，越稳定越好 |

> `design/` 三份是**设计依据**（状态=已落地），除非重新设计，否则不动。

## 四、三条铁律

1. **上游没定稿，别动下游** —— 否则下游要改两遍（本轮踩过：先改 README 再改 SPEC，返工一次）。
2. **数字不写死** —— 写命令，让读者自己跑（测试项数、行数、文件大小都在变）。
   唯一例外：**用户要照抄的文件名**（下载校验命令），因为那是复制粘贴用的。
   **行数尤其要当心量法**：(Get-Content <文件>).Count 在本机按 GBK 解码，含中文的文件会吞行尾换行（App.tsx 曾因此少算 126 行）；Measure-Object -Line 会跳过空行。用 (Get-Content <文件> -Encoding utf8).Count 或直接数 LF 字节，见 [错误合集 E-DOC-04](错误合集.md)。
3. **改完跑一遍工具**：
   ```powershell
   node docs/tools/doc-impact.mjs            # 按 git diff 反查受影响文档
   node docs/tools/doc-impact.mjs --grep 世界书   # 谁提到了"世界书"
   npm run doclinks                          # 链接校验（这个在根 package.json 里）
   ```

## 五、典型场景的完整清单

### A. 加一个功能（例：世界书）

```
1. 代码写完、测试绿
2. SPEC.md        加一节行为定义
3. UI_TREE.md     加了什么入口/面板
4. 提示词规则.md   如果进了 prompt
5. 测试用例.md     跑 cargo test --list 重新生成清单
6. ROADMAP.md     从"欠账"移到"能用"（或加一条"已完成"）
7. README.md      简介 + 版本记录
8. docs/README.md 索引（如果新增了文档）
```

### B. 发版

```
1. 代码 + 测试全绿
2. 三处版本号核对（package.json / tauri.conf.json / Cargo.toml）
3. npm run tauri build
4. README      徽章 / 下载链接 / 校验命令 / 版本记录
5. SECURITY    对应版本 + 支持范围
6. ROADMAP/docs/README/开发流程  版本号
7. 安全四件套  文件名里的版本号（4 个文件）
8. releases/<版本>.md  发布正文
9. 贴 Release 前：把正文里的相对链接改成绝对地址（`https://github.com/<owner>/<repo>/blob/<tag>/docs/...`），
   否则 Release 页点开全是 404（E-REL-03）
10. 打 tag → 推 → 贴 Release → 用 API 复核附件 name/size（别只信上传成功的提示）
```

### C. 改许可

```
1. LICENSE / LICENSE-CONTENT
2. package.json / Cargo.toml / package-lock.json
3. src/compliance.ts（license 名 / URL / 声明正文 / NOTICE_VERSION）
4. App.tsx / CompliancePage.tsx（标题措辞）
5. README §十 + 徽章
6. SECURITY.md 扫一遍
```

> 许可那次踩过：**改 LICENSE 不会自动改 UI**，而用户是靠点"同意"免责的，
> 两处不一致等于免责条款作废。

### D. 加一个插件

```
1. 抄 src/plugins/_template/ 建目录（manifest / panel / index）
2. src/plugins/registry.tsx 加一行
3. 跑 npx tsc --noEmit && npm test && cargo test --lib   ← 守卫会检查"模板不许进注册表"
4. PLUGINS.md        契约有变化才改（加字段 / 加宿主数据 / 改能力声明）
5. UI_TREE.md        §七 插件页：卡片从哪来、哪些入口变了
6. 测试用例.md        新增/变化的守卫项
7. ROADMAP.md        只有"用户能看到的能力"变了才加行
```

> 加插件**不改** `PluginsPage` / `PluginCard` / `usePlugins` —— 这是 v3.5.7 定的边界，
> 守卫 `plugins_page_must_not_branch_by_id` 会拦。真要改它们，说明契约该改，回来改本文件 §三。

## 六、工具：`doc-impact.mjs`

放在 `docs/tools/` 下（**文档侧工具，不进根目录**），零依赖，Node 内置模块。

| 用法 | 作用 |
|---|---|
| `node docs/tools/doc-impact.mjs` | 读 `git diff --name-only`（含未提交改动），按规则列出受影响文档 |
| `--staged` | 只看暂存区 |
| `--range origin/main..HEAD` | 看某段提交范围 |
| `--grep <关键词>` | 反查：哪些文档提到了这个词（文件:行号） |
| `--rules` | 打印当前的路径→文档规则表 |

输出的分两档：**必改（P0）** 和 **应查（P1）**。

> 规则表就是本文件 §三 那张矩阵的代码版。**改矩阵时同步改脚本里的 `RULES`**。
