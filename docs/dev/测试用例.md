## 四、启动自检

`scripts\selfcheck\selfcheck.cmd`（纯 cmd + PowerShell，不依赖 node/rust，用来排查"应用打不开"）。

脚本分 5 个区：**产物与版本 / 路径安全 / 真实启动测试 / 启动日志 / 结论**。

判定语义（重要）：

| 结果 | 含义 |
|---|---|
| `PASS` | 通过 |
| `WARN` | 通过但不理想（例如 exe 放在风险目录，已复制规避） |
| `SKIP` | **没测成**，不代表通过（例如找不到可测的 exe） |
| `FAIL` | 有问题 |

> CLI 退出码：`0` = 可用，`1` = 有问题。
> 已知 flaky：`主窗口已创建` 在 `cargo build --release` 之后**偶发**失败（约 2/8），复跑即过。

## 七、写测试的约定（避免踩过的坑）

1. **涉及 schema 的功能，必须有"从空库建起"的测试** —— 老库早就迁移过，测不出全新安装的崩（真实事故：`init_story_db` 少跑迁移）。
2. **回归测试要能证伪**：先把 bug 加回去，确认测试变红，再恢复。只看"测试通过"没有意义。
3. **不要在测试里往用户数据目录写文件**（中间产物一律写 `paths::test_root()` 或临时目录）。
4. **权重/阈值类参数要有下限或上限**（真实事故：单条均 token 实测 30 → N 算成 599 条/天）。
5. 前端只测 `src/lib/**` 的纯函数（没有 DOM 环境），页面交互靠自检 + 手工验收。
