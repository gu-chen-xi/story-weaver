## 四、启动自检（14 项）

`scripts\selfcheck\selfcheck.cmd`（纯 cmd + PowerShell，不依赖 node/rust，用来排查"应用打不开"）：

产物存在性 / 三处版本号一致 / Tauri npm 包与 Rust crate 版本匹配 / 数据目录可写 /
库能开 / 表结构齐全 / 主窗口枚举（含"等待 X.Xs"与窗口列表）…

> 已知 flaky：`主窗口已创建` 在 `cargo build --release` 之后**偶发**失败（约 2/8），
> 复跑即过。看到它失败先复跑一次再下结论。

## 五、症状 → 先查什么（给排查的人 / agent）

| 症状 | 先跑 / 先看 |
|---|---|
| 应用起不来、白屏 | `scripts\selfcheck\selfcheck.cmd`；再看 `data\logs\startup-trace.log` |
| 新建故事后报 `no such column: branch_id / parent_id` | `cargo test --lib fresh_story_db`（全新库 schema 回归）|
| 某个天数的选择/断档不对 | `cargo test --lib timeline`；查 `timeline_nodes`（`sort_order`、`parent_id`）|
| 生成内容重复/串行、停止无效 | `cargo test --lib generate_stream`（`stream_guards` 组，校验每个 emit 带 requestId）|
| 上下文超预算 / 前情提要不对 | 生成参数页「每日 N 值」；`cargo test --lib generate_stream`（`budget_tests` / `phase_recap_tests`）|
| 该带出的旧剧情没带 | 导演监视器「🔍 回顾试算」输入同一句话；`cargo test --lib recall` |
| 分支里下了天加到主线去了 | `cargo test --lib timeline::branch_resolve_tests`（共享历史不得覆盖 UI 分支）|
| 检查/补丁应用错字段 | `cargo test --lib check`（白名单、字段归一）|
| 回滚后数据不对 / 快照缺 | `cargo test --lib evolution`（`rollback_*`、`snapshot_diff`）|
| 立绘图片不显示 | 检查 `library/default/shared/portraits/` 与 `portraits.path`；CSP 是否允许 `asset:` |
| 出图失败 | `cargo test --lib generator`；`generator_cloud`（请求体/鉴权）|
| 调试记录涨到几十 MB | 设置 → 数据管理（概览 + 清理）；上限配置 `debug.max_rows`（默认 300，每次生成前自动裁）|
| 前端页面结构被改坏（App.tsx 膨胀） | `cargo test --lib frontend_guard`（行数上限 + 抽出的模块不许回填）|

## 六、诊断测试（`#[ignore]`，需真实库）

这些**不会**在 `cargo test` 里跑，需要手动指定真实库：

```powershell
$env:DW_DIAG_DB = "D:\...\data\library\default\projects\7\story.db"
cargo test --lib diag_phase_plan -- --ignored --nocapture
```

| 用例 | 看什么 |
|---|---|
| `timeline::diag_phase_plan_on_real_db` | 阶段摘要"会不会生成、覆盖哪几天" |
| `timeline::diag_manual_rebuild_on_real_db` | 手动重压能否绕过旧阶段覆盖 |
| `timeline::diag_x_cases_on_real_db` | x=5/7/10 各自的覆盖区间 |
| `generate_stream::diag_phase_recap_on_real_db` | 合并前后行数/字数与节省量 |
| `recall::diag_explain_on_real_db` | 一句话会带哪几天、为什么、各多少分 |
| `recall::diag_recall_tags_on_real_db` | 每天的派生标签与命中情况 |

> **注意**：诊断测试只**只读**打开真实库（早期版本会复制到真实数据目录，留下垃圾文件 —— 已修）。

## 七、写测试的约定（避免踩过的坑）

1. **涉及 schema 的功能，必须有"从空库建起"的测试** —— 老库早就迁移过，测不出全新安装的崩（真实事故：`init_story_db` 少跑迁移）。
2. **回归测试要能证伪**：先把 bug 加回去，确认测试变红，再恢复。只看"测试通过"没有意义。
3. **不要在测试里往用户数据目录写文件**（中间产物一律写 `paths::test_root()` 或临时目录）。
4. **权重/阈值类参数要有下限或上限**（真实事故：单条均 token 实测 30 → N 算成 599 条/天）。
5. 前端只测 `src/lib/**` 的纯函数（没有 DOM 环境），页面交互靠自检 + 手工验收。
