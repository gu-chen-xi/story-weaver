# 启动自检工具

> 受众：使用者 / 排查者 ｜ 状态：**现行** ｜ 最后同步：**2026-10-25**（按 `selfcheck.ps1` 实测重写；补与 `sync:run` 的分工）
>
> 一个**能独立于应用运行**的诊断工具，专门查"应用打不开"这类静默故障。
> 双击 `scripts\selfcheck\selfcheck.cmd` 即可 —— 黑框框，**不需要 node / Rust / 浏览器**。

---

## 为什么需要它

2026-10-16 排查"打不开"时，接连踩了 **5 个叠在一起的静默失败**：

| # | 故障 | 为什么难发现 |
|---|---|---|
| 1 | 数据目录写不进去 | 同一目录 **Python 能写、app.exe 不能**；`create_dir_all` 返回成功也可能写不了 |
| 2 | 日志插件初始化失败 | 让**整个应用起不来**（exit 101），且发生在错误对话框之前 |
| 3 | `.cmd` 里写中文注释 | cmd.exe 按 GBK 读 UTF-8，注释被撕碎**当成命令执行** |
| 4 | exe 所在目录名叫 `ai生成` | Tauri **建不出主窗口，完全静默**（进程活着、无 panic、日志停在"数据库就绪"） |
| 5 | 缺 `custom-protocol` 特性 | 打包版也去连 `localhost:5173`，页面"拒绝连接"，但**进程完全正常** |

**共同点：全都静默。** 单元测试（常规用例全绿时也一样）**永远抓不到**这类问题 ——
它测"函数对不对"，不测"这个 exe 在这台机器上能不能真的跑给人用"。

---

## 怎么用

```
双击 scripts\selfcheck\selfcheck.cmd
```

| 项 | 说明 |
|---|---|
| 输出 | 中文报告，**同时落盘**到 `debug-diagnostics\selfcheck-<时间>.txt` |
| 退出码 | **0 = 可用**，**1 = 有问题** |
| 出问题时 | 把报告文件发给开发者（比口述现象准得多） |

### 可选参数

```powershell
# 检查指定的 exe（默认用项目里的 target\release\app.exe）
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\selfcheck\selfcheck.ps1 -ExePath "D:\某处\app.exe"
```

## 检查项（16 个逻辑项，分 5 个区）

> 脚本里有 21 个不同的结果名（同一检查的 PASS / WARN / SKIP 用不同文案），
> 归并后是 **16 个逻辑检查项**。**实际通过几项看输出的「结论」行**，别背数字。

### 一、产物与版本（7）

| 检查 | 判据 | 为什么查 |
|---|---|---|
| 指定的 exe 存在 | 文件存在 | 指错路径时**不会偷偷回退**到别的 exe |
| 打包版 app.exe 存在 | 文件存在 | — |
| 按 start.cmd 的方式复制到安全路径 | 复制成功 | 见"为什么默认会先复制" |
| 前端产物 `dist\index.html` 存在 | 文件存在 | 没 dist → release 版内嵌的是空前端 |
| 三处版本号一致 | `package.json` / `tauri.conf.json` / `Cargo.toml` | 不一致说不清"我在跑哪版" |
| Tauri npm 包与 Rust crate 版本匹配 | major.minor 相同（**比 Cargo.lock 的解析版本**，不是 Cargo.toml 声明的最低版）| 不一致时 CLI 直接报 `version mismatched` |
| Tauri 插件版本一致（Rust vs npm）| 每个 `tauri-plugin-*` crate 与对应 `@tauri-apps/plugin-*` 的 major.minor 相同（只比前端确实装了的）| **不一致时 `tauri build` 会拒绝打包**，而单元测试与 `vite build` 全绿 —— 2026-10-21 就是这么被静默挡住的 |

> **2026-10-21 修过一次误报**：这条原来读 `Cargo.toml` 的声明值（`tauri = "2.11.6"`，caret 允许 2.12.x），dependabot 把 `Cargo.lock` 升到 2.12.4 后就拿 "2.11" 去比 npm 的 "2.12.4" → FAIL，但两边实际都是 2.12.4。现在改为优先读 `Cargo.lock`，读不到才退回声明值。
| **exe 内嵌了前端** | 全文搜 `<!doctype html` | 没有 → 仍会去 `localhost:5173` 取界面 |

### 二、路径安全（4）

| 检查 | 判据 | 为什么查 |
|---|---|---|
| **exe 路径不含风险目录名** | 祖先链里没有 `ai生成` | 实测该目录名下 Tauri 建不出主窗口。命中时若已复制规避 → WARN |
| start.cmd 用的数据目录可写 | **真写探针文件** | 写不了就起不来 |
| 数据根候选至少一个可写 | 逐级探测（%APPDATA% / %LOCALAPPDATA% / exe 同级） | 需要"至少有一条活路" |
| 找到含故事的数据库 | `library.db` 存在且 >10KB | 数据目录对不上时用户会以为"故事丢了" |

### 三、真实启动测试（4）

| 检查 | 判据 | 为什么查 |
|---|---|---|
| 启动前清理遗留进程 | 杀掉同名残留进程 | 残留进程会抢窗口/占文件 |
| 进程能启动并保持运行 | N 秒后仍在 | — |
| **主窗口已创建** | `EnumWindows` 找到 `class=Tauri Window` 且宽>500、高>400 | ⭐ **最有价值**：Tauri 建窗口失败**完全静默** |
| **没有去连 dev 服务器** | 假监听器收到 0 次连接 | 缺 `custom-protocol` 时会连 5173（**构建阶段**就拦住它的工具是 `npm run sync:run`，见下） |

### 四、启动日志（1）

| 检查 | 判据 | 为什么查 |
|---|---|---|
| 没有启动失败日志 | 不存在 `startup-error.log` | 存在 → WARN，说明之前失败过 |

只显示**最近一次**启动的 `startup-trace.log` 关键行（trace 是追加写的，只取最后一段，避免刷屏）。

### 五、结论

汇总 PASS / WARN / SKIP / FAIL，并单列"**有 N 项没测成（不代表通过）**"。

## 关键设计（都是踩坑换来的）

### 1. "可写"必须真写一个文件

```powershell
# 错：只看目录在不在
if (Test-Path $dir) { "可写" }

# 对：真写探针
Set-Content -Path "$dir\.probe" -Value ok    # 抛异常才算不可写
```

实测踩到：某机器上"**已存在目录可写、新建目录被拒**"，`create_dir_all` 返回成功仍写不进去。

### 2. "窗口正常"必须枚举窗口

我一开始把"进程还活着"当成"启动成功"，**这是错的** —— 让用户白试了 4 轮。
Tauri 窗口创建失败时进程照活着。只能靠 `EnumWindows` 枚举 + 检查尺寸。

> 顺带一个坑：P/Invoke 声明 `GetClassNameW` 时**必须加 `CharSet.Unicode`**，
> 否则 `StringBuilder` 按 ANSI 编组，宽字符被截成第一个字节 ——
> `"Tauri Window"` 变成 `"T"`，于是明明有窗口却报"没找到"。（自己先踩了一遍）

### 3. 检查项失败要说"没测成"，不能默认通过

- 窗口枚举功能不可用 → `SKIP`（不是 PASS）
- 5173 已被占用 → 跳过假监听器探测 → `SKIP`
- 结论里单独列"有 N 项没测成（不代表通过）"

### 4. 为什么默认会**先复制**再测

实测（同一台机器、同一个 exe）：

| exe 位置 | 结果 |
|---|---|
| `…\ai生成\src-tauri\target\release\app.exe` | ❌ 只有 Tao 事件窗口，**主窗口建不出来** |
| `%LOCALAPPDATA%\DreamWeaverRun\app.exe` | ✅ `class=Tauri Window 标题="织梦机" 尺寸=1295x837` |

用户实际用的是 `start.cmd`（它先复制到 `%LOCALAPPDATA%\DreamWeaverRun`，没有该变量时退到 `D:\DreamWeaverRun`），
所以自检也测"复制后"的那份 —— 否则会一直误报 FAIL。
"直接双击 target\release\app.exe 会失败"这件事，单独作为 **WARN** 提示。

### 5. `.ps1` 必须靠 `.cmd` 带 `-ExecutionPolicy Bypass` 拉起

直接双击 `.ps1` 会被执行策略拦（`PSSecurityException`）。`.cmd` 是**纯 ASCII**（实测非 ASCII 字节 0 个）。

### 6. `.ps1` 必须存成 **UTF-8 带 BOM**

Windows PowerShell 5.1 读**无 BOM** 的 UTF-8 会按 GBK 解释：
中文变乱码 → 引号/括号被破坏 → 一堆莫名 ParseError。（实测前三字节 `239,187,191` = BOM）

## 自证：它真的能抓到问题

工具最危险的是"全绿但没用"。所以做了**故障注入回归**：

| 场景 | 期望 | 实测 |
|---|---|---|
| 正常（模拟 start.cmd） | 全通过、退出码 0 | ✅ 通过，退出码 0 |
| exe 放在 `…\ai生成\…` 下 | 报「主窗口已创建」失败、退出码 1 | ✅ 命中，且给出祖先链 |
| `-ExePath` 指向不存在的文件 | 报「指定的 exe 存在」失败 + 启动测试 SKIP、退出码 1 | ✅ 命中，**不会偷偷回退** |

> 初版有 3 个误报（HTML 只扫前 6MB、窗口类名被截断、危险目录判定过严），
> 全是靠"故意制造问题看它抓不抓得到"发现的。

## 和 `npm run sync:run` 的分工

两者都在防"exe 打不开"，但**管的阶段不一样**：

| 工具 | 什么时候跑 | 管什么 | 不管什么 |
|---|---|---|---|
| `npm run sync:run`（`scripts/sync-run.mjs`）| **构建时** | 前端先构建 → 固定带 `--features custom-protocol` → 断言构建脚本输出里**没有** `cargo:rustc-cfg=dev` → 复制到运行目录并核 sha256 | 不测窗口能不能建、不测路径安全 |
| `scripts\selfcheck\selfcheck.cmd` | **构建后 / 出问题时** | 这份 exe 在这台机器上**能不能真的跑起来**（真启动、枚举窗口、假监听器）| 不改构建参数、不修 exe |

> E-BOOT-03（漏 `custom-protocol` → 白屏）的根因在**构建**，所以修复也放在构建阶段（`sync:run`）；
> 自检那条"没有去连 dev 服务器"是**事后确认**，两者互补，缺一个都会留缝。

## 不做的事（有意）

| 不查 | 原因 |
|---|---|
| **端口占用** | 应用**不监听任何端口**。5173 是 **vite 开发服务器**占的，不是应用 |
| 内存 / CPU / 句柄 | 那是长期运行监控，不是启动问题 |
| 通用网络连通性 | 运行时问题，且会误报（用户可能就想用本地模型） |
| DB schema 完整性 | `cargo test` 的常规用例已覆盖（**314 项**；另 20 项 `#[ignore]` 是真机诊断，不参与）|
