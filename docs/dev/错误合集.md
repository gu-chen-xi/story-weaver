# 错误合集（坑位索引）

> 受众：开发者 / AI agent ｜ 状态：**现行**（2026-10-20 建立，条目分批从 ROADMAP §10.x 迁入）｜最后同步：2026-10-20

## 这份文档解决什么问题

ROADMAP 记"做了什么"，这份记"**哪里会炸、炸了怎么修、怎么防止再炸**"。
遇到问题的第一反应应该是来这里按**症状**搜，而不是全文搜 5000 行 ROADMAP。

## 怎么用

1. 先查下面的**症状索引**，按你看到的现象找条目号
2. 找到条目 → 看「根因」判断是不是同一个问题 → 按「修法」处理
3. 修完补一句「防复发」：有没有测试、守卫、grep 能挡住它

## 症状索引

> 条目编号规则：`E-分区-序号`，例：`E-DB-03`。**只增不删**，修好的条目改状态而不是删除。

| 你看到的现象 | 先查 |
|---|---|
| 应用双击打不开 / 白屏 / 转圈不出界面 | E-BOOT-* |
| 数据对不上、节点丢失、分支切了看不到内容 | E-DB-* |
| 界面崩了、渲染错位、点了没反应 | E-UI-* |
| 调用 AI 报错、流式输出中断、token 异常 | E-AI-* |
| 编译失败、依赖装不上、打包出不来 | E-BUILD-* |
| 文档链接失效、数字对不上 | E-DOC-* |

## 条目模板

```markdown
### E-DB-01 · 一句话概括现象

- **症状**：用户/开发者实际看到什么（贴报错原文，别转述）
- **根因**：为什么会这样（不是"哪里改的"，是"为什么"）
- **修法**：当时怎么解决的（含关键代码位置）
- **防复发**：哪条测试 / 守卫 / grep 能挡住它；没有就写"无，靠 review"
- **状态**：已修复 / 已知未修（附原因）
```
