# v3.10.0 — 数值真的会动了，作息交给「日结」

> 发布 **2026-10-29** · 上一版 [v3.9.0](https://github.com/gu-chen-xi/story-weaver/blob/v3.10.0/docs/user/releases/v3.9.0.md)
>
> 这一版的主题是「**让"发生了什么"自己落到数值上，但只动能被撤销的那部分**」：
> 体力 / 理智 / 存在感第一次会随剧情变化（插件默认关，每次都能单条撤销）；
> 作息不再让模型每轮瞎猜，改成点「下一天」时结算一次；关系强度也有了可撤销的账本。

---

## 一、三维数值：会动了，但只按"发生了什么"

**以前**：体力 / 理智 / 存在感只存在数据库和界面上 —— 剧情里她熬了一夜、被当众羞辱、被人安抚，
数值一动不动，得你自己去角色页手改。

**现在**：插件页多了一张卡「🌱 三维数值自动变化」（**默认关**，要你自己打开）。
打开后，模型在回复末尾写一行「发生了什么」，**数字由软件查表算**：

```
〔状态变化〕被当众羞辱：他在饭桌上把她的旧事讲了出来
```

| 类型 | 变化 |
|---|---|
| 受伤 / 生病 / 力竭 | 体力 **−15** |
| 被欺骗 / 撞见无法解释的事 / 崩溃 | 理智 **−10** |
| 被安抚 / 想通 | 理智 **+10** |
| 被无视 −3 / 被当众羞辱 −5 | 存在感 **−3 / −5** |
| 被看见 +3 / 被认可 +5 | 存在感 **+3 / +5** |

（共 **12 种**"事件类"；另外 2 种作息类只在日结里出现，见第二节。）

规矩是**几条硬上限**，都写在代码里，模型碰不到数字：

- **单条封顶**：体力 15 / 理智 10 / 存在感 5 —— 再狠的一场戏也掉不出一个 0；
- **存在感按"当天净额"封顶 ±5**：一天被夸十次也只涨 5，不会变成"刷存在感"；
- **同日同类型只算一次**（睡好这类特殊）；
- **夹在 0~100**，换天**不自动恢复**（要恢复靠剧情或你手改）；
- **一次只认一条**（末尾协议区里的第一条），表外类型直接不记。

每次变化都写进 `stat_changes` 账本，导演监视器属性条下面会列「数值变化（最近 5 条）」，
每条带**撤销**按钮 —— 撤销是"反向补一次"，并留痕。**插件关着时三项仍可手改**，手改 = 重设基线（会清掉当天的累计）。

> 设计依据（协议、类型表、上限、去重、撤销、插件开关的完整口径）：
> [三维数值变更（设计稿）](https://github.com/gu-chen-xi/story-weaver/blob/v3.10.0/docs/design/三维数值变更.md)。

## 二、作息：从"每轮猜"改成"点下一天时结一次"

**为什么删「没睡好」**：这个词几乎每天都能成立 —— 模型会每轮报一次，于是体力天天掉，
变成慢性失血。判断"昨晚睡得怎么样"本来就不是每一轮都能回答的事。

**现在**：作息只在**日结**里判，日结发生在你点「+ 下一天」的时候：

- 单独一次请求（和"攒够 10 条自动摘要 / 手动生成日摘要"共用一张表，但**提示词分开**）；
- **那一天有剧情才调模型**，没有剧情就跳过（不白花钱、也不会无中生有地扣）；
- 回复里额外要求最后几行写 `〔作息〕角色名：睡好` 或 `〔作息〕角色名：熬夜`，
  软件只认这一块，并从摘要正文里剥掉；
- **三态**：`睡好` = 体力 **+15** / 理智 **+4**；`熬夜` = 体力 **−10**；
  **普通的一夜什么都不写**（不写 = 不变，这是默认，也是多数情况）。

---

## 三、时段：早 / 午 / 晚，只在变档处露一次

输入台多了「时段」下拉：**默认「早」，换天自动复位**。它会随你的消息存进 `messages.meta`
（**不写进正文**），所以：

- 消息头只在**变档**时显示一枚 chip（一天里一直「早」就只有第一句带）—— 不刷屏；
- 日结会带上「（时段：早 → 晚）」帮助判作息；
- 坏数据（既不是早也不是午/晚）按"没标"处理，不会污染消息。

---

## 四、关系强度也有账本了

关系强度以前是"改了就是改了"。现在每次**自动**改动都写一行 `relation_changes`：
来源（导演代价 / 状态变化…）、类型、原因、节点、消息，以及 `revoked` 标记。

- 导演账本面板底部多一栏「关系变化（最近 5 条）」，每条可**单条撤销**；
- 撤销 = **写一行反向变化 + 把原行标成 revoked**（不是删行，留痕），撤销行本身不能再撤；
- 变化夹在 **0~100**，分支隔离；
- 撤销后顺手刷新关系图谱，不用手动重进。

> 配合的边界：**负向可以自动（有据可查），正向变好仍走人工提案** ——
> "好"比"坏"主观，容易自我感动。这条写进了 README §11.4。

---

## 五、提案冷却：不再"挂一条就永远不弹"

**旧逻辑的坑**：同一个目标只要有一条待确认的提案挂着，就**永久不再提**新的 ——
用户实测"我把它放着没管，结果它再也不弹了"。

新规则三条：

1. **同一节点只提一条**（别在一个地方刷屏）；
2. **跨天允许再提**（pending 不再阻塞新的一天）；
3. **只有落地（applied）才进 3 天冷却**，被拒绝（rejected）不冷却 —— 拒绝是"这次不同意"，不是"以后别再问"。

---

## 六、赦免请求：把她的设定和当前关系一起给她看

用户实测（关系强度 0 + 刚被冒犯）时，她回了一句「我不太会认这个」—— 太软，不像一个真的在生气的人。

于是请求正文里多了一段【你的设定与当前关系】：一句话人设 / 性格标签 / 行为准则 / 当下状态 /
她与用户的关系（强度 + 档位 + 态势）。并且当**强度 ≤ 20 或态势是破裂**时，明令：

> 不要写心软，不要给台阶，不要主动靠近。

取不到数据就写「（未填）」，**不编造** —— 宁可少给信息，也不给她编一个不存在的过去。

---

## 七、新增的边界说明（README §11.4）

这一版把"谁说了算"写成了硬边界，判据三条：**事实 vs 解释** / **短尾 vs 长尾** / **方向盘 vs 后果**。

- 总则：**事实进角色，解释进审批；短尾自动，长尾人工；自动必须可撤销。**
- 自动写入必须同时满足：**可见**（当场提示）、**可撤销**（进账本、能单条撤）、**有上限**（幅度封顶）。
- 三条硬边界：软件**不替你决定剧情走向**；**生死与不可逆损伤只能人工**（自动链路里没有死亡/致残类型）；
  **你手改的数值永远优先**（手改 = 重设基线）。

原文见 [README §11.4](https://github.com/gu-chen-xi/story-weaver/blob/v3.10.0/README.md#114-谁说了算人工确认-vs-角色自决)。

## 八、内部（用户看不到的）

- 新模块：`relation_ledger.rs`（关系账本）、`stat_change.rs`（三维数值）、`timeline/day_close.rs`（日结），都带完整单测；
- 新表：`relation_changes`、`stat_changes` —— `story.db` 16 → **18 张**，总表数 19 → **21 张**（`library.db` 3 + `story.db` 18），
  带 `branch_id` 的 12 → **14 张**；老库启动时自动建表，不需要你动手；
- 提示词：`〔状态变化〕` 段**只在插件开启时**注入，协议行在历史 / 记忆 / 导出 / 回顾里**全链路剥掉**；
- 测试：Rust **435** 项（**415** 常跑 + 20 `#[ignore]`）· 前端 **162** 项 · `tsc` 0 错；
- **打包验证**（2026-10-29 实测，不是"应该没问题"）：
  - 本次构建窗口内 `target/release/build/app-*/output` **无** `cargo:rustc-cfg=dev` → 是打包版，不会去连 `localhost:5173`；
  - `msiexec /a` 解包 MSI → 只有 `app.exe`（24,729,600）+ `app_lib.dll`（1,736,704）；
  - 便携版 exe 拷到**空目录**双击：12 秒后窗口标题「织梦机」、进程健在（FileVersion **3.10.0**）；
- 数据库新增两张表这事，[数据与备份](https://github.com/gu-chen-xi/story-weaver/blob/v3.10.0/docs/user/数据与备份.md) 已同步。
