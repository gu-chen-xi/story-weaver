# v3.12.0 — 模型可以是「你自己机器上那个」了

> 发布 **2026-11-01** · 上一版 [v3.10.0](https://github.com/gu-chen-xi/story-weaver/blob/v3.12.0/docs/user/releases/v3.10.0.md) ／ [v3.11.0](https://github.com/gu-chen-xi/story-weaver/blob/v3.12.0/docs/user/releases/v3.11.0.md)
>
> 这一版的主题是「**把"模型"这件事交还给用户**」：
> 插件页那个一直挂着「规划中」的 Ollama 占位卡，这次变成了真面板 —— 填个地址和模型名，
> 主模型就能换成你本机跑的那个；**关掉插件就回云端**，两条路不会同时开。
>
> 另外把界面上欠的两笔账还了：章节页终于能**拖**天（也能编辑「关联的天」），
> 开发者模式则砍到只剩一件事 —— **只读看"当时到底发给模型了什么"**。
> 顺手修掉三处会把人骗过去的坏数据（插进去的天飘走、没建分支却画出分叉、未归章一片空白）。

## 一、Ollama 本地模型：模型换成你自己机器上那个

**以前**：插件页第一张卡写着「Ollama 本地模型（规划中）」—— 卡片是占位态，点开只有一句"依赖插件系统"。

**现在**：它是真面板了。填地址 → 点「检查连接」→ 填模型名 → 开开关，主模型就走本地。

| 面板上的东西 | 说明 |
|---|---|
| **地址** | 默认 `http://127.0.0.1:11434`；失焦即保存；必须以 `http://` 或 `https://` 开头（少了会直接提示）|
| **「检查连接」** | 读 `GET /api/version`，把版本号显示出来（**只检查服务在不在，不启动、不下载**）|
| **模型名** | 手填，比如 `qwen2.5:7b`（`ollama list` 里看到的那个）—— **不做下拉**，软件不去猜你装了哪些模型 |
| **上下文** | 五档：32k / 64k / 128k / 256k / 1M |
| **伏笔扫描走本地** | 独立开关，见第四节 |

几条边界（写死在代码里，也是这一版的设计取舍）：

- **软件不下载、不启动 Ollama**。你要先把 `ollama serve` 跑起来，再来点开关。它只发 HTTP 请求，从不调用外部程序。
- **上下文档位只影响软件这边的预算**（怎么裁剪历史），**不会下发给 Ollama**。本地真实上下文由 Ollama 自己的
  `num_ctx` / `OLLAMA_CONTEXT_LENGTH` 决定 —— 面板上就写着这句，免得你以为"改了就生效"。
- 适配目标 **Windows 版 Ollama 0.40.11**（本机实测同版本）；实际版本以「检查连接」读出来的为准。

> ⚠ **一句必须说的实话**：Ollama 默认上下文只有 **2048**。长对话会被它自己截断（表现是"聊到后面它忘事"）。
> 建议先设环境变量 **`OLLAMA_CONTEXT_LENGTH=32768`** 再启动 Ollama。
> （软件里的伏笔扫描已经改走原生接口单独指定了，不受这条影响 —— 见第四节。）

## 二、主模型只有一路：连不上就报错，不偷偷回落

这是这一版**最容易被忽略、但最关键**的一条规矩：

| 插件开关 | 主模型走哪 | 出问题怎么办 |
|---|---|---|
| **关着** | 云端（参数页里那个地址 / 模型 / 上下文）| 老样子 |
| **开着** | 本地 Ollama —— 地址换成 `{你填的地址}/v1`、模型换成你填的名字、上下文换成面板档位 | **连不上、或没填模型名 → 直接报错，不回落云端** |

为什么不做"本地失败自动切云端"？因为那样一来**你根本不知道自己在用哪个模型**：
回复变好了你以为是 7B 变强了，其实是偷偷用了云端；回复变差了你也找不到原因。
宁可给你一条明确的错误：「连不上 http://127.0.0.1:11434（Ollama 要先手动启动）」。

还有两个细节：

- **本地不需要 Key**：走本地时不读凭据库，请求里只有一个占位串 `ollama`（Ollama 的兼容层不校验）。
  也就是说**地址填错也不会泄漏你的云端 Key**。
- **拿不到用量**：本地模式会去掉请求里的 `stream_options`（兼容层不保证认，有的版本直接 400），
  所以「生成参数」页对本地请求**不显示「实测 / 估算」**，全局的「📐 估算校准」也不统计本地请求 ——
  **这不是 bug**，是拿不到上游的 `usage`。

## 三、「测试对话」：一句话验证

填完地址和模型名，先别急着写正文 —— 面板上有「**测试对话**」：

- 只发一句 **「请只回复两个字：你好」**；
- 用的是**插件里的地址与模型**，与云端配置**完全隔离**（不读模型配置、不读钥匙串）；
- 回什么、报什么错，就地显示（连不上 / HTTP 状态 / 空回复各有各的说法）。

它比「检查连接」更狠一层：检查连接只证明"服务活着"，测试对话证明"**这个模型名真的能出字**"。

## 四、本地扫描伏笔：让它读原文，而不是只读摘要

**以前**：伏笔只能手标，或者用「扫描候选」——那是**纯字符串规则**，只在日摘要里找
「答应 / 约定 / 没说完 / 没解释」这类字眼。**零成本，但同义改写、隐晦伏笔一律抓不到。**

**现在**：伏笔区多了「**🧠 本地扫描伏笔**」。它把**原文**交给本地模型读，按章分批：

| 项 | 规则 |
|---|---|
| 分批 | **每批 2 章**；每批喂给模型的是「**全部日摘要** + 本批两章的原文」 |
| 为什么带全部摘要 | 这样它能看见"第 1 章埋、第 3 章收"这种跨批的线索，又不用一次塞下整本书 |
| 输出协议 | 严格一行一条：`〔伏笔〕第 N 章：<东西或话题>`；找不到就回「无」+ 一句原因，**不许硬找** |
| 上限 | 每章不限，**单次扫描 20 条封顶**（到顶就停并告诉你） |
| 落到哪 | 进**同一个「提议」列表**（来源记为 `local`），和手标 / 规则提议一样，需要你**接受**才算数 |
| 进度 | 按钮下方有进度条 + 「第 X 轮 ｜ 第 N~M 章 ｜ 共 S 章 ｜ 已得 K 条」|
| 什么时候能点 | 只要插件里勾了「伏笔扫描走本地」就出现 —— **不需要**同时把主模型换成本地（本地扫、云端写是允许的）|

### 7B 级模型的五轮打磨（这部分很枯燥，但决定它能不能用）

第一版跑出来的结果是不能用的：**进了一堆 `*心声*` 和台词原文**，还有一行
`〔伏笔〕第 1 章：30 字以内的一句话` —— 那是它把提示词里的**格式模板**当答案抄回来了。
五轮之后才稳定：

1. **不是不会找，是不知道"什么算伏笔"** —— 加 5 类示例（物件 / 没说完的话 / 约定 / 反常细节 / 没交代的人或地方）后，
   它才开始出行；没示例时它直接回「无。」
2. **太保守** —— 加一条硬规则：材料里出现「没说完 / 没细说 / 约定 / 答应 / 改口」这些字眼，必须至少列一条。
3. **照抄格式模板** —— 解析层把含「30 字 / 一句话 / 第 N 章」的行丢掉。
4. **噪声** —— 提示词要求"用自己的话概括"，解析层丢含 `*` 行和「【样例】」测试数据，
   去重改成按"**去标点后的核**"比较（`把话咽了回去。` 与 `…夜里，把话咽了回去。` 算同一件事）。
5. **台词噪声** —— 它把心声的星号去掉之后照抄成句子（`他说这话之前，连我姓什么都没问过。`）。
   于是提示词改成**只写"东西/话题"**（不写谁做了什么、不出现我/你、不带句号、20 字内、不能光秃秃一个词），
   解析层再拦「我/你」「？」「…」「「」。

**顺手挖出来的一个真凶**：第 2 批永远回空。跟提示词无关 —— 是 **Ollama 默认上下文 2048** 把 2 万字符的原文截断了，
而当时用的 OpenAI 兼容端点 `/v1/chat/completions` **根本不接受 `num_ctx`**。所以扫描链路改走**原生 `/api/chat`**，
在 `options` 里带 `num_ctx`（等于面板档位），同样的输入就正常返回了。

> 每次扫描的**原始请求与回复都会记进库**（`debug_requests`，`node_id` 为空）——
> 用开发者模式「请求快照」能直接看到当次发给模型的原文，排查"规则扫得到、本地扫不到"不用靠猜。

## 五、章编辑能改「关联的天」了

**以前**（3.11 的缺口）：`set_chapter_nodes` 命令写着、注册着，**界面没有入口** —— 章建错只能删了重建。

**现在**：编辑章的弹窗里多一段「**关联的天（N）· 点一下加入/移出**」：

- 只列当前分支、且**没被别的章占用的天**（一天只属一章这条规矩没变）；
- 已经属于本章的排在前面，其余按天序排；
- 保存时 `update_chapter` 与 `set_chapter_nodes` **一起提交**，提示会带上「（N 天）」。

## 六、章 ↔ 天 拖拽：把天拖到别的章

章卡上现在会列出自己关联的「天」，每一个都能**拖**：

- 拖到**别的章卡**上 = 改归属；
- 拖到底部「**未归章**」区 = 移出这一章；
- 落点会高亮（边框和底色变主题色），成功给一句提示。

底部「未归章」区现在是**常驻**的 —— 哪怕它是空的也显示，否则"把天拖出去"没有落点。

> **一个代价要讲清楚**：为了让网页能收到拖拽事件，这一版把窗口的 `dragDropEnabled` 关掉了。
> Windows 上它默认是开的，会由宿主先把 `dragover`/`drop` 拦走（表现就是"禁止光标 + 松手没反应"）。
> 关掉的代价是**窗口不再接收"把文件拖进来"** —— 本项目所有导入都走对话框，没有这个功能，所以不亏。
> （排查过程见 [错误合集 E-UI-20](https://github.com/gu-chen-xi/story-weaver/blob/v3.12.0/docs/dev/错误合集.md)。）

## 七、开发者模式：只剩「请求快照」（仅开发构建）

**以前**：「开发者工具」页有五块 —— 概览 / 数据注入 / 数据体检 / 造样例 / 回顾试算。

**现在**：全删，只留一件事 —— **只读查看"当时发给模型的原文"**。

- 左栏是请求列表（`#id · 时间 · 状态` + 本轮输入前 40 字 + `tok ｜ 系统N 历史N 尾N`），可以**按天筛选**；
- 右栏七个页签：**系统提示词 / 尾部协议 / 关键记忆 / 回顾检索 / 历史 / 本轮输入 / AI 回复**；
- 「历史」不再是一行挤着的 JSON，而是每条一块（角色 chip + 真换行 + 字符数）；
- 所有 `【…】` 段**橙色高亮**，一眼能找到分段；
- 每段都能「复制」，字符数直接标在右上角。

> 为什么单独做这一页：剧情区和「prompt 预算」都会按展示需要裁剪、分段，
> 只有 `debug_requests` 里那份是**原样**的。要逐字对照，只能看它。

> ⚠ **这一页在正式版里没有**（导航项与后端命令都只在开发构建存在）。
> 用户版不关心"当时传了什么"，这条是刻意的 —— 别拿打包版去找它。

## 八、生成参数页：去掉重复的三件套

「Token 预算」页签里原来有一套「📋 复制整段 / ⬇ 导出 .txt / 对比 diff」：

- 「复制整段」与「Prompt 预览」里的"复制完整 prompt"**重复**；
- 「对比」是对两条历史请求做**行级 diff**，使用率很低，而且现在有「请求快照」了，功能重叠。

三个一起删掉（连带删掉行级 diff 视图与相关状态）。同时把抬头那行重复的「上下文窗口 × 系数 − 输出预留」也删了
（下面图例已经有了），并把「记录节点 … 实际带 N 条消息」与「📐 估算校准 …」合并成同一行 ——
先看"这次带了什么"，再看"估算准不准"。

## 九、修好的（都是实测踩到的）

| 症状 | 根因 | 现在 |
|---|---|---|
| 主线里插一天，树状图里它**排到后面去了**、药丸条里干脆没有这一天 | 父节点查询把占位符写死成 `?2`，而主线的分支条件是 `branch_id IS NULL`、**不占位** → 条件变成 `sort_order < NULL` → 父级写空 | 占位符跟着分支条件走；打开故事时还会把"父级为空"的节点**挂回前一天**（幂等） |
| **没建过分支，树状图却画出分叉**（第 5 天和第 6 天都挂在第 4 天）| 「删第 5 天 → 再插第 5 天」时，第 6 天没改挂到新节点上 | 插入中间时把**紧邻的下一个节点**改挂到新节点；打开故事时若无分支则按天序**把主线捋成一条链**；前端渲染再兜一层 |
| 树状图出现**两张「主线」卡**、药丸条缺一天 | 父级为空的孤儿节点被当成新的根 | 渲染层把孤儿挂回同分支前一个节点，只有真·第一天才是根 |
| 新故事里「未归章的天」**一片空白**，底部写「全部已归章」，拖都拖不进去 | `unassigned_days` 要求"这天有消息"，新建的空天（0 字）被排除了 | 去掉这个条件：只要节点在、未归章就列出来（0 字也正常）|
| 「你还记得我答应你的事情嘛」这类**回忆 / 追问被记成新承诺** | 承诺判定只排除了否定/威胁/转述/条件句 | 加第五道排除：命中词前 8 字含 `记得 / 忘了 / 忘没忘 / 说过 / 提过` 就不记 |
| 本地扫描进来一堆**心声、台词、格式模板行**、同一件事每次换个说法 | 小模型既不知道"什么算伏笔"，也会照抄原文 | 提示词 + 解析层双边堵（见第四节），去重按"去标点后的核" |
| 导演账本**永远空**、闸门永远不锁，可单元测试全绿 | 调用账本时 `characterName` 实参被注释吃掉 → 后端必填参数缺失 → 前端静默清空 | 修实参 + 补**源码扫描守卫**（再被注释掉测试就红）|
