# v3.13.0 — 本地模型终于按你选的上下文跑了，数值也开始管台词了

> 发布 **2026-11-02** · 上一版 [v3.12.0](https://github.com/gu-chen-xi/story-weaver/blob/v3.13.0/docs/user/releases/v3.12.0.md)（再往前 [v3.11.0](https://github.com/gu-chen-xi/story-weaver/blob/v3.13.0/docs/user/releases/v3.11.0.md)）
>
> 这一版**没有新页面、没有新表**。27 个提交全在做同一件事：把"看起来能用"变成"真的能用"。
>
> 最典型的是本地模型 —— 上一版接进来了，面板上也能选 32k / 64k / 128k，
> 但那条链路走的是 OpenAI 兼容端点，**它根本不收 `num_ctx`**：你选 32k，它按模型默认的 2048 跑，
> 于是"第 2 批原文读不进去、回复全是「无」"。这一版改成走 Ollama 原生 `/api/chat`，档位才真的发过去。
> 顺带的收获是：**本地请求第一次有真实 token 用量了**（以前参数页对本地永远显示 0）。
>
> 另一条主线是数值。体力/理智/存在感以前只有"方向"没有阈值 —— 模型知道"越低越累"，
> 但不知道台词该变多短。这一版给了**硬上限**（理智 0-19 就是每句 ≤15 字、这一整段 ≤3 句），
> 并且定死一条：**数值只决定"表现得出多少"，不决定"愿不愿意"**。

## 一、本地模型：这次真的按你选的档位跑

**以前**：插件开着 → 主对话换成 `{地址}/v1/chat/completions`。这条路是"假装成 OpenAI"的兼容层，
而兼容层**不认 `num_ctx`** —— 传了也被丢掉。结果是：面板上的五档只是软件内部的预算数字，
模型自己还按 2048 上下文跑。原文一长，它就只看到开头一小截，回复要么空、要么答非所问。

**现在**：本地那条改走**原生** `{地址}/api/chat`。

| 项 | 以前（3.12） | 现在（3.13） |
|---|---|---|
| 地址 | `{地址}/v1/chat/completions` | `{地址}/api/chat` |
| 行格式 | SSE（`data: {...}`） | **NDJSON**（整行就是一个 JSON） |
| 上下文档位 | 只影响软件预算，**不下发** | `options.num_ctx` = 你选的那一档，**真生效** |
| 输出长度 | `max_tokens`（兼容层认） | `options.num_predict`（原生才认） |
| 用量 | 没有（`stream_options` 被去掉了） | `done` 块的 `prompt_eval_count` / `eval_count`，**回填参数页** |
| 鉴权 | 带一个占位的假 Key | **不带 Authorization**（本地不校验，也省得假 Key 进调试记录） |

云端那条一个字没动（还是 SSE + `/chat/completions` + `stream_options`）。
两套协议用 `StreamProtocol` 枚举显式区分 —— 之所以要这么写，是因为"URL 换成本地了、行还按 SSE 读"
是个很容易犯的错，而它的表现是"什么都没发生"，很难查。

**怎么验证它真的生效**：真实回复变长、长原文不再回「无」；参数页的 Token 预算开始显示「实测 / 估算」。

## 二、敏感词：70 条、不漏字、也不误伤

这套过滤是**内置常开、不可关**的（只挡辱骂和脏话，不管题材）。这一版修了三类问题：

1. **词表 20 → 70 条**，仍按"辱骂 / 脏话"收口 —— 死亡、暴力、政治、宗教这些**不属于**这张表。
2. **变体能认了**：匹配前先归一化（大小写、全角、中间插空格 / 点 / 符号、零宽字符），
   所以 `傻b`、`傻 逼`、`ＣＮＭ` 都拦得住。按首字建桶，1.6 万字的消息也只扫一遍（约 1.1ms）。
3. **误伤修掉了**（这几处都是实测撞到的）：

| 以前会被误拦 | 现在 |
|---|---|
| 「她回到**妈妈的**房间」 | 放行（"妈的"前面是"妈"不算） |
| 「那些**狗日子**总算过去了」 | 放行 |
| 「把**体操你们**练完」 | 放行 |
| 「**牛杂碎**汤」「**杂种**优势」 | 放行 |

另外三处行为变化：

- **流式不漏字**：以前每个 chunk 单独替换，中文按字切的时候「傻」和「逼」分在两片里，谁都匹配不上。
  现在保留最后 **8 个字**不下发，等下一片到了再一起判断；收尾时把尾巴吐出来。
- **生成完不会又变回脏字**：流式期间的 `***` 原来会被"从库里重读原文"盖回去（表现为"生成时好好的，一结束就露字"）。
  现在气泡正文只走一个显示出口，显示前统一过一遍掩码；**库里存的仍然是原文**。
- **改历史消息也拦**：以前先发一句正常的话、再点「✏️ 编辑」改成脏话就能绕过去。现在编辑"我"的消息会走同一套检查
  （AI 那侧不查 —— 显示层已经掩码，不该妨碍你修 AI 回复里的错别字）。

> **导出保持不过滤**（这是明确的决定）：导出的文本是给创作用的，掩码只该活在界面里。

## 三、回顾：说第 4 天，就只给第 4 天

**以前**：「第 4 天」在检索里只是个**加分项**，于是第 1、2、3 天的分数同样过阈值，一起被塞进提示词。

**现在**：

- **点名某一天 = 只恢复那一天**，不再掺打分的结果。
- **范围说法交给按钮**：「第 3 到第 5 天」这类说法，自动检索**故意不接管**（宁可这次不回顾，也不要只给你第一天）。
  请点输入框的「🔍 回顾」—— 它现在是**多选**的，连点几天就是一段范围，输入台上会显示「已选 N 天」。
- **未来天不给**（还没发生）；**当天 / 前一天 / 前两天也不给**（本来就在近三天的原文区里）。
  **手动选也挡**，那几天在列表里是灰的，点一下只会告诉你"不需要回顾"。
- **「🔍 回顾试算」开始说人话**：先明说"这一轮会不会真的注入"，不会就黄条提示去手动选天。
  以前它只列打分表，很容易被理解成"这轮会带进去"。

## 四、阶段摘要：不再把「第 1~10 天」压一遍又一遍

**症状**：摘要管理里同一段天数出现好几条，每点一次"压一段"，最老的几天就被再压一遍。

**根因**：自动压缩写死了"忽略已有覆盖"，永远从最老的几天起，攒够 x 天就压一段 —— 于是第 1 天永远在第一段里。

现在自动压缩**尊重已有覆盖**，只压"还没被任何阶段摘要盖住"的天；「🧾 摘要管理」拆成两个格子：

| 已压缩 | 未压缩 |
|---|---|
| 覆盖了多少天、共几段 | 还剩多少天、「还能压 N 段」（不足一批时写"先攒着"）、**下一段是哪几天** |

删一段、清一次重叠之后，统计会立刻跟着刷新（以前删完界面还留着旧数字）。

## 五、关键记忆与关系：她能改口了，告白也记对方向了

五处修正，都是实测撞出来的：

1. **被拒的表白可以改判**。以前只有"这一轮又表白了一次"才会改判 —— 可现实是被拒之后过几天，
   她在**普通对话**里松口了，那一轮根本没有表白事件，卡就永远停在"被拒绝"，提示词还在一遍遍说"不要写成她已经答应"，
   演员被自己锁死。现在：只要这一轮**不是**表白轮，提示词就给一条明确的出口 ——
   她真的改主意了，就写 `〔态度:接受〕`，软件据此把卡改成「已接受」（并记下 `accepted_day`，提示词里能写"第 9 天她已经接受了"），
   同时补一条关系跃迁提案（仍需你确认）。
2. **协议写的"接受"也算数**。以前判定只认接受**词表**：第 13 天那轮用户说「我喜欢你」、她只回「……好。」+ `〔态度:接受〕`，
   词表一个都没命中，于是记忆卡改判了、关系跃迁提案却没生成。现在两者合并判断。
3. **关系归属三层**：① 你在沉浸对话里选的「我扮演 / AI 扮演」（生成时顺手存一份）＞ ② 双方名字都出现 ＞ ③ 整个故事只有一条关系。
   第 14 天就是这么丢掉一条提案的 —— 他喊「夏婉琴，…我喜欢你」，她回「愿意」，**谁都没提自己的名字**。
4. **同一轮重复分析不再累加**：给每一轮记指纹，同一轮点了两次「立即分析」不会把"表白 4 次"变成"表白 10 次"。
5. **表白卡只记用户的表白**：AI 反过来告白时，以前会被记成"用户第 1 次表白"（方向完全反了）。
   现在两个方向分开记 —— 她主动说的那句另开一张「**她的告白**」卡。这张卡由**日摘要顺手判**（每天都会跑，
   不额外多一次请求），输出一行 `〔告白〕角色名：原话`，这行会从摘要正文里剥掉，不进【前情提要】。

> 顺带把日摘要的「谁在说话」写清楚了：`[用户]` 开头是你说的话；`[AI]` 那一块可能同时有多个角色，
> 每行 `[角色名]` 后面紧跟的才是那个角色说的 —— **没重新出现就还是前一个人在演**。判断"谁对谁表白"一律按这个算。

## 六、数值影响台词：低理智的人，说不出长句

**以前**：体力/理智/存在感只给一个档位名（"偏低""很低"），模型知道方向但不知道**该短到什么程度**，
于是 15 点理智照样能说一整段排比句。

**现在**：三维统一五档（0-19 / 20-39 / 40-59 / 60-79 / 80-100，**不分角色**），并给出**台词硬上限**：

| 理智 | 每句最多 | 这一段最多 |
|---|---|---|
| 0-19（很低） | **15 字** | **3 句** |
| 20-39（偏低） | 25 字 | 5 句 |
| 40-59（正常） | 40 字 | 8 句 |
| 60-79（偏高） | 50 字 | 10 句 |
| 80-100（很高） | 60 字 | 12 句 |

**体力只收紧、不放松**：体力 0-19 再压到 ≤20 字 / ≤3 句，20-39 压到 ≤30 字 / ≤6 句；两者取**更严**的一组。
存在感不压字数，它管的是"话有没有人接"（很低：说了要重复、被抢话；很高：出场先被看见）。

**冲突怎么裁决**（写死在提示词里，不是暗示）：

```
关系态势（破裂 → 拒绝/回避）＞ 关系强度（愿不愿意）
＞ 理智（语言量）＞ 体力（气口）＞ 存在感（是否被打断）
```

也就是说：**数值只决定"表现得出多少"，不决定"愿不愿意"**。她体力见底也不会因此答应你，她只是说不出长句子。

**不占多余 token**：规则进 system（静态，吃前缀缓存），只有每轮会变的"当前数值 + 本段上限"进尾部；
三维全在正常档时**一行都不加**。另外规定死了**不许把数字写进正文**（不出现"体力 -15"这种血条式表达）。

### 6.1 存在感：正负各自记账

| 场景 | 以前 | 现在 |
|---|---|---|
| 同一天先被羞辱 −5、后被认可 +5 | 净额被抵成 0，两笔都不入账 | 两笔各自入账（扣的照扣、加的照加）|
| 同一天两次正向（被看见 +3、被认可 +5）| 净额 8 被夹到 5 | 正向累计最多 +5（+3 之后只再加 +2）|
| 同日同类型重复 | 去重挡掉 | 一致（不变）|

### 6.2 十二个类型补了口径

`〔状态变化〕类型：理由` 里的类型，现在每个后面跟一句 8-12 字的口径，归类不再只靠名字猜：

```
受伤（被打·被撞·见血） / 生病（发烧·咳嗽·病倒） / 力竭（撑不住·脱力·昏倒） /
被欺骗（对方对她说了谎） / 撞见无法解释的事（看到说不通的东西） / 崩溃（情绪失控·说不出话） /
被安抚（被哄住·被安慰） / 想通（自己想明白了） / 被无视（说话没人接·被晾着） /
被当众羞辱（当着人下不来台） / 被看见（被人注意到） / 被认可（被人肯定·被称赞）
```

只在「🌱 三维数值自动变化」插件开启时才注入，**不占默认提示词**；口径里**没有任何数字**（有测试盯着这件事，
类型清单里冒出阿拉伯数字就会红）。

### 6.3 普通的一夜 +10 体力

以前"没写作息 = 什么都不变"，而受伤/生病/力竭各 −15 是可以叠的 —— 结果体力长期单向贴地，五档永远显示"很低"。
现在日结时没被「睡好 / 熬夜」点名的角色，一律按**普通的一夜**恢复 **+10 体力**（模型不用写这一行，代码默认给）。

## 七、修好的

| 症状 | 根因 | 现在 |
|---|---|---|
| 界面上的「构建时间」永远停在上次改 `build.rs` 的那天 | `build.rs` 里写了 `cargo:rerun-if-changed=build.rs` —— 这条指令的意思是"只在 build.rs 变化时才重跑"，于是时间戳被钉死 | 删掉那颗"少编译"的心，改成包里任何文件变了都刷新时间戳 |
