# v3.14.0 — 体力低了搬不动；伏笔扫描改成一章一读

> 发布 **2026-11-04** · 上一版 [v3.13.0](https://github.com/gu-chen-xi/story-weaver/blob/v3.14.0/docs/user/releases/v3.13.0.md)（再往前 [v3.12.0](https://github.com/gu-chen-xi/story-weaver/blob/v3.14.0/docs/user/releases/v3.12.0.md)）
>
> **24 个功能提交 + 1 个修复 + 2 个文档同步**，没有新页面、没有新表、没有新命令。
>
> 两条主线：
>
> ① 上一版让数值管**台词**（低理智说不出长句）。这一版让它管**做不做得到**：
> 低体力时力气活要写失败或走形 —— 搬不动、扶不住、走两步就得停，硬撑会受伤。
> 定性仍是**表现层**：不改数值结算，也不加奖惩循环。
>
> ② 本地伏笔扫描上一版是"一批两章 + 整本日摘要"。喂全史的结果是模型顺着故事往下读，
> **「无」成了最省力的答案**。这一版改成**一批一章**，前情摘要只带"这一章的天 + 往前三天"；
> 顺便把本地和云端分成两条协议：本地只列候选，判定那种活留给会判的模型。

## 一、体力：从"说不动话"到"做不成事"

**以前**：低体力只压台词量（句子变短、本段句数变少）。人还是能把一袋米扛上三楼 —— 只是话说得短。

**现在**，体力**还决定动作能不能完成**：

| 体力 | 写出来的样子 |
|---|---|
| 0-19（很低） | 力气活**做不干净**：搬不动、扶不住、走两步就得停；硬要撑会受伤，或被别人扶住 |
| 20-39（偏低） | 重活要么**借力**（找个支点、拖、滚），要么**开口求人** |
| 40 以上 | 正常写，不许**无端写虚弱** |

另外两条硬规矩写进了提示词（不是暗示）：

- **正常以上不许无端写虚弱** —— 不能因为"氛围需要"就让她扶墙喘气。
- **不许用一句「她突然有了力气」把前面的疲惫抹掉** —— 前面写了脱力，后面就得付代价（歇一会儿、被人扶、动作走形）。

**它不改数值结算**：这一版没有"体力不够就扣血/扣成功判定"这类机制，也没有新增奖惩。
体力低只表现为**她做不成、做不利索、要求人**；数值怎么变仍由 `〔状态变化〕` 协议与日结那套管。

代码位置：`characters.rs::STAMINA_PLAY`（低档的两句表现描述）+ `performance_rules()`（规则段新增两条），
只随【数值与当下】/规则段进入提示词，低体力时才收紧。

## 二、伏笔扫描 v2：一章一读，只带往前三天

### 2.1 一批两章 → 一批一章

**以前**：一次喂两章，模型要自己判断"这条伏笔属于第几章"。实测它会把「第 11 天」写成「第 11 章」。

**现在**：**一批只喂一章，轮数 = 章数**。章号由**后端绑定**（`batch[0].id`），
模型连章号都不用写，写错的章号也不会污染数据 —— 这类错误从根上没了。

代价是请求次数变多（20 章 = 20 轮），换来的是每轮输入更短、归属不再靠模型猜。

### 2.2 前情摘要：整本历史 → 这一章的天 + 往前 3 天

**以前**：每批都带**全部日摘要**。看起来"信息更全"，实际是让模型顺着整本故事往下读 ——
阅读惯性吃掉注意力，「无」变成最省力的全局答案（这是你 2026-11-02 的判断）。

**现在**：只给**本批覆盖的那几天 + 往前 3 天**（`foreshadow::context_window`，窗口含端点）。
第一页没有前情，就写「（这一段前面没有摘要，直接看原文）」；章与天对不上时退回看原文。

| 项 | 以前（3.13） | 现在（3.14） |
|---|---|---|
| 每批章数 | 2 章 | **1 章** |
| 轮数 | ⌈章数 / 2⌉ | **章数** |
| 前情摘要 | 整本全量 | **本批的天 + 往前 3 天** |
| 章号 | 提示词里写「第 N 章」 | **不写，后端绑定** |

### 2.3 双规制：本地只列，云端才判

**试过什么**：给本地模型也上两步式（先列细节 → 逐条判「当场消化了吗」→ 只把「否」写成伏笔）。

**实测结果**：qwen3.5:9b / qwen2.5:7b，两个故事、四种措辞，**「是」的出现率 0/4** ——
一章之内绝大多数细节本来就不会再出现，判出「是」需要理解"同一场戏内的了结"，这个量级做不到。
但它**找东西是准的**。所以：

| 谁 | 怎么扫 | 输出 |
|---|---|---|
| 本地模型（现在就有） | **单步**：直接找「被提起却没交代清楚」的东西 | 6~10 条 `〔伏笔〕<东西或话题>`，不做是/否判定 |
| 云端模型（那一档还没接） | **两步**：先一条一行「细节 → 是/否」，再把「否」写成伏笔 | 提示词与兜底解析已就位（`no_lines` / `checklist_balance`） |

两步式的兜底也留着：模型常「标了 N 条否、只写 1 条伏笔」，让它补它干脆不回 ——
那就直接把第一步里「→ 否」的原文拿来用，报告里记「模型只写 X 条，另 Y 条取自第一步原文」。

### 2.4 输出干净了

- **剥掉「用户 / AI」**：模型会写「用户提前准备好的申请材料」这种视角词。提示词里已经写了
  「不许出现「用户」「AI」」，7B/9B 会当没看见 → 代码里再机械剥一遍（`scrub_actor_words`），
  顺手收拾删除后留下的「的的」「的门闩」。
- **容忍漏写「伏笔」二字的行**：9b 有时只写「〔未说明来源的奖学金项目信息〕」。现在带方括号的行
  只要不是别的协议行（状态变化 / 作息 / 告白 / 导演 / 态度 / 承诺），就当伏笔收下。
- **排障可以看真实提示词**：`cargo test --lib print_scan_prompt -- --ignored --nocapture`
  会把这一版的系统提示词原样写到 `.tmp/scan_system.txt`，方便拿它去手工 curl 对比不同模型。

## 三、生成链路：失败会重试，半截不会丢

### 3.1 429 / 5xx 自动重试

**以前**：服务端回 429（限流）或 5xx（网关抽风），这一条回复就废了 —— 只有超时和取消，没有重试。

**现在**：429 / 5xx / 网络错误 / 超时**自动重试**，最多 **3 次**，退避 **1s / 3s / 9s**。

```
第 1 次失败 → 等 1 秒 → 第 2 次
第 2 次失败 → 等 3 秒 → 第 3 次
第 3 次失败 → 等 9 秒 → 第 4 次（最后）
仍失败 → 报错，保留已生成的部分
```

**只在还没吐出正文时重试**：已经开始流式了就绝不重试 —— 重试会把同一段正文放两遍。
那之后的失败走"保留 + 标记"那条路（3.2）。

### 3.2 失败了也保留，末尾红字写原因

**以前**：末尾追加「（⚠ 本段生成未完成：…。以上为已生成的部分）」，一整段混在正文里。

**现在**：正文原样保留，末尾单独一行 `〔失败原因〕HTTP 429: …`；界面把这一段渲染成**红色小字**，
正文里不出现。**导出的文件会剥掉这一行** —— 那是给软件自己看的信息，不该出现在你导出的稿子里。

### 3.3 思考型模型的空正文，会说清原因

**症状**：Qwen3 / Qwen3.5 系在本地跑，界面只报"AI 返回空内容"，或者「测试对话」永远弹"模型返回为空"。

**根因**：这类模型不关思考时，token 全进 `message.thinking`，`message.content` 一直是空串 ——
解析器只读 content，于是"什么都没收到"。

**现在**：
- 主生成链路与「测试对话」都显式带 `think: false`（对不支持思考的模型是空操作）；
- 空回复时不再只说"没有输出"，而是给出诊断（`ollama::describe_empty_reply`）：
  `done_reason=length` + 输出上限被思考吃光 → 提示"多半是没有对话模板，或属于必须关思考的思考型模型"，
  并建议换官方带模板的模型（qwen2.5:7b / qwen3:8b）或提高输出上限。
- 「测试对话」改走**原生** `/api/chat`（兼容端点收不到 `think` 开关）：`num_ctx=4096`、
  `num_predict=256`、超时 60s → **180s**（思考型 + 冷加载首轮实测 20s 起）。

## 四、时间线：开头那段也算空档了

两处修，都是"删掉第一天之后"暴露出来的：

1. **在第 1 天之前插入事件，新天接不上原来的第一天**。以前插入到最前面（`parent_id` 为空）时
   代码什么都不做 → 新节点成了**第二个根**；药丸条只认"当前节点往上"那条链，于是第 1 天插进去了
   却在药丸里看不见（树状图能看见，因为它画全部节点）。现在会把**紧随其后的那个根**收到新节点下面。
2. **空档计算漏掉"开头那段"**。删掉第 1 天后天数从第 2 天开始，以前只算相邻两天之间，
   于是**第 1 天永远补不回来**（点「插入事件」直接说"时间是连续的"）。现在补一段
   `{ from: 0, to: 第一个天 }`；空档不止一段时，弹窗里多一个「插到哪段空白期」下拉。

> 末尾**不算**空档 —— 那是「+ 下一天」的事，不归插入。

## 六、安全：生产 CSP 不再允许内联脚本

生产构建的 CSP 从 `script-src 'self' 'unsafe-inline'` 收紧成 **`script-src 'self'`**；
`style-src` 的 `'unsafe-inline'` 保留（React 的内联样式要用它）。

**开发模式单独留了一份 `devCsp`**：Vite 的 HMR 需要内联脚本与 `ws://localhost:5173`，
把这两样塞进生产 CSP 等于没收紧 —— 所以只给 dev 开。

> 这条对应 2026-10-30 安全审计的 F-04（当时判"纵深、前置条件不成立"）。现在做了，先验的是
> `scripts\selfcheck\selfcheck.cmd`：15 项全过（窗口能起、没有去连 5173 → 用的是内嵌前端）。
> 前端是否完整渲染这件事，自检看不见，得肉眼过一眼。

## 七、明确不做：章节版本历史 + diff

「改章之前先存一版、能对比新旧」这件事**正式决定不做**，界面里也没留按钮。

原因不是懒：做它得先有一张 `chapter_versions` 表、每次改章都写一份快照、还要一套 diff 渲染 ——
而这套东西在"设定版本 + 回滚"那儿已经有一份更完整的（`setting_snapshots`）。
章是**聚合视图**，正文一律回剧情区改，改章本身只是圈天、改标题、改目标 —— 这些改动丢了重做一遍
比维护一张版本表便宜。已从 ROADMAP 欠账表移进「明确不做」。
