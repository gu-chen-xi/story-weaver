## 一、对话模式：她只知道自己该知道的事

### 变的是什么

| 段 | 旁白（不变） | 对话（角色视角） |
|---|---|---|
| 角色卡 | 全部 | **只有 AI 扮演的那一张** |
| 【你对面的他】 | 不出现 | **出现**：名字 / 年龄 / 性别 / 一句话身份 |
| 关系图谱 | 全部方向 | **只留 `from = 她` 的行** |
| 关系强度（尾部） | 全部方向 | 只留 `from = 她` |
| 角色属性（尾部） | 焦点优先 / 最多 8 人 | 只她自己 |
| 示例对话 | 三级回落 | 只认她，没有就不给 |
| 关键记忆 | 全量 | 含她的 + 无归属的 |
| 历史 | 近 3 天全部 | 近 3 天里「她这一对 + 旁白 + 无标记老消息」 |

**规则、数据字典、台词口径、时间基准、前史、世界观、情绪表演、以及所有对账协议段（导演代价 / 表态 /
承诺 / 状态变化 / 章目标）两种模式完全一样** —— 这一版没有动任何"怎么写"的规则，只动了"她能看见什么"。

### 为什么不是省 token

省字是顺带的（实测一个真实故事：system 从 7,862 字降到 7,733 字，尾部从 2,140 字降到 1,203 字）。
真正的目标是**角色隔离**：她不该知道别人的体力、不该知道别人对她的真实态度、不该知道别处的对话。

### 怎么关掉

故事级配置 `prompt.roleplay_scope`：默认 `role`；写 `global`（或 `false` / `0` / `off`）就退回全量，
行为与 3.15.0 逐字节一致。旁白模式不受这个键影响。

## 二、配对视角与"换扮演者"的提示

- **键是 `ai_role × my_role`**，顺序无关；`a×b` 与 `b×a` 是同一段关系。
- 历史过滤顺序：旁白消息 → 一律可见；无标记老消息 → 可见（兜底）；有标记 → 配对相同或互换才可见；
  当前 `my_role` 为空（「自由」）→ 退回按角色判。
- **换任一边扮演者都会弹提示**：「AI 扮演已切换 → 现在是「王老师」×「顾宸熙」的视角。这段关系里的旧对话不会消失，
  只是不在这个视角里（旁白一直看得到）。」配对没变不弹。

## 三、关键记忆：归属从"一个人"改成"参与者"

以前一张卡只能挂**一个**角色（写卡时取 `play.ai_role`），后果很具体：

> 「顾宸熙 向 夏婉琴 表白」这张卡挂在夏婉琴名下 → 你哪天改成让 AI 演顾宸熙，**这张卡就从他视角里消失了**，
> 他会重新表白一次。

这一版改成多参与者：

```
characters: 夏婉琴,顾宸熙      ← 老卡的单值 character: 照样读，零迁移
```

- 写卡时记**这一轮的两个扮演者**（演进 = `play.ai_role` + `play.my_role`；日结的告白 = 告白者 + 对面那个人）；
- 读卡时「含自己的」+「无归属的（全局兜底）」可见 → 「a 向 b 表白」两边都记得；
  「a 和 c 的事」b 看不到；
- MVP **不区分"参与者"和"知情者"**：只记直接参与 —— 少给只是缺信息，多给是知道不该知道的。

> 顺手修了一个 bug：**表白卡的 front matter 以前绕过了归属写入**（单独一个构造函数），
> 所以表白卡永远是"全局卡"、在配对视角里根本看不到。现在补上了；已写坏的老卡不追溯。

## 四、双池对比（生成参数页 / 开发者工具）

「生成参数 → 🔀 双池对比」+「开发者工具 → 右侧页签 → 🔀 双池对比」，同一套：

1. **说明卡**：比什么、不比什么、只读；
2. **通用段**（默认收起）：两边逐字节相同的规则只显示一次；
3. **有差异的段**：左全局 / 右角色并排（她自己的卡 / 关系图谱 / 你对面的他）；
4. **尾部**：关系强度 / 角色属性 / 示例对话（这三块也依赖视角）；
5. **关键记忆（按关系组）**：只显示当前这一对的卡；没有就写「有才显示」，底下列出"其它关系组：X（N 张）"；
   可展开每张卡的正文（标注**不进提示词**）；
6. **漂移护栏**：拿最近一次真实请求的 `tail_block` 字数当对照，两版都对不上就红字警告。

它读的是真实装配函数（`build_system_prompt`），**不调模型、不写库**。

## 五、安全与工程（这一版顺带收的）

- **插件命令按能力域授权**：每个插件只能调自己声明过的域（`ollama` / `portrait-gen`），13 条命令逐个归域；
- **命令面审计**：每条注册的命令都必须有前端消费者，否则测试红（因此删掉了没人调用的 `portrait_update`）；
- **内置 SQLite 的 CVE（RUSTSEC-2026-0459）**：升级不动（sqlx 0.9 固定 `libsqlite3-sys 0.30`），
  改为**运行期防线** `db_guard`：打开库前比对主库与 `-wal` 的页大小，不一致直接拒绝并说明处理办法；
- **CI 代码门禁**：新增 `.github/workflows/test.yml` —— 前端 job（tsc + 224 项 + 文档链接 + 构建）与
  Windows Rust job（618 项）；`security.yml` 补上 `bans` 检查与 push 触发；
- **文档**：新增「提示词拼接说明」24 份（8 个场景 × 按职责拆）+ 引用校验脚本
  （扫 113 条「文件::符号」，对不上就红），并做了一轮全仓去重与归档。
