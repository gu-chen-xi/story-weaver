# v3.7.0 — 该拒绝的时候真的拒绝了，立绘也能挑表情了

> 发布 **2026-10-25** · 上一版 [v3.6.0](v3.6.0.md)
>
> 这一版的主题是「别让界面说假话」：导演指令从"建议"变成**闸门**，
> 所有提示各归其位；立绘从"一角色一张卡"变成**一个角色 × N 个表情 × N 个组**。
> 顺手删掉了一批"看起来能用、其实没人用"的控件。

---

## 一、导演指令：彻底决裂了，就写不了

**之前的问题**：导演指令只是提示词里的一段要求（"必须执行 + 写出转变过程"），
模型心情好就照做、心情不好就软处理。更糟的是：**关系强度已经是 0（彻底决裂）时，
你照样能写"强制让她接受告白"** —— 软件完全不拦，全靠模型自己权衡。

现在分成两层，各管各的：

**第一层：软件闸门（新增）**

AI 扮演的角色 → 你扮演的角色，关系强度 = **0** 时：

- `🎬 导演指令` 变成 `🔒 导演指令`，点了会告诉你为什么不给写；
- 已经排队的指令也**不随这次发送**（不然闸门形同虚设）。

判定是前端纯函数 `src/lib/directorGate.ts`（11 条测试盯着）：

| 情况 | 结果 |
|---|---|
| AI→我 强度 0 | 🔒 拦住 |
| AI→我 强度 ≥ 1 | 放行 |
| 双向关系，反向那条是 0 | 拦住（只看"她还能不能对你低头"） |
| 单向关系，反向不存在 | 放行 |
| **压根没有关系记录** | 放行（数据稀疏不该让功能不可用） |
| 旁白 / 自由模式 / 同一角色 / 查无此人 | 放行 |

> 为什么放前端不放提示词：**"能不能写"是软件层的判断，"怎么写"才该交给模型。**
> 把两件事混在提示词里，就永远只能"希望"模型听话。

**第二层：提示词口径改了**

原来写「必须执行 + 须写出转变过程」，模型读成"可以商量"。现在写死四句：

> **必须达成** · **必须付代价** · **不得白给** · 强度 0 时**兜底拒绝**

其中"必须付代价"是说：强度低的时候，导演指令**不是不能达成**，而是必须经由
条件 / 交换 / 时限 / 外部压力之一换过来 —— 并且不许「嘴上拒绝、身体先软」那种半推半就。

## 二、消息分级：什么话该出现在哪

**之前的问题**：所有提示走同一条通道，于是"插件配置保存失败"会出现在**剧情对话区**里 ——
你在写戏，突然冒出一句程序的抱怨。

现在按"离开这个语境还有没有意义"分三级：

| 级 | 在哪 | 什么话 | 判断标准 |
|---|---|---|---|
| **T1** | 右下角浮层（3.2 秒，错误 6 秒，点一下关） | 保存 / 删除 / 导入 / 导出 / 清理 / 失败 | 换个页面也该看到的 |
| **T2** | 控件旁边的小字 | 插件「检查配置」结果、开发者工具试运行、Key 清除结果 | 离开那个控件就没意义的 |
| **T3** | 剧情区上方那条（**6 秒后自动淡出**） | 切分支 / 切天数 / 删节点 / 生成中断 / 导演指令被锁 | 离开剧情上下文就没意义的 |

T1 的位置刻意跟着右侧导演监视器的宽度走（`right = 301 + 10`）—— 浮在内容上，
但不会盖住监视器。

## 三、确认框自己画了

**之前的问题**：`window.confirm` 弹的是 `tauri.localhost` 的**浅色系统框** ——
贴窗口顶部、标题是网页标题、颜色跟系统走，在一套深色三栏界面里像贴了张便利贴。

现在换成自绘的 `src/confirm.tsx`：

- 460px 居中，深色，和界面同一套配色；
- `Esc` 关、点遮罩关（都是"取消"）；
- 焦点默认落在**「取消」**上 —— 删东西的时候回车不该是"确认删"；
- `Enter` 不做全局确认。

另加了一条静态守卫 `tests/noNativeConfirm.test.cjs`：`src/` 下再出现
`window.confirm(` / `window.alert(`，或者 `confirm(` 少了 `await`（= 漏改回原生写法），
`npm test` 直接红。这种替换最怕的就是"下次谁图省事又写一句" —— 编译不报错、跑起来也能用，
只有点下去那一刻才发现又冒出个白框。

## 四、立绘：一个角色，N 个表情

**之前的问题**：一个角色有多张立绘时，导演监视器里会**渲染出好几张卡**，
看着像"这个角色重复了"。

现在**一个角色一张卡**，多张立绘收进卡里当「表情差分」：

- 卡上立绘左下角有个 `1/N 表情名` 的小标记，**点它（或点立绘）换下一张**；
- 轮到最后一张再点就绕回第一张；
- 只有一张时这个标记不出现（没有第二个可选，就不装作有）；
- 右下角 `⛶` 直接跳到素材详情。

**表情名从哪来**：立绘的**标签**。取第一个**非系统标签**（`AI生成` 这类被打上"系统"标记的不算），
没有标签就叫「默认」。所以在素材页给立绘打上 `哭` / `笑` / `羞` / `怒`，监视器里就变成
可轮换的表情。

> 原计划是"表情差分 ×4"（固定四张）。落地时改成了**按标签、有几张算几张** ——
> 凭什么规定只能四种情绪。ROADMAP 里那条旧的 ×4 设想已作废。

素材页给标签时可以直接从预设里点（`默认 / 笑 / 哭 / 羞 / 怒 / 惊 / 困 / 冷 / 温柔`），
也可以自己打；同一个角色已经被别的立绘用掉的表情会**置灰**，免得两张图都叫"哭"。

## 五、立绘分组：一张图可以同时在几个组

**之前的问题**：分组是"一个分组字段装一串名字"，但界面按"要么在角色组、要么在自定义组"
处理，同一张图没法既挂在角色名下、又挂在"夜景"这种自定义组里。

现在：

- **角色组由绑定角色派生** —— 不给立绘存"角色组"这个字段，直接从 `bound_character` 算出来。
  改了角色名，组名跟着变，不会残留一个旧组；
- **自定义组多归属** —— `group_name` 存逗号分隔的组名，同一张图可以同时在
  「夏婉琴」+「夜景」+「待删」里；
- 组是**索引不是拷贝**：在多组视图里看到的是同一张图，删掉某个组里的它，
  只是从那个组移除，**不删文件、不动别的组**；
- 组名 chip 上的 `✕` 就是"从这一组移除"；角色组那个橙色 chip 没有 `✕`（它由绑定决定，
  想拆掉请去改绑定）。

## 六、素材详情：1:1 看清 AI 画坏的手

- 预览框固定 **1:1**（宽度撑满左栏，但不超过 `60vh`）—— 以前是自适应高度，
  竖图和横图换着看时框会跳；
- **滚轮缩放 1–4 倍**，`🔍+` / `🔍−` 同款，`1:1` 一键复位；
- 放大后可以**按住拖动**看其他区域（1× 时没有可拖的，光标是 `not-allowed`）；
- 缩放时右上角显示百分比；
- 详情里可以直接**删掉单张**（不再是"删整个角色的所有图"）。

## 七、修掉的立绘生成坑

| 坑 | 表现 | 原因 / 修法 |
|---|---|---|
| 种子传负数 | 硅基流动返回 `400 {"code":20015,"message":"seed: Must be greater than or equal to 0"}` | 之前用 `unwrap_or(-1)` 表达"没设置"。现在只验证了：所有取 seed 的路径都会夹到 ≥ 0（`resolved_seed()`，有测试盯着）|
| 云端配置块消失 | 云通道的表单打不开了 | 插件拆分（P1）时这块丢了，已补回 |
| 两个通道共用一份 `response_path` | OpenAI 兼容通道出图后取不到 URL | 拆成 `openai_response_path` / 自定义各一份，默认都 `auto:data` |
| 空占位符被原样发出去 | 请求体里带着 `""` 或整个空键 | 空占位符**整键丢弃**，不再塞空值 |
| OpenAI 通道显示了用不上的字段 | 表单里一堆 body 模板、认证头 | 该通道只显示 `base_url` / `model` / `API Key`；自定义通道才显示全部 |

减法同样是功能。删的都是**没有消费者**的 —— 判据统一：**一个功能如果没人用，就别留着"看起来能用"**。

| 4 个预览按钮 | 换成 1:1 预览框 + 缩放 |
| 两枚**假筛选 chips**（`标签：全身` / `表情差分`） | 点了没有任何效果 —— 最不该留的就是这种 |

## 九、内部（用户看不到的）

- 结构守卫 +3 条：
  - **立绘查询禁用 `SELECT *`** —— 这次真踩了：加了列之后按位置解码，运行期报
    `error occurred while decoding column 11: Rust type String (TEXT) not compatible with SQL INTEGER`；
  - `scripts/sync-run.mjs` 的 **dev 标志判据不许拆**（见下）；
  - 原生弹窗扫描（见第三节）。
- **构建入口统一**：新增 `npm run sync:run` —— 前端构建 → **带 `custom-protocol` 特性**编 exe →
  确认构建输出里**没有** `rustc-cfg=dev` → 复制到运行目录并核对 sha256。
  这一版开发中手搓过一次 `cargo build --release`，漏了特性 → exe 去连 `localhost:5173` → **白屏**
  （就是 [E-BOOT-03](../../dev/错误合集.md) 复发）。现在这条入口会提前拦住。
- `App.tsx` **1104 行**（结构守卫上限 1300）。
- **打包验证**（2026-10-25 实测，不是"应该没问题"）：
  - 本次构建窗口内 `target/release/build/app-*/output` **无** `cargo:rustc-cfg=dev` → 是打包版，不会去连 `localhost:5173`；
  - `msiexec /a` 解包 MSI → 只有 `app.exe` + `app_lib.dll`；
  - 便携版只放 exe 也能独立启动（拷到空目录双击，10 秒后窗口标题「织梦机」，进程健在）。
- 测试：Rust **325** 项（305 跑 + 20 `#[ignore]`）· 前端 **136** 项 · `tsc` 0 错 · 文档 34 份 / 208 条链接 0 断。
