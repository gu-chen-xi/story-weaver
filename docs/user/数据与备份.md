# 数据与备份

> 受众：使用者 ｜ 状态：**现行** ｜ 最后同步：**2026-10-24**（按 `paths.rs` 与实测重写）
>
> 一句话：**你的剧情、设定、立绘全部在一个"数据根"目录里，备份它 = 备份一切。**
> API Key 不在里面 —— 它在 Windows 凭据管理器。

---

## 一、数据到底在哪

软件按下面的顺序找一个**真能写**的目录当数据根（判定方式是"真写一个探针文件"，
不是看目录存不存在——踩过坑：目录在、权限看着对，实际写不进）：

| 顺序 | 位置 | 说明 |
|---|---|---|
| 1 | **环境变量 `DREAMWEAVER_DATA_DIR`** | 显式指定优先；**但它不可写时会继续往后兜底** |
| 2 | `%APPDATA%\com.guchenxi.story-weaver` | 标准位置 |
| 3 | `%LOCALAPPDATA%\com.guchenxi.story-weaver` | 有些环境 Roaming 被拦、Local 可以 |
| 4 | `<exe 同级>\data` | 便携 / 受限环境兜底 |
| 5 | `<exe 同级>\dreamweaver-data` | 再退一步 |
| 6 | `<当前目录>\data` → 系统临时目录 | 最后手段 |

> 用了兜底位置时，日志里会有一行：
> `[startup][warn] 标准数据目录不可写（...），已改用：...`

### 📌 本项目的实际情况（实测）

`start.cmd`（**本地脚本，不在仓库里**）第 71 行**显式设置**了：

```bat
set "DREAMWEAVER_DATA_DIR=%PROJ%data"
```

所以**用 `start.cmd` 启动时，数据就在项目下的 `data\`**：

```
D:\project\ai生成\data\
```

启动日志 `data\logs\startup-trace.log` 里能直接看到：

```
[dreamweaver] 数据根 = D:\project\ai生成\data
[dreamweaver] 日志根 = D:\project\ai生成\data\logs
```

> **直接双击 `app.exe` 而不走 `start.cmd`**，就不会有这个环境变量，
> 数据会落到 `%APPDATA%\com.guchenxi.story-weaver`。
> **两种启动方式的数据是分开的** —— 换着用会觉得"故事不见了"，其实是在另一处。

## 二、数据根下的目录

| 子目录 | 内容 |
|---|---|
| `library/` | `library.db`（故事索引 + 全局配置 + 立绘素材表）+ `default/projects/<id>/story.db` + `default/projects/<id>/memories/`（关键记忆 Markdown）+ `default/shared/portraits/` |
| `exports/` | 导出产物（`story/` `character/` `portrait/` `backup/` `quick/` `key-memories/`） |
| `temp/` | 运行期临时文件（含生图中间产物） |
| `logs/` | 日志，含启动诊断 `startup-trace.log` |
| `backups/` | 备份 |

## 三、两个数据库各装什么

### `library.db`（全局，3 张表）

| 表 | 内容 |
|---|---|
| `stories` | 故事列表、绝对时间起点、**前史/序章**（`prologue`）、**当前分支** |
| `configs` | 全部全局配置（模型地址/Key 状态/预算/上限…），**插件开关也在里面**（键名 `plugin.<id>.enabled` / `plugin.<id>.panelOpen`，绘图云端通道是 `portrait.cloud_*`）|
| `portraits` | 立绘素材（**全故事共享**）：`tags`（第一个非系统标签当表情名）、`group_name`（逗号分隔的自定义分组，可以多个）|

> **立绘版本历史已经删掉了**（2026-10-25）：`portrait_versions` 表在打开库时会被自动 `DROP`，
> 里面的历史记录一起清掉 —— 这是软件自己做的，不需要你动手，也不影响素材本身。

### `story.db`（每故事一个，16 张表）

时间线与剧情：`timeline_nodes`（树形节点 + 日摘要）、`messages`（消息，带 `branch_id`）
角色与设定：`characters`、`relations`、`world_settings`（均带 `branch_id` + `version`）
版本与审计：`setting_snapshots`（设定版本链）、`event_logs`、`audit_logs`、`change_proposals`
摘要与分支：`story_summaries`（阶段摘要）、`branches`（分支）
调试：`debug_requests`（请求记录，每次生成前写入，超上限自动裁剪）
评估：`reply_evaluations`（评估模型的四维打分）
导演代价：`director_costs`（每次用导演指令记一笔：类型 / 理由 / 分值 / 是否被赦免，带 `branch_id`）

> **关键记忆不在数据库里**：它是 `<故事>/memories/*.md`，一条一个文件（front matter 带 `branch`）。
> 所以它**不参与回滚、也不随分支复制**，备份时跟 `library/` 一起拷就对了。

> ⚠ `story.db` 里还有 `configs` 和 `cache_entries` 两张表，是**建库时顺手建的、实际没人用**
> （配置只在 `library.db`；缓存表从未写入）。看到它们别以为有内容。

## 四、API Key 在哪

**Windows 凭据管理器**（`keys.rs` / `keychain.rs`），**不在数据根里**。

这意味着：

- 备份数据根 → **不会**带走 Key（换电脑要重新填）
- 把数据根发给别人 → **不会**泄露 Key ✅
- 删掉数据根 → Key 还在（除非你去凭据管理器里删）

## 五、怎么备份 / 怎么恢复

**备份**

1. **先完全关闭软件**（`story.db` 有 WAL 文件，运行中复制可能拿到半截数据）
2. 整个数据根目录复制一份即可（`data\` 或 `%APPDATA%\com.guchenxi.story-weaver\`）
3. 想省空间可以跳过 `logs\` `temp\`，但**别跳过 `library\`**

**恢复**

1. 关掉软件
2. 把备份的目录放回原位置（保持 `library\` 内部结构不变）
3. 启动

> 软件也自带**设定版本**机制：改设定/回滚前会自动存快照，误改可以回滚。
> 但那是"设定层面"的后悔药，**不是整库备份**，替代不了复制目录。

## 八、常见问题

**Q：换个启动方式，故事怎么不见了？**
A：见 §一末尾 —— `start.cmd` 用项目下 `data\`，直接双击 exe 用 `%APPDATA%`。两套数据是分开的。

**Q：能放到 D 盘/移动硬盘吗？**
A：可以。设环境变量 `DREAMWEAVER_DATA_DIR` 指向那个目录即可（**要能写**，否则会静默兜底到别处，
日志里有 warn）。

**Q：数据加密了吗？**
A：**没有，明文 SQLite**。这是有意选择（无密码、方便备份/迁移/直接查库）。
需要加密请给整个目录套 BitLocker / VeraCrypt，而不是在软件里做"半吊子加密"。

**Q：把数据发给别人安全吗？**
A：剧情、设定、立绘都会一起发过去；**API Key 不会**（在凭据管理器里）。
但 `debug_requests` 表存着完整提示词与历史，发之前建议先在「设置 → 数据管理」清空。
