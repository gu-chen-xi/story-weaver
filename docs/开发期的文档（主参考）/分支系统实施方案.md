# 分支系统实施方案（第五批 ③）· 按项目实情修订版

> **来源**：基于用户提供的《织梦机-时间线分支系统设计文档》（v1.0 · 2026-10-14），
> 按**本仓库当前实现**修订为可执行方案。**本文件取代**此前的《分支系统实施方案.md》初稿。
> **用户已定的三点**：① 分支身份用文档的 `branches` 表 ② 嵌套分支**不限**（不止一级）③ **分支删除暂不做**。

---

## 一、一句话概括

为织梦机加"故事分支"：用户可选任意时间线节点作为分叉点，fork 出一条新故事线。
**分叉点之前的对话节点共享（不复制）**，分叉点之后的**对话内容与世界状态（角色/关系/世界观/设定快照）完全独立**。
模型等同 git branch。

## 二、核心概念

| git | 织梦机 |
|---|---|
| repository | 一个故事（一个 `story.db`） |
| commit | 一个时间线节点（`timeline_nodes` 一行） |
| main | **主线：`branch_id IS NULL`**（不叫 main，就是 NULL） |
| branch | `branches` 表的一行 |
| fork point | `branches.fork_node_id` |
| checkout | 界面顶部的分支切换条 |
| HEAD | 当前分支的最新节点 |

**数据归属规则（最重要）**
- `branch_id IS NULL` 的数据 = **主线专属**（不是"共享"，不是"默认"）
- `branch_id = X` 的数据 = 分支 X 专属
- 创建分支时：**复制世界的状态**（角色/关系/世界观/设定快照）到新分支 —— **数据复制，不是引用**
- 创建分支时**不复制对话节点**：分叉点之前的节点靠 `parent_id` 链共享
- 查询当前分支数据：主线用 `branch_id IS NULL`，分支用 `branch_id = ?`。**不需要"回退"到主线**，因为创建时已完整复制

## 三、与当前项目的衔接（本方案的关键修订）

设计文档写于不了解本仓库现状的前提下。以下逐条对齐**实际代码**：

| 文档原口径 | 项目实情 | 本方案采用 |
|---|---|---|
| 未提时间线树 | **`timeline_nodes.parent_id` 已实现**（第五批 ①），含幂等补链、五个纯函数与单测；跨天记忆**已改为按父链取历史** | **保留并复用**。`parent_id` 管"历史的形状"，`branch_id` 管"这条线是谁的"，两者互补 |
| 只支持一级分支 | `parent_id` 树天然支持多层 | **不限层级**（用户 2026-10-14 定）。`source_branch_id` 因此会真正被用到 |
| 做 `delete_branch` | — | **暂不做**（用户定）。将来做时需处理"被删分支的子分支怎么办" |
| `fork_node_id TEXT` + 外键 | `timeline_nodes.id` 是 **INTEGER 自增** | `fork_node_id INTEGER NOT NULL`（类型亲和才会让外键真正生效） |
| 复制时"`id` 生成新 UUID" | `characters`/`relations`/`world_settings` 的 id 是 **INTEGER 自增** | 复制时**不沿用原 id，交由数据库自增分配** → 切分支后角色 id 会变（故切换后需清空右侧面板选中，与文档 5.4 一致） |
| `messages` 加 `branch_id` | `messages.node_id` → 节点已有 `branch_id`，理论上冗余 | **仍然加**（显式、查询快、将来删分支方便）；代价是写入时要同步维护 |
| 未提设定版本的临时性 | `setting_snapshots` 已有 `temporary` 列（会话内临时版本） | 复制快照时**跳过临时版本** —— 它们是"回滚/编辑前的备份"，属源分支的操作痕迹，不该被继承 |
| 未提 `story_summaries` | 阶段摘要表存在，跨天汇总属"整条线" | **也加 `branch_id`**（不加会让各分支共享阶段摘要、串味） |
| 未提 `change_proposals` | 演进提案表存在 | **也加 `branch_id`**（用户已确认"快照与提案也隔离"） |
| 未提审计/事件日志 | `audit_logs` / `event_logs` 存在 | 加 `branch_id` 便于过滤，但**默认不过滤**（日志是流水，全看更有用） |
| 未提立绘素材库 | 素材是跨故事的共享资源 | **不隔离** |

**已经提前解决的最大风险**：文档 4.3 要的"回溯时不能读到别的分支内容" —— 第五批 ① 已把跨天装配改为**按父链取**，
并有 `linear_story_path_equals_positional`（线性等价性）与 `forked_story_path_excludes_other_branch`（分支隔离）两项单测守着。

## 四、数据模型变更

### 4.1 新增表 `branches`

```sql
CREATE TABLE IF NOT EXISTS branches (
    id               TEXT PRIMARY KEY,            -- UUID
    story_id         TEXT NOT NULL,               -- 所属故事（library.db 的 stories.id）
    name             TEXT NOT NULL,               -- 用户起的名，如"角色A牺牲线"
    fork_node_id     INTEGER NOT NULL,            -- 从哪个节点分叉（timeline_nodes.id；INTEGER）
    source_branch_id TEXT,                        -- 从哪个分支 fork（NULL = 从主线；嵌套分支时非 NULL）
    color            TEXT NOT NULL DEFAULT '#6B7280',
    created_at       TEXT NOT NULL DEFAULT (datetime('now','localtime'))
);
```

- `color` 从预设池按创建顺序轮替：`['#3B82F6', '#F59E0B', '#10B981', '#EF4444', '#8B5CF6']`
- 外键：`FOREIGN KEY (fork_node_id) REFERENCES timeline_nodes(id)` —— **类型必须与 `timeline_nodes.id` 一致（INTEGER）**，否则 SQLite 的外键约束不生效

### 4.2 现有表新增 `branch_id`（全部幂等补列）

| 表 | 是否加 | 说明 |
|---|---|---|
| `timeline_nodes` | ✅ | 该节点属于哪条分支（NULL = 主线） |
| `messages` | ✅ | 冗余但显式（写入时与节点同步带上） |
| `characters` | ✅ | 该角色是哪个分支的版本 |
| `relations` | ✅ | 同上 |
| `world_settings` | ✅ | 同上 |
| `setting_snapshots` | ✅ | 同上 |
| `story_summaries` | ✅ | **补充**：阶段摘要不隔离会串味 |
| `change_proposals` | ✅ | **补充**：提案按分支隔离（用户已确认） |
| `audit_logs` / `event_logs` | ✅ | **补充**：加列便于过滤，默认不过滤 |

```sql
ALTER TABLE timeline_nodes   ADD COLUMN branch_id TEXT;   -- 无默认值：NULL 即主线
-- …其余各表同理（用 PRAGMA 列存在性检查保证幂等）
```

**已有数据零转换**：所有现存行 `branch_id` 为 NULL = 主线。

### 4.3 索引

```sql
CREATE INDEX IF NOT EXISTS idx_timeline_nodes_branch  ON timeline_nodes(branch_id);
CREATE INDEX IF NOT EXISTS idx_messages_branch        ON messages(branch_id);
CREATE INDEX IF NOT EXISTS idx_messages_node          ON messages(node_id);
CREATE INDEX IF NOT EXISTS idx_characters_branch      ON characters(branch_id);
CREATE INDEX IF NOT EXISTS idx_relations_branch       ON relations(branch_id);
CREATE INDEX IF NOT EXISTS idx_world_settings_branch  ON world_settings(branch_id);
CREATE INDEX IF NOT EXISTS idx_setting_snapshots_branch ON setting_snapshots(branch_id);
CREATE INDEX IF NOT EXISTS idx_branches_story         ON branches(story_id);
```

## 五、后端变更

### 5.1 通用过滤辅助（`story_db.rs`）

```rust
/// 生成分支过滤的 WHERE 片段。主线 = NULL，分支 = 具体 id。
pub fn branch_clause(col: &str, branch_id: &Option<String>) -> String {
    match branch_id {
        Some(_) => format!("{col} = ?"),
        None => format!("{col} IS NULL"),
    }
}
```
调用方据返回值决定是否 `.bind(branch_id)`。

### 5.2 新增命令

| 命令 | 行为 |
|---|---|
| `create_branch(story_id, name, fork_node_id, source_branch_id)` | **同一事务**内：① 查源分支与分叉点（不存在则报错）② 插入 `branches` ③ **复制世界状态**：`characters` / `relations` / `world_settings` / `setting_snapshots`（**跳过 `temporary = 1` 的临时版本**），逐行 INSERT 且 `branch_id = 新分支`、**id 交给数据库自增** ④ 返回 `Branch` |
| `list_branches(story_id)` | 按 `created_at` 升序返回（含额外统计：该分支节点数，供界面显示） |
| `get_branch(branch_id)` | 单个分支详情 |
| ~~`delete_branch`~~ | **暂不做**（用户定） |

**嵌套分支**：`source_branch_id` 非 NULL 时从该分支复制状态（而非主线）。因为状态是"行级带 branch_id"的，
所以复制逻辑与一级分支**完全相同**，只是过滤条件换成源分支 id —— 不需要为嵌套额外写代码。

### 5.3 现有查询加 `branch_id` 过滤（逐条对齐实际命令）

| 现有命令/模块 | 改法 |
|---|---|
| `list_timeline_nodes` | **主线要返回全树**（含各分支节点，树形展示需要）；另加 `list_branch_nodes(branch_id)` 只取该分支的节点。**不要**简单粗暴地把主线查询加上 `branch_id IS NULL`，否则界面上的树会缺枝 |
| `list_messages(story_id, node_id)` | 消息挂在节点上，**按 node_id 查即可**；若加了 messages.branch_id，则一并校验一致性 |
| `list_characters` / `character_get` | 加分支过滤 |
| `list_relations` / 关系网络 | 加分支过滤 |
| `list_world_settings` | 加分支过滤 |
| `list_snapshots` / `preview_snapshot` / `rollback_snapshot` | 加分支过滤（回滚只影响当前分支） |
| `check_board_struct` / `check_board_ai` / `apply_check_patch` | 只检查 / 只替换当前分支的数据 |
| `analyze_evolution` / 提案列表 / 确认提案 | 只基于当前分支数据产提案、只落当前分支 |
| `list_story_summaries` | 加分支过滤 |
| `generate_story_reply*` | 新增 `branch_id` 参数；新建节点与消息时写入该 `branch_id` |

### 5.4 发送消息 / 生成回复时的分支处理

1. 新建 `timeline_nodes` 行：`branch_id = 当前分支`（主线为 NULL），`parent_id = 当前节点`
2. 新建 `messages` 行：`branch_id` 同上
3. **上下文回溯沿 `parent_id` 链向上走，不限制 `branch_id`** —— 分叉点之前的节点本就该共享；
   分支的第一个节点 `parent_id` 就是分叉点，链**天然在分叉点之上继续**（这是共享历史的来源）
4. "取当前分支最近 N 条消息"这类**横向**取数要加 `branch_id` 过滤（避免把别的分支的内容读进来）

> ⚠️ 第 3、4 条的区别是本方案最容易搞错的地方：**纵向（父链）回溯要跨分支，横向（同日/近 N 条）取数要限分支**。
> 第五批 ① 已按此实现并有单测，本步只需把 `branch_id` 接上。

### 5.5 "当前分支"记在哪

`library.db` 的 `stories` 表加一列 `current_branch_id TEXT`（默认 NULL = 主线）—— 记住用户上次在哪条分支，
重新进入故事时自动切回去。**只动这一列，不改 library.db 其它结构。**

### 5.6 迁移

在 `story_db.rs` 里加 `ensure_branch_columns(pool)`（幂等：按列存在性判断），在 `open_story_pool` 中调用
（与既有 `ensure_timeline_parent_column` 等同一套路）。`branches` 表用 `CREATE TABLE IF NOT EXISTS`。

## 六、前端变更

### 6.1 新增状态

```typescript
const [branches, setBranches] = useState<Branch[]>([]);
const [currentBranchId, setCurrentBranchId] = useState<string | null>(null); // null = 主线
const [showBranchDialog, setShowBranchDialog] = useState(false);
const [branchForkNode, setBranchForkNode] = useState<number | null>(null);    // 弹窗里预设的分叉节点
```
`Branch { id, name, fork_node_id, source_branch_id, color, created_at, node_count? }`

### 6.2 界面改动（三处）

**改动 1：顶部分支切换条**（故事标题下方、对话区上方）
- 形如 `[🔵 主线] [🟠 角色A牺牲线] [＋ 新建分支]`；每项为颜色圆点 + 名称
- 点击 → `setCurrentBranchId` → **重新加载全部数据**（时间线 / 消息 / 角色 / 关系 / 世界观 / 设定版本 / 提案）
- 当前项加粗 + 下划线 + 颜色加深
- **超过 5 个时**第 6 个起收进「更多 ▾」
- **只有主线时整条隐藏**（不打扰）

**改动 2：时间维树形化**（在**已完成的时间维条**上扩展，不新起一条）
- 树干（分叉点之前）只显示一次；当前分支的后续展开显示，其它分支收成一行（可展开查看，但**不可操作**）
- 分叉点旁加 `🔀`；节点颜色点 = 所属分支颜色 —— 复用 ① 已实现的"有分叉才显示折叠控件"机制，只是把折叠状态**按分支初始化**（当前分支默认展开）

**改动 3：新建分支弹窗**
- 触发：顶栏「＋ 新建分支」/ 时间维节点右键「从此处新建分支」
- 内容：`分支名称`（必填）+ `分叉节点`（右键时自动填入；顶栏触发时默认当前节点，可下拉改）
- 创建成功 → **自动切到新分支** + toast「分支「XXX」已创建」

### 6.3 切换分支时的行为
1. 显示遮罩「正在切换分支…」
2. 带 `branch_id` 重新请求全部数据
3. 时间维滚动到该分支的第一个节点（或分叉点）
4. **清空右侧面板选中**（角色 id 变了 —— 新分支的角色是复制出的新行）
5. 移除遮罩 + toast「已切到分支 X」

### 6.4 前端代码量约束
文档要求新增控制在 200 行内。本方案据此：分支相关 UI 集中在一处组件，不复用/重构既有大段代码。

| **5** | 前端：分支切换条 + 状态 + 新建弹窗 | 界面能看到切换条；能建分支；切换后对话/角色/世界观都刷新 |

| **7** | 集成验收（文档 §7.3 的手动流程） | 主线写 3~5 天 → 第 3 天建分支 → 分支写 2 天 → 切回主线继续写不受影响 → 第 5 天再建第二个分支 → 三条线数据互相独立 |

## 八、边界（不做 / 不预留）

- ❌ 分支合并（merge）　❌ 分支对比（diff 视图）　❌ 分支间拖拽节点
- ❌ **分支删除**（用户 2026-10-14 定：暂不做）
- ❌ 分支标签 / 分类　❌ 分支间的角色 / 关系同步
- ✅ **嵌套分支不限层级**（`parent_id` 树天然支持；复制逻辑与一级分支相同）

## 九、风险与对策

| 风险 | 对策 |
|---|---|
| **改动面大**（9 张表加列 + 大量查询加过滤） | 分步走（先迁移、再 CRUD、再改查询、最后界面）；每步跑全量测试；`branch_id IS NULL` 时必须与现在**逐项一致** |
| **纵向/横向取数搞混**（父链要跨分支、近 N 条要限分支） | ① 已实现并有"线性等价性""分支隔离"单测；本步接 `branch_id` 时这两项测试是回归网 |
| **复制世界状态时漏表** | 复制清单写成**一个常量数组**，测试按该数组逐表断言行数一致 |
| **切分支后状态没跟上** | §6.3 的强制重新加载 + 清空选中 + toast 提示 |
| **老库** | 幂等补列 + 默认 NULL；真机库（story 7，15 节点 / 3 角色 / 3 关系 / 7 世界观 / 15 版本）先在上面验证迁移再继续 |
| **误以为主线也被隔离** | 界面明确标注「主线」；主线 `branch_id` 恒为 NULL |

## 十、名词对照表（防误解）

| 用语 | 代码 | 说明 |
|---|---|---|
| 主线 | `branch_id IS NULL` | 不是 "main"，就是 NULL |
| 分支 | `branches` 一行 | 用户创建的故事分支 |
| 分叉点 | `branches.fork_node_id` | INTEGER，指向 `timeline_nodes.id` |
| 节点 | `timeline_nodes` 一行 | 一天 / 插曲 / 倒叙 |
| 世界状态 | `characters` + `relations` + `world_settings` + `setting_snapshots` | 复制这四张表 |
| 纵向回溯 | 沿 `parent_id` 上溯 | **跨分支**（共享历史） |
| 横向取数 | 同日 / 近 N 条 | **限分支** |
