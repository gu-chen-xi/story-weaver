# 启动自检工具 · 说明

> 一个**能独立于应用运行**的诊断工具，专门用来排查"应用打不开"这类问题。
> 双击 `scripts\selfcheck\selfcheck.cmd` 即可（黑框框，无需任何其它环境）。

---

## 为什么需要它

我们在 2026-10-16 排查"打不开"时，接连踩了 **5 个叠在一起的静默失败**：

| # | 故障 | 为什么难发现 |
|---|---|---|
| 1 | 数据目录写不进去 | 同一个目录 **Python 能写、app.exe 不能**；`create_dir_all` 返回成功也可能写不了 |
| 2 | 日志插件初始化失败 | 它会让**整个应用起不来**（exit 101），而且发生在错误对话框之前 |
| 3 | `.cmd` 里中文注释 | cmd.exe 按 GBK 读 UTF-8 文件，注释被撕碎**当成命令执行** |
| 4 | exe 所在目录名叫 `ai生成` | Tauri **建不出主窗口，且完全静默**（进程活着、无 panic、日志停在"数据库就绪"） |
| 5 | 缺 `custom-protocol` 特性 | 打包版也去连 `localhost:5173`，页面显示"拒绝连接"，但**进程完全正常** |

**共同点：全都静默。** 而单元测试（149 项全绿）**永远抓不到**这类问题——它测的是"函数对不对"，不是"这个 exe 在这台机器上能不能真的跑给人用"。

于是把排查过程固化成这个工具。

---

## 怎么用

```
双击 scripts\selfcheck\selfcheck.cmd
```

- **无需** node / Rust / 浏览器
- 输出中文报告，**同时落盘**到 `debug-diagnostics\selfcheck-<时间>.txt`
- 退出码：**0 = 可用**，**1 = 有问题**
- 出问题时把报告文件发给开发者即可（比口述现象准得多）

### 可选参数

```powershell
# 检查指定的 exe（默认用项目的 target\release\app.exe）
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\selfcheck\selfcheck.ps1 -ExePath "D:\某处\app.exe"
```

## 检查项（共 14 项）

### 一、产物与版本

| 检查 | 判据 | 为什么查 |
|---|---|---|
| 打包版 app.exe 存在 | 文件存在 | — |
| 按 start.cmd 的方式复制到安全路径 | 复制成功 | 见下方"为什么默认会复制" |
| 前端产物 dist\index.html 存在 | 文件存在 | 没 dist → release 版内嵌的是空前端 |
| 三处版本号一致 | package.json / tauri.conf.json / Cargo.toml 相同 | 不一致说不清"我在跑哪版" |
| Tauri npm 包与 Rust crate 版本匹配 | major.minor 相同 | 不一致时 CLI 直接报 `version mismatched` 拒绝启动 |
| **exe 内嵌了前端** | 全文搜 `<!doctype html` | 没有 → 它仍会去 localhost:5173 取界面 |

### 二、路径安全

| 检查 | 判据 | 为什么查 |
|---|---|---|
| **exe 路径不含已知风险目录名** | 祖先链里没有 `ai生成` | 实测该目录名下 Tauri 建不出主窗口 |
| start.cmd 用的数据目录可写 | 写探针文件成功 | 写不了就起不来 |
| 数据根候选至少一个可写 | 逐级探测（含 %APPDATA% / %LOCALAPPDATA% / exe 同级） | 需要"至少有一条活路" |
| 找到含故事的数据库 | library.db 存在且 >10KB | 数据目录对不上时用户会以为"故事丢了" |

### 三、真实启动测试（核心）

| 检查 | 判据 | 为什么查 |
|---|---|---|
| 进程能启动并保持运行 | N 秒后仍在 | — |
| **主窗口已创建** | 枚举到 `class=Tauri Window` 且宽>500、高>400 | ⭐ **最有价值**：Tauri 建窗口失败**完全静默** |
| **没有去连 dev 服务器** | 假监听器收到 0 次连接 | 缺 custom-protocol 时会连 5173，页面报"拒绝连接" |

### 四、启动日志

只显示**最近一次**启动的 `startup-trace.log` / `startup-error.log` 关键行。
（trace 是追加写的，跑多次会有多段——只取最后一段，避免刷屏。）

## 关键设计（都是踩坑换来的）

### 1. "可写"必须真写一个文件

```powershell
# 错：只看目录在不在
if (Test-Path $dir) { "可写" }

# 对：真写探针
Set-Content -Path "$dir\.probe" -Value ok    # 抛异常才算不可写
```

实测踩到：某机器上"**已存在目录可写、新建目录被拒**"，`create_dir_all` 返回成功仍写不进去。

### 2. "窗口正常"必须枚举窗口

我一开始把"进程是否活着"当成"启动成功"，**这是错的** —— 让你白试了 4 轮。
Tauri 窗口创建失败时进程照活着。只能靠 `EnumWindows` 枚举 + 检查尺寸。

> 顺带一个坑：P/Invoke 声明 `GetClassNameW` 时**必须加 `CharSet.Unicode`**，
> 否则 `StringBuilder` 按 ANSI 编组，宽字符被截成第一个字节 ——
> `"Tauri Window"` 会变成 `"T"`，于是明明有窗口却报"没找到"。（我自己先踩了一遍）

### 3. 检查项失败要说"没测成"，不能默认通过

- 窗口枚举功能不可用 → `SKIP`（不是 PASS）
- 5173 已被占用 → 跳过假监听器探测 → `SKIP`
- 结论里单独列出"有 N 项没测成（不代表通过）"

### 4. 为什么默认会**先复制**再测

实测（同一台机器、同一个 exe）：

| exe 位置 | 结果 |
|---|---|
| `D:\project\ai生成\src-tauri\target\release\app.exe` | ❌ 只有 Tao 事件窗口，**Tauri 主窗口建不出来** |
| `D:\DreamWeaverRun\app.exe` | ✅ `class=Tauri Window 标题="织梦机" 尺寸=1295x837` |

用户实际用的是 `start.cmd`（它会先复制到 `%LOCALAPPDATA%\DreamWeaverRun`），
所以自检也测"复制后"的那份 —— 否则会一直误报 FAIL。
而"直接双击 target\release\app.exe 会失败"这件事，单独作为 **WARN** 提示出来。

### 5. `.ps1` 必须靠 `.cmd` 带 `-ExecutionPolicy Bypass` 拉起

直接双击 `.ps1` 会被执行策略拦（`PSSecurityException`）。`.cmd` 是纯 ASCII 的。

### 6. `.ps1` 必须存成 **UTF-8 带 BOM**

Windows PowerShell 5.1 读**无 BOM** 的 UTF-8 会按 GBK 解释：
中文变乱码 → 引号/括号被破坏 → 一堆莫名其妙的 ParseError。

## 自证：它真的能抓到问题

工具最危险的是"全绿但没用"。所以做了**故障注入回归**（每次都跑）：

| 场景 | 期望 | 实测 |
|---|---|---|
| 正常（模拟 start.cmd） | 全通过、退出码 0 | ✅ 14/14 通过，退出码 0 |
| exe 放在 `…\ai生成\…` 下 | 报"主窗口已创建"失败、退出码 1 | ✅ 命中，且给出祖先链 |
| `-ExePath` 指向不存在的文件 | 报"指定的 exe 存在"失败 + 启动测试 SKIP、退出码 1 | ✅ 命中，**不会偷偷回退**到别的 exe |

**本工具自己就是靠这套故障注入验证出来的** —— 初版有 3 个误报（HTML 只扫前 6MB、窗口类名被截断、危险目录判定过严），全是靠"故意制造问题看它抓不抓得到"发现的。

## 不做的事（有意）

| 不查 | 原因 |
|---|---|
| **端口占用** | 应用**不监听任何端口**。5173 是 **vite 开发服务器**占的，不是应用。所以"启动失败因为端口被占"这个场景不存在 |
| 内存 / CPU / 句柄 | 那是长期运行监控，不是启动问题 |
| 通用网络连通性 | 运行时问题，且会误报（用户可能就想用本地模型） |
| DB schema 完整性 | `cargo test` 的 149 项已覆盖 |
