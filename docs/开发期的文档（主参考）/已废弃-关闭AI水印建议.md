# 已废弃做法：关闭服务方的「AI 生成」水印

> 本文件是**风险留痕**，不是教程。请勿按被废弃的做法操作。
> 建立于 2026-10-11。

## 被废弃的做法

早期版本的《立绘生成使用指南》曾建议：在调用云端绘图接口时加一个请求头

```
X-Enable-Watermark: 0
```

以关闭服务方在生成图上添加的「AI 生成」水印。

**该建议已作废，并已从文档中删除。**

## 作废原因

《人工智能生成合成内容标识办法》（国家互联网信息办公室、工业和信息化部、公安部、国家广播电视总局，
**2025 年 9 月 1 日起施行**）规定：

> 任何组织和个人**不得恶意删除、篡改、伪造、隐匿**本办法规定的生成合成内容标识，
> **不得为他人实施上述恶意行为提供工具或者服务。**

该办法同时确立了标识的两类形态：

| 标识 | 形态 | 谁添加 |
|---|---|---|
| **显式标识** | 用户能明显感知的标识（文字 / 水印 / 图形等） | 生成合成服务提供者 |
| **隐式标识** | 写在生成合成内容**文件元数据**中的技术标识 | 生成合成服务提供者 |

因此：**用请求头或参数关闭服务方水印属于「删除标识」**，法律风险落在使用者身上；
而软件文档建议这么做，等于**为他人实施该行为提供服务** —— 风险更高。

## 本软件当前的既定行为（有测试锁定）

| 行为 | 实现 |
|---|---|
| **不改标识** | 生成结果全程**字节直通**：base64 解码 → 原样写临时文件 → 素材库 `std::fs::copy` 字节拷贝入库，**不重编码**；显式水印（像素）与隐式标识（元数据）均原样保留 |
| **测试锁定** | `generator_cloud::tests::image_bytes_pass_through_without_stripping_metadata` —— 构造带 `tEXt` 元数据块的 PNG，走完整链路后断言逐字节一致、元数据块仍在 |
| **主动提醒** | 生成面板内置合规提示；素材库 AI 角标与按来源筛选；导出文件名带 `_AI` 后缀并附「导出清单.json」 |
| **不再提供的功能** | 不提供任何"去水印 / 清元数据 / 洗掉 AI 痕迹"的选项，今后也不会加 |
